## 1. 这是要解决什么问题（必填，人话）

- 现在的球局是假的：每个手机各演各的，你发的局只有你自己的手机看得到，球友"报名"了也进不了真名单，换台设备全没了。账号系统是真的，认得出人，但没有局。
- 一句话的成功画面：组织者在手机上发一个局，球友在各自的手机上翻到同一个局、报进同一份名单；到截止时间局自己判生死；谁的手机打开，看到的都是同一份名单、同一个进度。

## 2. 给谁用（必填，按角色写）

- **组织者**：发局、管名单（改局/锁必打/登记订场）、翻意向挑人邀请、撤局、救回人数不足的局——全程只管自己的局。
- **球友**：翻局、报名带人、退局（截止前）、留打球意向、接受邀请——管的是自己那一格。
- **游客**：从微信群链接点进来看局、看名单（只显昵称）；想报名那一刻填名片建号（1.1 的链路原样接上）。
- 不为任何角色服务的部分：无。

## 3. 用户故事（必填）

1. 作为组织者，我想发一个局并定下时间地点、人数、规则和"谁能翻到"，以便球友各自报名、我不用在群里接龙。（→ §1 假局）
2. 作为球友，我想翻到能参加的局、报名时带上朋友，以便和朋友一起占坑。（→ §1）
3. 作为球友，我想留下"大概什么时候想打"，以便组局的人凑人时想到我。（→ §1，0号「留打球意向」）
4. 作为组织者，我想翻意向列表看中谁就邀请谁，以便局的名单自己长起来。（→ §1）
5. 作为组织者，我想登记订场（场地号+总价）或锁"必打"，以便人数不够也照开、费用当场落定。（→ §1）
6. 作为组织者，我想在开打前撤局或救回人数不足的局，以便临时变故有退路。（→ §1）
7. 作为球友，我想换台手机打开还是同一份局和名单，以便数据不丢。（→ §1 假局）
8. 作为组织者，我想让局默认只被跟我打过球的人翻到、必要时才公开，以便不被完全陌生的人拼局。（→ §1）

## 4. 输入 / 输出场景（必填，文档核心）

> 全篇数人数只用一把尺：**人头 = 每位报名者自己 + 带的人数**（带的人也占坑）；进度只讲"还剩几坑"；最少人数只干一件事——截止时判局成不成。全篇说时间只用一种写法：发局表单里"今晚 19:00"这类顺手话，提交时一律换算成准确的日历时刻（北京时间）；过了发布那一刻，截止时刻定死不改。

### 场景 4.1：组织者发局
- **身份**：组织者（已登录）
- **前提**：约球页点右下角"+"唤起发局表单
- **操作**：填时间（起止时刻）、组局截止（默认自动 = 开打前 2 小时，手动拨过即固定）、地点（球馆名+地址）、人数（最少—最多）、规则三件（分制、轮转方式、得分规则）、**谁能翻到**（三选一：跟我打过的人 / 任何人 / 仅邀请，默认第一档）；局名可不填（自动起"日段 · 场馆"）；点发布
- **结果**：局立起来，组织者自己就是名单第一个人（占 1 坑）；局出现在组织者和能翻到它的球友的约球页列表里；费用显示"未定"。默认档下没有"打过"关系的新球友翻不到这个局——发布成功的提示里带一句引导："这个档位下，球友主要通过你转的链接看到这个局"
- **禁止**：截止时刻不在"现在之后、开打之前"的提交被拦下；最少人数大于最多人数被拦下

### 场景 4.2：球友找局（谁能翻到谁）
- **身份**：球友
- **前提**：约球页"找局打"列表
- **操作**：翻列表
- **结果**：三档局各就各位——「任何人」档的局人人翻得到；「跟我打过的人」档的局，只有跟这位组织者打过球的人翻得到；「仅邀请」档的局列表里根本没有，只能靠组织者转链接或从意向列表邀请进场。**链接永远是门票**：不管哪档局，拿到链接的人点开都能看详情、都能报名——档位只管"谁能翻到"，不管"谁能进"。"打过"的算法只有一条：**两人同在一个已成局的正式名单里**——到截止名单锁定那一刻起算；报名了没成局的、被撤的、只在候补待过的，都不算。局的状态按时刻自动翻：开打时刻一到变"进行中"、结束时刻一到变"已结束"，不靠任何人动手
- **禁止**：档位不拦链接进来的人

### 场景 4.3：球友报名带人
- **身份**：球友
- **前提**：看中一个局，没满员
- **操作**：点加入 → 选带几个人（**最多带 3 人**）→ 确认
- **结果**：自己加带的共占坑；进度"还剩几坑"随之减少；报满之后再有人点加入，自动进局下方的**候补栏**，有人退出或上限放宽按先后自动转正；**剩下的坑装不下你这一整行**（自己+带的人）时，整行落候补并提示"坑不够，已为你排候补"——候补转正也是整行算：谁装得下谁先转，装不下的顺延下一位，不拆行；已加入的人再点一次加入，就当没事（不报错、不重复占坑）
- **禁止**：带的人数超过 3 的提交被拦下

### 场景 4.4：球友退局
- **身份**：已报名的球友
- **前提**：分两种——截止前 / 截止后
- **操作**：点退出（确认）
- **结果**：截止前——退出成功，名额立刻释放，候补第一位自动转正，带的人跟着一起退；截止后——拦下，提示名单已锁定不能退出（截止锁的是"防鸽退出"，不是"拒人进门"——加入照常，见场景 4.14）；**一个例外**：截止后组织者改了时间或地点的局，名单解锁可退（见 4.6）
- **禁止**：组织者没有退出按钮（只能撤局，见 4.10）

### 场景 4.5：游客从微信群链接进来（先看后报）
- **身份**：游客（还没账号）
- **前提**：群里点开局链接
- **操作**：翻看时间、地点、名单（只显昵称）→ 点我要报名 → 填三行名片（昵称/头像/手机号，1.1 的名片卡）
- **结果**：建号与报名一步完成，动作不中断；这台设备从此记住他。名片上填的手机号已经有账号的（比如换新手机的老球友），按 1.1 的规矩登录回原账号，报名同样一步完成——不会建出第二个账号
- **禁止**：浏览之前出现任何要求登录的窗口

### 场景 4.6：组织者改局
- **身份**：组织者
- **前提**：局还没开打
- **操作**：点改信息，复用发局表单带出原值，改完保存
- **结果**：时间、地点、人数范围、规则三件、可见档都能改；名单里的人再打开看到的就是新信息。**截止不能改**——连带一条：开打时间只能改到截止之后（否则出现"截止晚于开打"的倒挂局，被拦下）。**上限往小改**：按报名先后，最后报的先转候补（带的人跟主人整行走、不拆），转到达标为止；组织者是名单头一个，永远不会被转。**上限往大改**：候补按先后自动转正（同样整行算），转完仍超出，多出的候补者看到"满员，建议下次再参加"。**截止后改时间或地点（改约解锁）**：名单解锁——参加者看到新信息后可以退（退了候补照常递补），到开打时刻重新锁死；组织者先动的约，参加者有一次说"新时间来不了"的机会
- **禁止**：改档不赶人——换可见档后已在名单里的人一律不动

### 场景 4.7：组织者锁必打与订场登记
- **身份**：组织者
- **前提**：局未开打；订场发生在 app 外（场馆现场/订场平台），app 只登记结果
- **操作**：点「锁定必打 · 订场登记」面板——只上锁不登记（空锁，免费场/老友局用；点空锁时先确认一句"锁上后人数不够也照开，且不能解锁（只能撤局）"）；或填场地号（如"3号、5号"，几片填几个）+ 总价（照订场小票手填，免费填 0），保存；面板随时可重开改登记；场地全退光可清空登记
- **结果**：手动锁一上不撤（清空订场也不松）；填了场地号即"已订场"——这局必开、费用落定（总价+人均，人均按当前人数摊——哪怕最后比最少人数还少，也按实际人数摊）、场地号亮给参加者；清空登记后费用回"未定"、截止照常判人数，手动锁保留。**必打 = 手动锁过 或 场上有号**，一个判定管到底：必打的局人数不足也不终止。截止后（名单已锁）面板仍可改——临到场场馆换号很常见，锁名单只锁人
- **禁止**：已订场的局走到"人数不足自动终止"那一步

### 场景 4.8：到截止，局自己判生死
- **身份**：系统判定；组织者与球友打开时看到结果
- **前提**：截止时刻到了；判定发生在**任何人打开或动这个局的那一刻**——谁先来谁触发（翻约球页列表本身就是"打开"，判定在进列表那一刻完成，不会有过期未判定的局挂在列表里），系统当场判完记档，后来的人看到的就是判完的结果
- **操作**：无需任何人操作
- **结果**：人头 ≥ 最少人数 → **名单锁定**（成局，参加者不能再退出，见 4.4）；人头 < 最少且**不是必打局** → **自动终止**：局从列表撤下，报名者"我的局"里这条局变一行灰字"该局已取消"（次日自动收走），组织者的约球页留一条"未成局"记录（见 4.9）；人头 < 最少但**是必打局** → 同样名单锁定成局（人数不够也照开）
- **禁止**：必打局（手动锁或已订场）被人数不足终止

### 场景 4.9：组织者救回人数不足的局（恢复）
- **身份**：组织者
- **前提**：局因人数不足自动终止；**开打时刻还没到**
- **操作**：约球页单独的"未成局"区（仅组织者可见）里点恢复
- **结果**：局回到组织者手里，进**待处置**状态——只对组织者可见、**不触发截止判定**（球友打开也不会把它再判死），直到组织者锁必打或撤局，处置完局才回到正常列表、名单原样
- **禁止**：开打时刻已过的局不能恢复（时间地点都过去了，想再打发新局）

### 场景 4.10：组织者撤局
- **身份**：组织者
- **前提**：开打时刻还没到
- **操作**：点取消局 → 过确认
- **结果**：局从约球页撤下，报名的人"我的局"里这条局变一行灰字"该局已取消"（次日自动收走），链接点开变说明页（"这个球局不存在或已被删除"）；已订场的局，确认框里提醒一句"记得去场馆退订"。撤局后组织者"我的局"**不留痕**——撤局是想清楚了的明确动作，要再组发新局
- **禁止**：开打后的局没有撤局按钮（开打后是现场的事，归打球页收尾）

### 场景 4.11：组织者翻意向、挑人邀请
- **身份**：组织者
- **前提**：意向列表里有球友留过"大概什么时候想打"（时段+频率+一句话备注）
- **操作**：翻意向列表（被邀请过的标"已邀"、排后面；新留的和新改过的排前面）→ 看中谁点邀请
- **结果**：局直接出现在对方的"我的局"里，提示有人邀请；重复邀请同一个人就当没事（不重复打扰）。**被邀请不占坑**——对方点不点加入随他
- **禁止**：组织者之外的任何人发不了邀请

### 场景 4.12：被邀请的球友
- **身份**：被邀请的球友
- **前提**：组织者刚邀请了他
- **操作**：打开 app → "我的局"里出现这个局（带有人邀请的提示）→ 点一下加入（或放着不动）
- **结果**：点了就占坑（满员进候补，与 4.3 同）；放着不动局就一直挂在"我的局"，直到那局截止、被撤或打完
- **禁止**：不点加入就被算进名单

### 场景 4.13：留 / 改 / 删意向
- **身份**：球友
- **前提**：任何人都能翻别人的意向（含游客，3.1 已定的规矩）；自己的一份随时可动
- **操作**：留一份（至少选一个时段 + 频率：随缘/每周 1 打/每周 2 打 + 一句话备注可空）；随时改、随时删
- **结果**：意向长期挂着，组局的人凑人时会看到；被邀请过的人**改了意向**，"已邀"标记自动清掉、重新排到列表前面——"我又改了想法"= 可以再来邀我
- **禁止**：一个时段都不选的意向存不进去

### 场景 4.14：两个边缘——抢最后一个坑 & 截止后进场
- **身份**：球友
- **前提**：①只剩 1 个坑，两个人同一秒点加入；②局已过截止、名单已锁，一个人从现场链接点进来
- **操作**：①两人都提交；②点加入
- **结果**：①只有一人进正式名单，另一人自动落候补栏（不报错，候补也是加入）；②报名照常成功——**加入窗口到局结束为止**：截止后、进行中都能加（现场空降靠这条路先进名单再签到，满员照旧进候补），已结束的局链接点开只读、没有加入按钮（历史名单不许被污染）
- **禁止**：正式名单的人头永远不超过最多人数那条线

## 6. 边界与非目标（必填）

- ❌ **明确不做**：
  - 现场轮转、记分、结算（另立 1.3 现场规格；本规格把交接棒递好——名单锁定的那一刻就是交接点，局身上留得住现场进度）
  - 账单收付款（依赖打完的局，后置）
  - 主动推送通知（满员/截止/改局/被邀都不发消息——没有推送通道，球友打开自然看到；3.2 原话「名单里的人再打开，看到的就是新信息」）
  - 换组织者/转让、撤回邀请、局草稿/定时发布、地图选点（地点手输球馆名+地址）、局名查重与敏感词
  - 截止时刻的修改（发布即定死，不做延期）
- ✅ **做但降级（自用够用即可的部分）**：
  - 分享卡片：微信群转发的链接样式不可控（与 1.1 定的做法一致），将来认证服务号就绪再升级（2026-10-10 实现补记：MVP 底线「链接照转」已落地——点「分享到群」优先弹系统分享面板，不支持的环境复制局详情链接进剪贴板并提示去群里粘贴；带图卡片仍挂起待服务号资质）
  - 改局无变更通知：名单里的人下次打开看到新信息即可，不为它建提醒
  - 截止判定不靠定时器：由"谁先打开或动这个局"触发，当场判完——开打前没人再打开的极端情况下，判定最晚发生在组织者/球友下一次打开时

## 7. 附录（后端必拼，本规格拼 B/C；A 记 3.2 修订面）

### 附录 A：前端行为（3.2 的修订面，随本规格实现）

**A1. 屏幕清单**
- 发局表单：新增"谁能翻到"三选（跟我打过的人 / 任何人 / 仅邀请），默认第一档；其余沿用 3.2
- 约球页列表：按档位过滤——"跟我打过的人"档只给同局打过的人看，"仅邀请"档不上列表；"我的局"不受档位影响（组织者/已报名/被邀者照常看到）
- 局详情、报名弹层：带人选择上限 3；其余沿用 3.2

**A2. 每屏的状态**
- 空状态：找局打翻不到任何局时显示引导（留个意向 / 发个局）；"我的局"为空显示"去翻个局 / 留个意向"；意向列表为空显示"还没有人留意向"；"仅邀请"档局多起来的圈子，列表空是正常态不报错
- 加载中：列表/详情等待提示，超过 2 秒提示网络问题
- 出错：提交失败提示可重试、已填内容不丢；链接失效给说明页；被拦的操作（截止后退出、带人超 3、时间倒挂）提示明确

**A3. 操作与响应**
- 报名/退出/邀请等操作即时反馈；重复点加入静默无事
- 改局上限改小：保存时提示将转候补的人数；误转可把上限改回去，候补自动转正（全程可逆）

**A4. 数据从哪来**
- 人头、还剩几坑、人均、候补次序、"已邀"标记与排序、名单锁定/终止状态——全部是系统算好给的定死结果，画面只负责显示，不自己加减
- 时间进度（还差几小时截止/开打）由准确时刻现场换算成文案

### 附录 B：后端行为

**B1. 触发与响应**
- 发局、报名、退局、改局、锁必打、订场登记、撤局、恢复、邀请、留改删意向——点下去 1 秒内给结果
- 截止判定发生在任何人打开或动这个局的那一刻，当场判完记档；不依赖定时器到点扫描
- 两人同一秒抢最后一个坑：系统保证只有一人进正式名单、另一人落候补，正式人头永远不超线；两人的操作都不报错
- 同一个人对同一动作重复提交（再点一次加入/再邀一次同一个人/已锁过的局再锁一次），一律就当没事，不产生重复记录

**B2. 失败时用户看到什么**
- 网络断：提示失败可重试，已填的内容不丢
- 被拦的操作（截止后退出、带人超 3、时间倒挂、开打后恢复/撤局）：一句人话提示拦下，界面停留在原处

**B3. 量放大 100 倍时**
- 热门局开报瞬间集中涌入：不丢报名、不重复占坑、允许等待提示——方向指引，不作为验收标准

### 附录 C：数据行为

**C1. 数据清单**
- 局档案：谁发的、时间地点、人数范围、规则三件、可见档、截止时刻、必打与订场登记、局的生死状态（报名中/已锁定/进行中/已结束/已终止/已撤）——组织者产生
- 报名行：谁、带几人、报名时刻、在正式名单还是候补、候补次序——球友产生；组织者是第一条
- 邀请记录：哪局、邀谁、何时——组织者产生
- 意向：一人一份（时段+频率+备注）+"已邀"标记+最后留/改的时刻（列表排序的依据：新留的和新改过的排前面）——球友产生

**C2. 谁能看 / 改 / 删**
- 局档案与名单：链接进来的人都能看（名单对外只显昵称+头像，手机号最多露尾号 4 位且仅同局可见——1.1 已定的规矩）；改的只有组织者（名单行本人可退）
- 可见档只管列表翻不翻得到，不管链接进不进得来
- 报名行/候补位：本人可退（截止前）；组织者可经"改上限"间接调整（后报转候补）
- 意向：谁都能翻（含游客，3.1 已定的规矩）；只有本人能改删自己的
- 邀请记录：只有组织者自己看得到（意向列表上的"已邀"标记是其对外的影子）
- 换设备数据都在——全部存云端，手机里只留钥匙（1.1 已定的规矩）

**C3. 留多久、删了会怎样**
- 局档案长期保存：打完的局永久可看（历史是资产）；撤局/终止的局从各列表消失，但底账留档不物理删除（对账与误操作留底）
- 注销账号（1.1）：未结束的报名自动退出；该人在名单与历史里显示"已注销球友"
- 意向：本人删掉即真没了（可随时再留）；"已邀"标记随下一次邀请自动产生、随本人改意向自动清

  - 等签到数据才算（未选，因为：那是 1.3 现场的交接棒，本域没有这数据，默认档落空）
  - 裁决人：用户拍板（评审两员同推 A）

  - 裁决人：用户拍板
