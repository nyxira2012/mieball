## 1. 这是要解决什么问题（人话）

- 现在，现场那本账只有组织者能开。组织者不点「开始打球」，球友对着卡片上"进行中"三个字干瞪眼——点进去是空的，还会被挡一句"只有组织者能开现场账"；倒计时只在页顶跑马灯里报全局最近的那一局，不长在自己那局的卡片上。
- 一句话的成功画面：开打前两小时，球友在约球页自己那局的卡片上看到「进入现场」，点进去现场已经亮着、签到一步到位；开打时刻一过，点进现场，账就是开着的——不用任何人再点开始；点进现场只是看，人到没到以签到为准；组织者迟到，球照样打。

## 2. 给谁用（按角色写）

- **组织者**：锁定必打之后，随时能把账先开了（不受两小时限制）；自己没来得及开、别人开的账，到场后自然说了算。
- **正式报名的球友**：开打前两小时内直接从卡片进现场看名册、签到；第一个签到的人自动当上管理员，现场不会因为组织者迟到卡壳。
- **候补球友、没报名的人**：app 内一律不服务——候补只要还是候补，就没有签到入口、进不了轮转名单（上场唯一路＝到现场扫场地二维码空降入册）；没报名的人卡片维持原样（只有时间和报名入口）。
- 与本功能无关的角色不受影响：约球页其他局的卡片、意向区、死局区一律不动。

## 3. 用户故事

- 作为**球友**，我想在开打前两小时从约球页直接进现场把到签了，以便不用干等组织者开账、人一到就能进轮转。（对应问题：进不去现场）
- 作为**球友**，我想在还早的时候看到自己那局离开打还有多久，以便安排出发时间。（对应问题：卡片没有临近感）
- 作为**组织者**，我想锁定必打之后随时把现场先开起来，以便人陆续到了直接就能打。（对应问题：组织者也得掐点）
- 作为**球友**，我想开打时刻一过点进现场就能签到上场、我第一个签到就能把现场管起来，以便组织者迟到球也不散。（对应问题：一切等组织者）

## 4. 输入 / 输出场景

### 场景 4.1：远看倒计时
- **身份**：正式报名的球友（组织者同样适用）
- **前提**：离开打还有两个多小时；局可以是报名中，也可以已锁定必开
- **操作**：打开约球页，看自己那局的卡片
- **结果**：卡片上显示离开打还有多久（照着开打时刻倒着走）；没有进现场的入口
- **禁止**：这个时段不显示任何进现场的按钮

### 场景 4.2：临近开门（本规格的主场景）
- **身份**：正式报名的球友
- **前提**：离开打不足两小时，且这局已定必开（锁了必打、订了场、或人数够到截止成局，都算）；现场账还没人开
- **操作**：在约球页自己那局的卡片上点「进入现场」
- **结果**：
  1. 现场亮起（账开张——两小时内谁先点进现场，账就开起来；点开只是看，不算到场）；
  2. 进现场页，能看名册、看场地，自己那一行有醒目的「签到」；
  3. 点签到，提示"已签到 · 自动加入候场队"，从此参与轮转；他是这本账开张后第一个签到的人，就自动当上管理员，屏幕给一句"组织者还没来 · 现场你先管着"（组织者到场自然说了算）；
  4. 只看不点签到也可以——不签到就不进候场队，看一眼不算到场。
- **禁止**：点卡片不等于签到；没点签到的人绝不进候场队

### 场景 4.3：局还没成局
- **身份**：正式报名的球友
- **前提**：离开打不足两小时，但这局还在报名中（没锁必打、截止没到）
- **操作**：打开约球页看卡片
- **结果**：卡片仍显示倒计时，没有进现场的入口；等这局定了必开（锁必打、订场或人数够到截止成局）之后，入口才出现。若截止时人数不够、局被判终止，卡片按现有的死局规则显示
- **禁止**：没定必开的局，谁都不能把现场硬开起来

### 场景 4.4：组织者提前开账
- **身份**：组织者
- **前提**：这局已定必开（通常是组织者自己锁了必打或订了场）；离开打还有两个多小时也行
- **操作**：在卡片（或球局详情页）点「开始打球」
- **结果**：现场亮起，自己当然全权；从这一刻起，所有已报名球友的卡片立刻变成「进入现场」——不再看时间，也不显示倒计时
- **禁止**：这局还在报名中时，组织者也开不了账——按钮位置显示一句"先锁定必打，才能开始打球"的指引（不是按钮悄悄消失）。这是一条现有行为的收紧：今天报名中的局组织者能直接点开始，此后不能

### 场景 4.5：到点点进即开
- **身份**：正式报名的球友（任何人）
- **前提**：已过开打时刻；这局已成局（必开）；一直没人提前开账
- **操作**：点卡片上的「进入现场」
- **结果**：现场已经是开的——不用任何人再点开始，谁先点进现场，系统顺手把账开了（点开只是看，不算他到场）；签到、记分一切照常。账开之后第一个签到的人自动当上管理员
- **禁止**：不显示"等组织者开账"之类的字样

### 场景 4.6：组织者迟到的现场
- **身份**：账开后第一个签到的球友（管理员）
- **前提**：现场是球友开的账，组织者一直没出现
- **操作**：正常组织现场——确认对局结束、排下一场
- **结果**：现场自主运转，不卡壳；名册上看得出谁是管理员（包括签到自动当上的），封管理员仍只有组织者能做；组织者到场后现场事项照旧与管理员同权处理，并可收回这位临时管家的身份（名册行上的管理员标识随之消失）
- **禁止**：不出现"现场无人管理"的死锁

### 场景 4.7：开打后才来的人
- **身份**：正式报名的球友
- **前提**：已过开打时刻，他第一次点签到
- **操作**：进现场，点签到
- **结果**：签到后统一显示"已签到 · 自动加入候场队"——不区分迟到与否、没有单独的迟到提示；排队天然按签到先后，签得晚的人自然排在后面。规矩始终一条：没签到就是人没到，人没到就排不进上场阵容

### 场景 4.8：候补球友
- **身份**：候补中的球友
- **前提**：他在候补名单里（无论开打前后、无论账开没开）
- **操作**：打开约球页看卡片；或人到现场扫场地二维码
- **结果**：
  1. app 里：卡片只显示倒计时和候补状态，没有签到入口，也进不了轮转名单——只要还是候补，app 签不了到；
  2. 唯一的上场路：人真到了现场，扫场地二维码强行入册（空降），扫码即签到、排候场队尾；
  3. 递补转正（有人退出即刻递补，现有规矩）后他就不是候补了，转正后按正式球友的规矩来。
- **禁止**：候补不触发开账；app 内不出现候补的签到入口

### 场景 4.9：网络不给力
- **身份**：正式报名的球友
- **前提**：点了「进入现场」，网络断了
- **操作**：等提示出现
- **结果**：提示"网络不给力，请稍后再试"，人留在原地；再点一次照常进现场（账只有一本，重试不会开两本）

## 5. 验收标准

- [ ] **正常流程**：距开打超过两小时，我那局的卡片显示倒计时、无进现场入口 —— 对应故事 2
  → 验证：用一局三小时后开打的局，打开约球页，卡片能看到倒计时在走、找不到进现场按钮
- [ ] **正常流程**：两小时内且局已定必开，卡片显示「进入现场」，点进去现场亮起、点签到排进候场队 —— 对应故事 1
  → 验证：把一局的开打时刻改到 90 分钟后并锁定必打，打开约球页点卡片按钮，看到现场页、自己那行点签到后提示"已签到 · 自动加入候场队"
- [ ] **正常流程**：只看不签不排队 —— 对应故事 1
  → 验证：进现场后不点签到，候场队里没有这个人；再点签到，候场队里出现他
- [ ] **正常流程**：组织者锁定后随时开账，成员卡片立刻变「进入现场」 —— 对应故事 3
  → 验证：组织者在一局开打前三小时点「开始打球」，用另一位成员的账号看卡片——已变「进入现场」
- [ ] **正常流程**：开打时刻过后，任何人直接进已开的现场 —— 对应故事 4
  → 验证：让一局过了开打时刻且无人提前开账，成员点「进入现场」，看到现场已在、无需任何人点开始
- [ ] **正常流程**：账开后第一个签到的人自动当管理员，名册看得出、组织者收得回 —— 对应故事 4
  → 验证：成员点卡片把账开了但先不签到，名册上无人是管理员；他点签到后名册上他的名字带管理员标识、能确认一场对局结束；组织者登录后能收回该身份，标识消失；他不能封别人当管理员
- [ ] **空状态**：没报任何局的人，卡片无倒计时、无入口 —— 
  → 验证：新账号打开约球页，卡片与今天的样子一致
- [ ] **加载中**：点「进入现场」后开门那一下的等待 —— 
  → 验证：慢网下点按钮，先看到等待的骨架画面，随后现场出现，全程无白屏
- [ ] **出错**：断网点进入 —— 
  → 验证：断网点「进入现场」，看到"网络不给力，请稍后再试"；恢复后再点，正常进入且只开了一本账
- [ ] **出错**：点进瞬间撞死局 —— 
  → 验证：在截止判定的当口进现场，若这局被判终止，看到该局已终止的死局样子、进不去现场
- [ ] **边界**：报名中未锁定的局，两小时内也没有入口 —— 
  → 验证：一局 90 分钟后开打但还在报名中，卡片只有倒计时；锁必打后入口出现
- [ ] **边界**：组织者不能开报名中的局（现有行为收紧） —— 
  → 验证：组织者打开报名中局球的详情页，按钮位置是一句"先锁定必打，才能开始打球"的指引；锁必打后才出现「开始打球」
- [ ] **边界**：候补 app 签不了到 —— 
  → 验证：候补成员的两小时卡片无「进入现场」、现场页里没有他的签到入口；他到现场扫场地二维码后，名册出现他（带空降标）并自动签到、排候场队尾；递补转正后才有正式球友的入口
- [ ] **边界**：签到提示不分迟到 —— 
  → 验证：开打时刻过后第一次签到的成员，提示与开打前签到同一句"已签到 · 自动加入候场队"；候场队按签到先后排序
- [ ] **边界**：账开后没有退报 —— 
  → 验证：开账后一名未到的成员无法退报（现有规矩），名册上他记"未到"；候补照旧没有 app 签到入口（人不够时靠到场扫码，见候补条）
- [ ] **正常流程**：详情页与卡片同规矩同文案 —— 
  → 验证：成员打开两小时内必开局的详情页，看到「进入现场」；组织者看到「开始打球」
- [ ] **边界**：两小时整是分界 —— 
  → 验证：距开打两小时零一分时卡片是倒计时；不足两小时（含整点）变入口

## 6. 边界与非目标

- ❌ 明确不做：候补的 app 签到、报名中局的开账、候场大厅中间态、跑马灯改动、既有 bug 修复。
  - 候补的 app 签到（只要还是候补，app 签不了到、进不了轮转名单；上场唯一路＝到现场扫场地二维码空降入册——人到没到只有到场能证明；递补转正后按正式球友规矩）；
  - 没定必开的局不开账（先锁必打或等截止成局，组织者同规）；
  - 预开的"候场大厅"中间态——开账即真现场，不做第二现场；
  - 正式球友的到场核验（签到显式点一下即算，不查位置不强制扫码——候补除外，候补上场只能到场扫码，见 4.8）；
  - 跑马灯倒计时条的去留改动（维持现状）；
  - 「点回到现场被弹回约球页」的既有 bug 不进本规格验收——随实现批一起修。
- ✅ 做但降级：
  - 倒计时粒度从粗（"还有 3 小时""明天 19:00"），不做秒级跳字；
  - 两小时门槛是定值，不做组织者自定义；
  - 临时管理员身份随局走、散场即止，不做转让/任期。

## 7. 附录

## 附录 A：前端行为

### A1. 屏幕清单
- **约球页·我那局的卡片（改动点）**：三种长相——倒计时（远）/「进入现场」（近且必开、账未开）/「进入现场」（账已开）——后两种同名，进去都是同一颗醒目的签到键；从哪进：打开约球页即见；做完去哪：后两种点进现场页。
- **球局详情页（同一套规矩）**：组织者的「开始打球」与成员的「进入现场」按同一套规矩出现——报名中的局谁都没有开账入口（给"先锁定必打，才能开始打球"的指引句），必开后组织者随时有、成员两小时内有，文案与卡片一致。
- **现场页（签到一步）**：自己那一行的签到入口要醒目（进现场后第一眼能找到）；其余照旧。

### A2. 每屏的状态
- **空状态**：没报局的人卡片维持原样，无倒计时无入口。
- **加载中**：点「进入现场并签到」后开门瞬间显示等待骨架（沿用现场页现有骨架），慢网不白屏。
- **出错**：断网提示"网络不给力，请稍后再试"，人留在卡片页可重试。

### A3. 操作与响应
- 点卡片「进入现场」→ 现场亮起并进入（账开后第一个签到的人，签到时看到"组织者还没来 · 现场你先管着"的提示）→ 签到提示"已签到 · 自动加入候场队"（开打前后同一句，不分迟到）。
- 只看不签：不产生任何到场记录，可随时再签。
- 误签到的救法沿用现有：报"早退"即记离场时刻（不新造撤销键）。
- 不做快捷键/批量签到。

### A4. 数据从哪来
卡片长哪个样，画面自己不判，全用引擎算好定死的：
- 开打时刻（倒计时照它走，画面只负责倒着数）；
- 这局成没成局（必开与否）；
- 现场账开没开、谁开的；
- 我是正式成员、候补、还是组织者。
签到后的候场队位置、迟到判定，也全是引擎算好送来的，画面一个字不改。

## 附录 B：后端行为

### B1. 触发与响应
- 已定必开的局，组织者随时点开始、成员两小时内点进现场：系统当场把账开好（秒级）。账开之后第一个签到的人自动记为管理员——点开看不算到场，没人签到时现场没有管理员，也不需要。
- 过了开打时刻的活局，谁先点进现场，系统顺手把账开了——不需要有人提前点，也不需要定时到点强开。
- 账只有一本：两人同时点进现场、或重复重试，都只开一本，后到的直接进已开的现场。
- 卡片要显示的"账开没开、谁开的"：系统从今往后记下每本账是谁开的，并把"账开没开"送到卡片上（这两笔今天没有记，是本规格要求新记的）。
- 账开着的时候没有退报这回事——局一定必开才能开账，必开的局本就退不了（现有规矩）；没来的人就是不签到，名册上记"未到"，仅此而已。人手不够时，候补也只有一条路：人到现场扫场地二维码空降入册，扫码即签到、排候场队尾（这条扫码入册今天的账本还不认，随本规格实现补上）；没有远程把候补补进名册的路。

### B2. 失败时用户看到什么
- 断网：提示"网络不给力，请稍后再试"，不丢数据，重试即可。
- 点进瞬间局恰好被判终止（截止人数不足）：进不去，显示该局已终止的死局样子。

### B3. 量放大 100 倍时
- 百人同时进同一局：账仍只有一本，众人先后拿到同一张现场画面，第一个签到的当管理员（只有一位）；十人自用规模远够。
