## 2026-10-05 打球页改版（2.1 · 依 temp/打球页原型.html）

**落点**：pages/live/live.vue 整页重写（编排层）；新组件 9 个 biz（LiveTopbar/CourtMatchCard/QueueBar/PersonSheet/CheckinSheet/QueueSheet/RulesSheet/EndSettleModal/QrOverlay）；stores/live.ts 改结算流；删退役 CourtCard/Scoreboard/QueueList/AttendRow/WinPopup。规格冲突的 7 条裁决记录在 docs/2.1 §六（遥测常驻/比分即按钮/歇两轮/确认制终局/到场者都发牌/登记页未做/换人最简互换）。

**裁决**
1. **弹层不走全局 SheetPayload**：点人/签到/队列/规则 4 抽屉+终局弹窗+二维码 = live 页本地弹层（liveSheet 单槽 ref）。理由：这些入口只存在于打球页，塞进全局 union 会把体量热点 api/types.ts 撑宽；全局单槽语义（开新顶旧）本地照抄。战力档案仍走全局 profile（打开前先关本地抽屉）。
2. **终局确认制的数据形态**：settling={sa,sb} 快照进 store（cur 不动），弹窗本地改分/选胜方，confirmSettle(winA,sa,sb) 内部重算 settleElo 落账（纯函数同入参幂等，预览与落账不会劈叉）。被否：EndSettleModal 直接改 cur——遮罩关闭=「回来说比分被改过」，语义脏。
3. **「还有 N 轮到我」公式**：ceil((4×待开片数 + 队列位次 + 1) / 4)——待开片的人排我前面、在打的人结算后回队尾不挡我。推导锚过原型演示数据（待开 1 片 + 我第 3 位 = 还有 2 轮）。
4. **片数/场馆/场地名/到场判定收单一源**（末批刺客 4 Blocker 全是「同一知识第 2-3 回散落」）：maxCourts→utils/rotate、venueOf/courtLabel→utils/format、isArrived→stores/live、badge 色板→base.scss。改片数规则/loc 格式/显示名时只动一处。
5. **slice_commit 期间遇并行暂存**：批1 时用户另一会话在暂存区留了活（simplify 整理），脚本按设计拒绝混合提交；待其提交后（4711c2f/2a497e0）正常走 slice_commit，未发生混合。

**坑**
- **backdrop-filter 对 opacity:0 的元素照样生效**：EndSettleModal/QrOverlay/AppSheet 的全屏遮罩常驻 DOM、只切透明度，隐藏态的毛玻璃+暗底把整页压糊（用户实测「屏幕是模糊的」）。修法：隐藏态连 `visibility: hidden` 一起收（visibility:hidden 下 backdrop-filter 必定失效），过渡列表补 visibility 保证淡出后再隐。原型是 display/存在性切换所以没这问题——凡是「常驻 DOM + 类切换显隐 + backdrop-filter」三件套齐了就必须收 visibility。
- **vue-tsc 不查模板表达式语法**：PersonSheet 里 `emit('swap-mode', false')` 多一个引号，type-check 0 错、vitest 全绿，dev server 才炸（vite:vue Unterminated string）。模板里 emit 字符串参数要靠 H5 起服务走查兜底——本轮浏览器走查正是抓的这个。
- **uni-input 的 placeholder 不走原生 attr**：Playwright getByPlaceholder 拿不到（getAttribute('placeholder')=null），定位 uni-app 输入框用容器类名 + input 标签。
- **同页 hash 深链不重跑 onLoad**：?id=102 换 hash 不切局（uni-app H5 hash 路由同页不重挂），走查要 tab.reload() 强刷。
- **建号换 id 撞上 mock 种子**：扫码建号把 U.me.id 从 0 改成新 id，场上/队列里的旧 0 号变孤儿（显示"—"）。真实扫码路径不触发（访客不在册），显示层已做 byId 过滤兜底；根修要等真账号体系接管 live 名册。
- **走查注意**：AppSheet 常驻 DOM 只切类——DOM 快照里能看到所有抽屉的文本，「存在」不等于「开着」；判定看 .sheet.on。

**验证**：vue-tsc 0 错；vitest 10 文件 137 用例全绿（+2：setCheck late 进队尾、avail 放行 late 发上场）；H5 真页走查全流程（只读拦截/记分弹结算/改胜方预览/确认落账联动战力榜/带访客/歇两轮/换人/规则/二维码/撤分清零取消/自动排阵/深链/建号链路）。

## 2026-10-04 账单「欠款对手方」（5.1 修订实现）

**落点**：类型（BillPayer/Bill.payee/payers）进 api/types.ts；种子重写进 mock/data.ts；口径与动作收口在 stores/bill.ts；行内展开、「谁还欠你」块、欠 ××× 行在 pages/mine/bills.vue。该收金额口径单点收口在 store 模块层 amountOf，页面与三数都消费它，页面不自算人均（明细由数据侧给好，界面对给定明细加总合法）。

**裁决**
1. **该收三数＝未结明细加总**（别人"还"该还我的）。否掉了实现工先提的「amt − 运行期逐人已收」扣减表方案：它语义不自洽（种子里已结的钱仍算该收、运行期收的才扣），还引入 store 侧额外状态。纯推导无新状态，且与「谁还欠你」（debtors）天然同源——该收三数 === Σ debtors，测试里有恒等断言锚。裁决人：主 agent（依据规格原文"我垫的钱别人该还我"的"还"字）。
2. **行点击按 status 分类，不按 payers 存在性**。运行期全清翻转的 received 行仍带 payers 数据，若按数据分支会展开而不进局详情——刺客 Blocker，谓词统一 `status === 'receivable'`。
3. **mock 种子 bill 6（94 局）从 received 翻成 receivable**：为了让「谁还欠你」演示同一人跨两场聚合（亮马河快攻 100+90=190·2场）。received 态运行期可达（一场全结清自动翻转），静态四态少一个演示位是接受的代价。
4. **旧案作废**：刺客合议 #2「org 行 amt＝垫付总价」→ 新口径「org 行 amt＝别人摊费合计（我自己那份自己出了）」，types/mock 注释已同步留痕。

**坑**
- slice_check 的 SC5「导出无使用方」不认 .vue 文件里的 import——BILL_STATUS_NAMES / PERIOD_OPTS / PERIOD_FROM 三个导出被误报，实际 bills.vue 与 logs.vue 都在用。以 grep 复核为准，别急着删"化石"。
- 三数总览的「已付」不含别人还我的钱（四个状态是逐笔的，别人已结的部分只活在逐笔行的"已收 ¥X / 共 ¥Y"里）——三数语义是"我欠的/我付的/别人还欠我的"，别把它读成收支总账。
