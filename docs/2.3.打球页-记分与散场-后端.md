## 1. 这是要解决什么问题（必填，人话）

- 三片场同时开打是常态，现在的记分却挤一条道：同一时刻只有一片能上记分板，其余排着等上一场结束——组织者一个人追着三片跑，记不过来。
- 现在待确认锁的只是记分，而且是全场一刀切：只有一片在打时看不出毛病，可多片并行后「1 号片弹确认、2 号片照打」时，待确认那片上的人还能被换走——回头落账，战报名单和实际打过的人对不上。
- 手抖连按两下 +1，现在真会多一分（没有防护）；往后现场账要搬进全场一本的总账，连击、弱网重发、两人同时记，每一样都能把账记乱——防线得一次立好。
- 散场没有走到底的收尾：残局没人清、战报和考勤没有封存的终点，组织者提前走了连局都散不掉，赛后想翻「今天都打了什么、谁几点走的」没处翻。
- 成功画面：三片场各记各的分，谁得分点谁那边；到分或人工提前收都先进「待确认」、由人点头才落账；确认完胜者败者各回各家、积分当场结算、该片自动补人、全场手机秒同步；散场时把残局逐片清干净、全场封存；赛后扫码还能回看战报。弱网连击，分不重不错。

## 2. 给谁用（必填，按角色写）

- **组织者**：全场写权——记分、换人、规则、场地、封/撤管理员、结束对局类动作（清零、改比分、提前结算、确认、取消对局）、散场收局（现场散或从「我的局」远程散）；只有他能封撤管理员、只有他能散场（组织者早退时管理员可代收，沿 2.2）。
- **管理员**：组织者现场临时封的帮手，与组织者同权处理现场事项（含结束对局类动作），随时可封可撤；封谁撤谁是组织者独有，管理员不能再封别人；权限只在单个球局内有效，散场即止。
- **球友（已签到）**：可给任意一片记 ±1 分、可换任何人（沿 2.2，操作留名）；自己的事自己管（到场、早退、休息一轮/连战）；结束对局类动作与散场碰不了。
- **赛后回看的人**：任何人扫码能看战报与名单；考勤时刻（谁几点到、几点走）只有组织者和本人能看。
- 不为任何角色服务的部分：无。
- 与本功能无关的角色：没进现场的球友不受影响（谁能看谁的名单，1.2 已管，本册不动）。

> 谁能做什么，全靠 §4 场景讲清楚，不另立权限表。

## 3. 用户故事（必填）

1. 作为球友，我想给任意一片加分、撤一分，以便组织者没盯着的片也有人把分记上。（§1 问题一）
2. 作为组织者，我想记岔了能撤、搞砸了能清零重开或作废，以便现场任何乌龙都有出口、不把脏账带进积分。（§1 问题一、三）
3. 作为组织者，我想到分或提前收都先进「待确认」、由人点头才落账，以便比分记反、记错都能在落账前纠正。（§1 问题二）
4. 作为球友，我想待确认的片锁住不动、别的片照常打，以便确认那一两分钟里比赛不乱。（§1 问题二）
5. 作为组织者，我想确认窗里能点胜方、调比分、看每人 ±积分预览，以便落账前最后一眼把账对齐。（§1 成功画面）
6. 作为记分的人，我想手抖连按、断网重发比分也不重不错，以便球馆信号差不至于记出鬼账。（§1 问题三）
7. 作为组织者，我想散场时逐片清残局、一键收尾，以便不留悬挂对局、战报考勤有个干净终点。（§1 问题四）
8. 作为球友，我想赛后扫码回看今天的战报，以便没赶上结尾也知道打了什么比分、谁赢了。（§1 问题四）
9. 作为带访客的球友，我想访客按新人初始等级代入、我自己的积分照常结算，以便带朋友来打球不亏我的分。（§1 成功画面）

## 4. 输入 / 输出场景（必填，文档核心）

> 前提沿用 2.2：现场已点亮，名册、候场队、轮换方式都在；本册从「一片上有人开打」接手。每片场地是独立的一本小账：**空闲（人不满）→ 在打 → 待确认 → 落定后回到补位**；1 号片弹确认窗，2 号片照常加分，互不牵连。全场只有一本总账，谁改了什么，几秒内大家的手机看到同样的变化。

### 场景 4.1：记分与撤一分（任意签到的人）
- **身份**：组织者、管理员或球友——谁能上场区域谁就能记（沿 2.2）
- **前提**：至少一片在打；全场共用一个分制（规则抽屉里定的 11/15/21 分，全场统一；开打后改分制＝在打那局照旧打完、下一场起按新制，见 §8 2026-10-08 修订）
- **操作**：点某片卡底的大数字——点哪边哪边加 1 分；点「撤一分」减 1
- **结果**：
  1. 比分跳动，全场几秒内看到同样的数
  2. 每片各自记住「最后得分方」；撤一分只撤**该片最后一次得分方**的那 1 分，别片的、别的时候的一概不动
  3. 多片同时记互不影响：1 号片加着分，2 号片照样加它的
- **禁止**：撤分撤成负数。

### 场景 4.2：清零重开（组织者/管理员）
- **身份**：组织者或管理员（球友点清零提示「请找组织者或管理员」，沿 2.2）
- **前提**：某片在打或待确认，比分记乱了——站位反了、球拿错了
- **操作**：在打时从片卡点「清零重开」（待确认时从确认窗里点）→ 弹一句后果「这片比分归零、重打这一盘，人不下场」→ 再点一次确认
- **结果**：该片比分归 0:0、「最后得分方」清掉、待确认状态作废、这片回到在打；四个人不下场，这盘重新打
- **禁止**：清零把人弄下场或弄进候场队——人是同一批人，只清账。

### 场景 4.3：到分自动进待确认（任意记分人）
- **身份**：任意签到的人（谁点的最后一分都一样）
- **前提**：某片在打，比分到了「分制数且净胜 2」（如 11 分制的 11:9、13:11）
- **操作**：无——记到分线那一刻自动发生
- **结果**：
  1. 该片自动进入**待确认**，这片卡上弹出确认窗（片号、两队名单、当前比分、胜方预选）
  2. **该片冻结**：这片上的加分、撤分、换人锁死，谁点都不动；其他片的记分、换人照常。冻结不锁出口——清零重开与取消对局照常可用，待确认时入口收在确认窗里，仅组织者与管理员能点
  3. 球友看这扇窗只能看：确认按钮是灰的，旁边一句「请组织者或管理员确认」（沿 2.2 §4.8）
  4. 多片同时待确认是正常情况：各片各弹各的确认窗，互不等待
- **禁止**：待确认的片继续加分、撤分或换人；一片待确认拖累别的片。

### 场景 4.4：提前结算（组织者/管理员）
- **身份**：组织者或管理员
- **前提**：某片在打，还没到分线——包时到点了、双方商量散了、有人临时有事
- **操作**：该片卡上点「提前结算」→ 弹同一扇确认窗（胜方默认预选当前领先方；平分时不预选，手点胜方后才能确认）
- **结果**：该片进入待确认，与到分自动触发走同一条路（冻结、窗内可改胜方调比分）
- **禁止**：球友点提前结算（提示找组织者或管理员）；提前结算绑时间限制——没有，随时可收。

### 场景 4.5：确认窗里发现加错了，撤一分接着打（组织者/管理员）
- **身份**：组织者或管理员
- **前提**：某片待确认中，但分是多记的——比如 10:9 时手抖点了两下变 11:9，触发了待确认，实际比赛没打完
- **操作**：在该片确认窗里点「撤一分」
- **结果**：
  1. 撤掉最后一个得分方那 1 分，窗内比分跟着变，撤完重新判一次
  2. **到分自动弹的窗**：还够分线的（如 15:12 撤成 14:12，仍净胜 2），窗留着、比分已改；不够了的（如 11:9 撤成 10:9），窗自动关、该片回到在打、比赛继续
  3. **提前结算开的窗**（本来就不到分线）：撤一分只改比分、窗不关——窗是人工开的，收不收由人再决定
- **禁止**：无

### 场景 4.6：确认结束对局、排下一场（出口 A）（组织者/管理员）
- **身份**：组织者或管理员
- **前提**：某片待确认中
- **操作**：在确认窗里——点胜方（防左右记反，可改预选）、微调最终比分（纠偏）、看每人 ±积分预览 → 点「确认结束 · 排下一场」
- **结果**：
  1. **战报上账**：追加一条谁也改不了的战报——片号、这片今天的第几场、两队名单、比分、胜方、结束时刻；落了账的战报组织者也改不了。调完比分胜方自动跟到分高的一方——分低的一方当不了胜方，落不出「分低的赢了」的战报
  2. **积分结算**：确认的这一下里同时办完——战报上账、积分结算、人回流、空位补上，要么都办成、要么都不办，不会出现战报记了、积分没落的半截账。积分按战力域那本册定好的公式算（公式和里面的数都归它管，本册不写数值）；随行访客按**新人初始等级**代入一起算，同场的正式球友照常结算，**访客自己不落账、不进榜**；预览与结算不一致时，以结算回来的数为准，画面自动改成一致的
  3. **人员回流**（按 0号的「轮换方式」）：谁下、谁留场、缺几人从候场队哪里补，全按轮换规矩办——规矩的真值归《2.4 轮换算法》册，本册不重定义；随行访客与正式球友同规（打赢照样留场，沿 2.2 §4.13 现行文本）
  4. **自动推进**：该片空位马上按轮换方式补上，只重排这一片，其他在打的片一概不动；确认完的那一下，全场每个人手机上的现场画面都换成最新的
- **禁止**：确认动作只动该片；落账后的战报与积分再改（纠偏归战力域那本册）。

### 场景 4.7：取消对局（出口 B）（组织者/管理员）
- **身份**：组织者或管理员
- **前提**：某片在打或待确认——争执、拉伤、发错牌，这场不算了
- **操作**：在打时从片卡点「取消对局」（待确认时从确认窗里点）→ 弹一句后果「这场比分作废不计分，场上的人回候场队最前面」→ 再点一次确认
- **结果**：这场对局彻底作废、不计积分、不进任何人的战绩；场上的人**原样回流候场队首**（补偿没打成的，沿 2.2 §4.12）；该片腾出来重新发牌
- **禁止**：作废的对局留下任何积分或战报。

### 场景 4.8：弱网连击与两人同时记分（防线，自动发生）
- **身份**：任意签到的人
- **前提**：球馆信号差，或两个人几乎同时动手
- **操作**：各自点各自的（手抖连按两下 +1；断网后重点一遍；组织者在 1 号片记分、球友同时在 2 号片记分）
- **结果**：
  1. **不同片同时记**：两笔都生效，互不拒绝
  2. **同片两人先后点**：先到的那笔算数；后到的发现这片已经变过、自己拿的是旧画面，这笔被退回，同时最新的画面送来。他看一眼最新比分：自己要记的那分已经在里面（和先到那人记的是同一分）——**不用再点**；自己要记的是另一笔、不在里面——再点一下补上。无论哪种，都不会记两次
  3. **手抖连按 / 断网重发**：第一下已经把这片往前推了一步，重放的那一下被拒——比分只加一分，不重、不跳字
  4. 记分这类只动一片的事按「片」拦，出勤、换人、规则、场地这类动全场的事按「全场」拦，同一套规矩——现场几十笔写操作，账永远只有一本
- **禁止**：重复计分、旧画面覆盖新变化、两边长期各记各的（最迟几秒对齐）。

### 场景 4.9：散场收工（组织者）
- **身份**：组织者——现场散，或从「我的局」里对进行中的局**远程散场**（换了台手机、人先走了都能收）；组织者已标早退走了的，管理员能看到散场按钮代收（沿 2.2 §4.14 兜底）
- **前提**：现场已点亮；可能还有片在打或待确认
- **操作**：点「散场 / 结束球局」→ 还有在打或待确认的片时，**散场先不放行**：弹出残局清单逐片强制处理，每片三选一——**确认这场比赛的比分**（待确认的片直接在窗里调好比分胜方、确认结束）/ **提前结束**（在打的片开同一扇确认窗定胜负）/ **取消**（作废）；另有「未完对局全部取消」一键处理 → 全部片处理完，散场放行 → 再点一次确认，收工（没有残局时直接二次确认收工）
- **结果**：
  1. 清扫里对每片的确认与取消，落账规矩与平时一模一样（战报、积分、人回流照常），但**不排下一场、不补位**——散场途中的对局没有下一场，人只回流定格，不会有人被补上一块没人打的片
  2. 全场落定：球局从「进行中」转为「已结束」；战报汇总封存；考勤底账（谁几点到、几点走、哪位访客是谁带的）定格
  3. 积分不用补算——每场确认时就实时结算完了，散场只是封存；费用怎么按考勤摊，交给账单那本册
  4. 二维码不销毁，转为只读回看（见 4.10）
- **禁止**：跳过残局直接散（每片必须被「确认」或「取消」处理完）；散场后再动比分、战报、考勤。

### 场景 4.10：赛后只读回看（任何人）
- **身份**：扫到二维码的任何人——参加过的球友、没赶上结尾的人、组织者
- **前提**：球局已散场
- **操作**：扫散场后的二维码（或从我的局点进）
- **结果**：
  1. 进的是**只读回看**：能翻本场战报（每片每场的比分与胜方）、名单（含访客挂谁名下）；组织者和本人还能看考勤时刻（谁几点到、几点走）
  2. 到场、签到、记分这类写动作全部关闭——旧画面上残留的点按一律被拒并提示「球局已结束」，页面是翻旧账的，不是续摊的
- **禁止**：扫已散场的码还能改任何东西；随便扫到的人看别人的考勤时刻。

### 场景 4.11：积分预览与访客标识（确认窗内，组织者/管理员看、战报同款标识全场可见）
- **身份**：组织者或管理员（预览）；球友在战报里看标识
- **前提**：某片待确认，窗内点胜方、调比分
- **操作**：每改一次胜方或比分
- **结果**：
  1. 每人 ±积分**当场跟着变**——预览按战力域同一份公式当场算（当场变、不等网络），算完的权威数字以确认为准回来落账
  2. 预览行里随行访客带「访客 · 不计积分」标识，战报里同样带——带客的人看得明白
  3. 战报与预览里的积分数字不一致时（公式改过等），显示改成落账回来的那个数
- **禁止**：预览数当成落账数（落账只认结算回来的）。

## 6. 边界与非目标（必填）

- ❌ 明确不做：
  - **超时自动确认**——待确认挂着没人管，现场喊一嗓子就解决；散场清扫兜底，不留悬挂（拷问已否）。
  - **对局中途暂停**——清零重开（人不下场重打）与取消对局（作废回流）把两头兜住，中间态不设（拷问已否）。
  - **散场后改战报 / 散场反悔恢复**——战报不可篡改是积分可信的地基；散场是危险动作，先弹后果二次确认，落定即封存（拷问已否）。
  - **逐球记录**——撤一分只需要「最后得分方」，逐球时序自用场景没消费者（拷问已否）。
  - **按片各定分制**——全场统一一个分制，一处改全场生效（拷问已否）。
  - **访客积分半折**——整体作废：改按新人初始等级代入、访客不落账不进榜（本册修订清单②）。
  - **散场清单里行内改比分**——改比分的能力收进确认窗（确认比分/提前结束的窗里都能调），散场弹窗不另养一个改分编辑面（评审轮裁决）。
  - **发牌与换人算法本身、积分公式与数值**——发牌归「发牌与换人算法」册（本册只管「确认后该片补位/重排」的触发与边界），公式与数值归战力域册。
- ✅ 做但降级（自用够用即可的部分）：
  - 积分预览是**当场按公式估算**给看的，落账以结算回来的权威数为准、不一致自动修正显示——不保证两边永远分毫不差，但保证最终账只有一本。
  - 战报「不可篡改」指落账后不能改，不提供「更正申请」类流程——记错了用下一场打回来，积分纠偏归战力域。
  - 「邀访客注册」不在本册做全——跨名片域的事，本册只在战报/预览留「访客 · 不计积分」标识，注册转化记待裁决。

## 7. 附录（前端必拼，后端/数据按需，同样人话）

### 附录 A：前端行为

**A1. 屏幕清单**
- 打球页（现有页面）：本册重造其记分部分——每片卡的独立记分框（比分即按钮）、待确认覆盖层（该片冻结的呈现）、按片就地的确认窗（胜方/比分/±积分预览/访客标识，清零重开与取消对局的待确认入口也在此窗）、「提前结算」「清零重开」「取消对局」入口（球友视角不可点或不见）。
- 散场流程：从「散场 / 结束球局」进——残局清单逐片强制处理（确认比分/提前结束/取消）＋「未完对局全部取消」一键，全清完放行散场，收尾二次确认；「我的局」里进行中的局也有散场入口（远程散场）。
- 只读回看态：散场后扫码/点进看到的画面——战报、名单、（组织者与本人的）考勤时刻，全部只读。

**A2. 每屏的状态**
- **空状态**：全场没有在打的对局——各片空闲态（还差 N 人 / 待开），记分不可用；回看态找不到战报时提示「球局不存在或已结束」。
- **加载中**：进现场页，各片比分与状态几秒内出全，先出灰色占位块，不白屏。
- **出错**：断网/失败提示「网络不给力，请稍后再试」可重试；重试后比分不多加、确认不重复落账；被并发挡下的那笔显示「现场已更新」并自动对齐，不用用户自己刷新。

**A3. 操作与响应**
- 点数字 +1 → 比分即时跳动 → 全场几秒同步；撤一分即时生效。
- 到分/提前结算 → 该片确认窗就地弹出 → 该片冻结（加分/撤分/换人点不动；清零重开与取消对局从窗里可点）→ 窗内改胜方调比分预览即时变。
- 窗内撤一分 → 比分变 → 到分自动弹的窗：够分线窗保留、不够自动关回到在打；提前结算开的窗：只改比分不关窗。
- 确认结束 → 窗关、战报与人流按 §4.6 落定 → 该片新对阵几秒内出现。
- 危险动作先确认：清零重开、取消对局、散场——点下先弹一句后果，再点一次才执行（沿 2.2 防线）。
- 越权操作前置拦截：球友点结束对局类按钮置灰或提示「请找组织者或管理员」，不是点完才报错（沿 2.2）。
- 误操作可救：加分有撤一分、清零有确认防线、待确认有窗内撤分回在打；落账后的战报无撤销——以确认窗为最后一道闸。

**A4. 数据从哪来**
- 画面上每片的比分、最后得分方、状态（空闲/在打/待确认）、待确认窗里的名单与预选胜方，都是现场总账**算好定死**给的，画面只负责显示，一个字不自算。
- 身份旗也由总账视图直接给定（2026-10-08 修订）：「我是组织者吗／我是全权吗／组织者是谁」三个定值随视图下发，画面直读不再自己拼——翻批4a 的「视图不带身份块、前端拼 viewer」（拼装在深链冷启动依赖异步身份与局簿缓存，「组织者按不了散场」补丁族由此而生；详见开发日志当日条目）。
- ±积分预演由总账**算好两套**随画面给（2026-10-08 修订：Elo 分差只看两队现分与谁胜、与比分无关——A 胜/B 胜各一套，点胜方当场切换，仍当场变、不等网络；公式收归后端唯一处，前端不再持拷贝，预演与落账走同一条算路，逐行一致）。页面要让预演看起来就是预演（访客行的「不计积分」标识一并显示）。
- 战报条目（片号、第几场、名单、比分、胜方、时刻）是落账时定死的，回看页原样翻出，不重算。

### 附录 B：后端行为

**B1. 触发与响应**
- 记分/撤分：即时生效；别人动手的变化几秒内出现在各自画面（画面定期与总账对表，沿 2.2）。
- 到分判定：每笔记分落账时当即判「分制数且净胜 2」，够线立即把该片转待确认——不靠手机端提醒。
- 确认结束：一下办完战报上账、积分结算、人员回流、该片补位（要么都办成要么都不办）；确认完全场画面换新。散场清扫途中的确认与取消落账规矩相同，但不排下一场、不补位。
- **连击与重发的防线（两级号）**：全场记一个总号（任何改动都往前进一），每片另记自己的号（该片记分类改动往前进一）。每笔改动都带着「我出发时看到的号」——号对得上才办，号落在后面的说明别人先改过：这笔退回、最新画面送来。只动一片的事（记分/确认/取消）按该片号拦，动全场的事（出勤/换人/规则/场地）按总号拦——组织者与球友在两片同时记互不拒绝，只有同片并发才被挡。（这套号是实现的路数之一；用户看得到的行为，以场景 4.8 的承诺为准。）
- 权限与状态由总账把关：球友的越权动作（清零/改比分/确认/提前结算/散场）就算绕过画面直接送到，也一律拒绝并回同一句提示（沿 2.2）；散场后旧画面上的任何写动作一律拒收，回一句「球局已结束」。

**B2. 失败时用户看到什么**
- 断网/失败：提示可重试；重试送来的还是旧号的改动，会被防线拒收并送回最新画面——到场只记一次、比分只加一分、确认只落一次账。
- 部分成功：散场清扫逐片处理，一片成一片；某片处理失败时清单停在那一片，提示重试，不用从头再来。

**B3. 量放大 100 倍时**
- 几百人的「现场」、十几片同开：先扛不住的是画面同步速度（对表变久、战报刷不过来）；但总账不乱——每片各自的号各自拦、全场一个总号，慢而不错，比分不会因量大而重或丢。
