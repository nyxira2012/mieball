## 1. 这是要解决什么问题（必填，人话）

- 散场后的战报页**出无收尾**：它住在底部「现场」格子上，没有正式的「看完走人」动作——打完的死局一直占着现场页，直到下一场球开局才被换掉。
- **回无入口**：「回现场」的入口在散场那一刻就被收走（那是给「到点没散、回去补散场」留的），此后 App 内翻不了旧账；唯一的后门是贴在场地边的二维码——场都散了，扫不到。
- **记录漏人**：打球记录列的是「报名过且打完」的局——**空降**进场的（扫码进场没报名）打过球、积分也落了账，记录里却查无此局；偏偏「没赶上结尾、最想翻战报」的就有这批人。（缺席照摊的今天就在记录里——报名没退就一直在，本册不改不收窄。）
- 成功画面：散场当场，战报页上部一行醒目提示「赛后可在 我的-打球记录 翻看」，右上角完成与分享并排——点完成，现场页收摊，别的在办球局接上；点分享，战报链接发进微信群。赛后哪天想回味，从 我的-打球记录 点那局的卡片 → 局详情 → 「查看战报」，翻回的就是同一页。群友点链接，谁都能看。

## 2. 给谁用（必填，按角色写）

- **组织者**：散场当场体面收尾，并把战报晒进群里——分享欲的顶点不被绕路凉掉；免费局里忙前忙后没顾上场的组织者，自己组的局也在自己的记录里。
- **空降的球友**：赛后在打球记录里找到这局，翻战报看自己打的比分、积分涨跌。
- **摊了钱没上场的球友**：账单里有这局，记录里也有——两本账对得上（现状已如此，本册守住房不被收窄）。
- **拿到分享链接的任何人**（没赶上结尾的球友、想看热闹的路人、未登录的游客）：点开链接就看战报，不用到场、不用翻 App。
- 不为任何角色服务的部分：无。
- 与本功能无关的角色：没散场的局不受影响（「查看战报」不亮、现场页照旧）；终止、取消的局不涉及（没有散场定格，无从翻起）。

> 谁能看什么，全靠 §4 场景讲清楚，不另立权限表。

## 4. 输入 / 输出场景（必填，文档核心）

> 前提沿 2.3 §4.9-4.10：球局散场确认完成，现场页已原地翻成战报页（战报、名单、考勤分权照旧）。本册从「散场之后怎么出去、怎么回来」接手。**同一份战报内容，两个门牌**：现场格子上的战报页（散场当场看、分享链接落点）与从打球记录进的战报页（普通子页，带返回）——长相一致，右上角都是「完成」与「分享」两个键，各自的意思见 4.1/4.2。

### 场景 4.1：散场当场，战报页收尾（在场的人）
- **身份**：散场那一刻在现场页上的人——组织者、管理员、球友
- **前提**：球局散场确认完成，现场页已翻成战报页
- **操作**：看提示、点完成、点分享
- **结果**：
  1. 战报页**上部**有一行醒目提示（这局的人才见这句）：「球局已结束 · 赛后可在 我的-打球记录 翻看」——不弹窗、常驻可见，不点完成也知道去处
  2. 右上角两个键：**完成** 与 **分享**
  3. 点**完成**：现场页收摊——本局信息**只清自己这部手机上的画面**，别人手机上的战报页不受影响，账更是一点不动；若我还有别的在办球局，现场页接上显示那个（同时在办多个时挑最近开打的），否则显示「还没有进行中的球局」
  4. 点**分享**：拉起手机系统分享面板（能直接发微信）；系统不支持分享面板的设备，复制战报链接并提示
  5. 不点完成直接切走照旧可以——战报页仍挂在现场格子上，下次切回还在，直到点完成或下一场球开局
- **禁止**：收摊后现场页残留本局任何信息；收推动到战报与记录本体（收摊只是画面，随时从记录翻回——验收见 §5）。

### 场景 4.2：赛后再看，从打球记录进（这局的人）
- **身份**：这局的组织者，或上过场、或账单里有份的球友（含空降、缺席照摊——名单怎么判见 4.4）
- **前提**：球局已散场；已登录
- **操作**：我的 → 打球记录 → 点那局的局卡片 → 局详情页点「查看战报」
- **结果**：
  1. 打球记录列表里出现这局，点局卡片先进局详情（沿既有习惯）
  2. 局详情页上已散场的局亮出「**查看战报**」；能打开这局详情的人都见此键——战报本就是链接即门票，多一个门不多拦一个人
  3. 点进去的是战报页——内容与散场当场那份一模一样（战报、名单、考勤分权照旧）
  4. 这是个普通子页：手机返回键或页上返回即出，回到局详情；右上角同样有完成与分享，点完成＝退出这页回到来路
- **禁止**：未散场的局亮「查看战报」；记录列表出现我没上过场、没摊过钱、也不是我组织的局。

### 场景 4.3：分享与看分享（任何人）
- **身份**：分享者＝这局的人（两处战报页右上角都有分享）；看的人＝拿到链接的任何人
- **前提**：球局已散场
- **操作**：分享者点分享发群；看的人点链接
- **结果**：
  1. 看的人打开的是战报页（落在底部「现场」格子上）——战报与名单全可见
  2. 考勤时刻分权照旧：组织者全见、本人见自己，其余人看不到任何人的考勤时刻
  3. 看的人若是这局的人（按 4.4 同一把尺判），上部提示行是「可在 我的-打球记录 翻看」；不是——路人、以及**未登录的一律**——提示行换中性说法（如「球局已结束 · 战报仅供回看」），不指一条走不通的路
  4. 看的人也能再分享（右上角分享照常）；点右上角完成，现场页同样收摊——收摊后同 4.1-3：有在办局接最近开打的、无则空态（沿现场页既有的「还没有进行中的球局」）——**点链接只让自己的现场让位，不丢自己的现场**
  5. 战报页零写动作——翻旧账的页，不是续摊的（沿 2.3 §4.10，写了也一律拒收「球局已结束」）
- **禁止**：点链接的人改任何东西；路人和游客看到别人的考勤时刻。

### 场景 4.4：打球记录里谁有这局（名单的判定规矩）
- **身份**：每个与这局有交集的球友各自验证
- **前提**：球局已散场。判定规矩＝**上过场的**（现场账里有上场记录）**或 账单里有份的**（摊了钱的）**或 这局的组织者**（谁发起的，局档案里记着）——满足其一，这局就算「打过」
- **操作**：无——系统照规矩自动列，用户无感
- **结果**：
  1. 空降的球友：记录里有这局，点开能翻战报
  2. 报名了没来、钱照摊的：记录里有这局（现状已如此——报名没退就一直在，本册不改不收窄）
  3. 免费局（不收钱的局，账单上没账可出）里没上场的人：只有组织者按第三笔算进来；签到到场但一场没上的板凳球友不算——两本账对得上，按同一把尺给中性提示，不说假话
  4. 带访客的担保人：自己按前三笔判；访客份额记在他账上
  5. 纯候补没转正、没到场没摊钱的：记录里没有
  6. 访客本人：无账号，不涉及
  7. **记录跟着账单走，不跟着散场时刻走**：组织者散场后才补填总价、账单晚几天才出的，账单落定的那一刻，这局自动长进相关人的记录——不是散场那一刻一次算死
  8. 这把尺对**全部已散场的局**生效，包括本册上线之前就散场的老局——存着的账按新尺重列，历史空降照样翻得回
  9. 记录页头部写「累计打了 N 场**对局**」——「场」数对局、列表行数球局，单位写全，各表各的，谁也不欠谁
- **禁止**：规矩走样——放宽成「报名过就算」（候补没上场的会混进来）或收窄成「只算上过场」（摊了钱的对不上账）都不行。

### 场景 4.5：零战报的局（开局即散）
- **身份**：这局的人
- **前提**：散场时一场对局都没落下（全员没上场就收工）
- **操作**：从打球记录点进「查看战报」
- **结果**：战报页显示「这场没落下战报」的空态，名单照常显示；分享照常（链接打开是同款空态）
- **禁止**：无

### 场景 4.6：链接指向的局不存在（边缘）
- **身份**：点链接的人
- **前提**：局被撤销、或链接损坏
- **操作**：点开链接
- **结果**：一句「找不到这个球局，可能已被撤销」，可退回，不白屏——链接失效的场景**不说「已结束」**（散场恰恰是翻得回战报的状态，那半句会把人教歪；现场页旧提示语是另一个语境的，不跟着搬）
- **禁止**：无

## 6. 边界与非目标（必填）

- ❌ 明确不做：
  - **战报摘要分享卡**——不做「先看一张摘要卡再转发」的专门页：链接打开本就是完整战报，一步到位（拷问已否）。
  - **微信小程序原生分享卡片样式**——先用手机系统分享面板与复制链接；小程序端的卡片样式以后随小程序端一起做。（修订 2026-10-17：微信网页一侧的定制分享卡已由 2.10 点亮——服务号资质到位，三处分享在微信内改走右上角转发＋登记卡；小程序端仍随小程序端做）
  - **发出去的链接收不回（作废手段）**——手抖发错群没有撤回键；战报是定格旧账、不含考勤敏感项，接受转发不可控（知情取舍）。
  - **「别晒我」通道**——战报的名单与积分涨跌随链接公开，掉分的、没到场的球友没有单项隐藏开关；熟人球局晒战绩是常态，分享处给一行小字「链接任何人可看」让分享者知情。
  - **已注销球友的战报脱敏**——战报是散场时定格的历史旧账，注销者的名字照定格显示；公开链接下的可见性留痕在此，脱敏做法以后跟账号注销的整体处理一起定（1.6 冻结册的事）。
  - **终止/取消局的战报入口**——没有散场定格，无从翻起。
  - **考勤分权扩口**——照 2.3 §4.10：组织者与本人，不多给一个人。
  - **多局并存的现场页改造**——「收摊后接上最近的在办局」只是显示上的选择，不做多局切换器。
- ✅ 做但降级（自用够用即可的部分）：
  - 系统不支持分享面板的设备，退「复制链接」——复制粘贴多发一步，但人人可用。
  - 上部提示行按「是不是这局的人」给两句文案——不做更多花样的千人千面。

## 7. 附录（前端必拼，后端/数据按需，同样人话）

### 附录 A：前端行为

**A1. 屏幕清单**
- 现场页·战报态（改）：加三件——上部去向提示行（这局的人见「可在打球记录翻看」、其他人及未登录见中性句）、右上角**完成**（收摊：只清本机画面、有别的在办局接上、否则空态）与**分享**（系统面板→复制链接兜底；分享处一行小字「链接任何人可看」）。
- 局详情页（改）：已散场的局亮「查看战报」，能打开详情的人都可见。
- 打球记录页（改）：名单规矩放宽（见附录 B）；头部文案写全单位「累计打了 N 场对局」；点局卡片仍先进局详情（沿既有习惯）。
- 战报子页（新门牌，内容与现场那份同一副长相）：从局详情「查看战报」进；返回即出；右上角完成（＝返回来路）与分享。

**A2. 每屏的状态**
- **空状态**：零战报局见「这场没落下战报」（名单照常）；链接指向不存在的局见「找不到这个球局，可能已被撤销」。
- **加载中**：战报页等待时灰色占位块，不白屏（沿现场页既有长相）。
- **出错**：断网提示可重试；重试不产生重复账（本页只读，无写动作）。

**A3. 操作与响应**
- 点完成（现场格子）→ 现场页收摊：本机画面清空 →（有则在办局接上 / 否则空态）。
- 点完成（战报子页）→ 返回局详情。
- 点分享 → 系统分享面板拉起 → 选目标发出；无面板 → 链接已复制 + 提示。
- 误操作可救：完成不删任何账——战报与记录原地都在，随时从打球记录翻回；分享无破坏性。两处完成都**不弹确认**（无损失动作不加门）。

**A4. 数据从哪来**
- 战报内容（每场名单/比分/胜方/积分涨跌、名单、考勤分权后的时刻）＝散场时定格的现场总账**原样翻出**，页面一个字不重算（沿 2.3）。
- 「我还有没有在办球局、最近的是哪个」＝局的信息里算好给死的，现场页收摊时只挑显示，不自判。
- 「我的记录里该有哪些局」＝系统按规矩（上过场 或 账单有份 或 组织者）算好给的，记录页不自判。
- 「上部提示行给谁看哪句」＝按「我是不是这局的人」这个给死的身份判定换文案，**判定的尺与 4.4 名单规矩同一把**。
- 分享出去的东西＝一条能打开这局战报页的链接。

### 附录 B：后端行为

**B1. 触发与响应**
- 打球记录名单：按「上过场 或 账单里有份 或 这局的组织者」算好给页面——**跟着账单走**：账单落定时就能列（已填总价的局散场那一刻即落定；散场后补填的，补填落定那一刻生效），秒回，不用现场再算。对全部已散场局生效（含存量老局）。
- 战报可读：持链接的任何人（含未登录）拉到定格战报——沿 2.3 §4.10「任何人扫码可看」的同一条读路，链接只是又一个入口；考勤时刻按观看者身份裁（组织者全见、本人见自己、其余拿不到）。
- 「查看战报」亮不亮、提示行哪句文案，所需的「我是否这局的人 / 这局是否已散场」随局信息给定值。

**B2. 失败时用户看到什么**
- 链接指向的局不存在：一句「找不到这个球局，可能已被撤销」，不白屏。
- 断网：提示重试；战报是定格旧账，重试多少次读到的都一样。

**B3. 量放大 100 倍时**
- 一条链接被整个群同时点开：战报是散场时就定格的旧账，读多少次、多少人同时读，内容不变、不互相拖慢——先扛不住的只是并发读本身，慢而不错。

### 实现偏差（2026-10-11 实现收口，全部实现期技术裁定，无范围/验收变更）

1. **三笔规矩现算不落库**：名单判定每次拉记录时现算（不建新表、不回填）——「跟着账单走」（补填落定即长）与「老局追溯」（存量局同一把尺）两条由现算天然成立；十人规模秒回。落库+两锚点写入的备选被否（成本高且要处理存量迁移）。
2. **「这局的人」定值随现场视图下发**：提示行文案的判定尺由后端给死（与名单规矩同一把尺、同一份代码），前端不自判；未散场的局恒按路人算（4.4 前提本就是已散场，前端只在回看态消费）。
3. **头部场数口径落定**：「累计打了 N 场对局」的 N＝上过场的对局数（与积分落账同拍）：缺席照摊进列表不加场数、访客不计（无账号）——比「报名局数」「积分场数」都准，两本账对得上。
4. **未开账局的战报直链给中性句**：战报子页对「局还在但从没开过账」的直链显示「球局还没散场 · 战报等打完才有」，不说「已被撤销」（走查发现死链句在该场景是说假话；已开账未散场同句）。已撤销/不存在的局才见死链句。终止局的同类缝隙经评估不可达（撤局局不进任何列表、详情钮只在已散场亮），留痕不改。
5. **收摊接局口径补一笔**：「有在办局接最近开打的」在办判定排除已散场的局——散场后「开过账」的标记永远在，不排除的话点完成会被原路接回刚收掉的局（收摊按钮失效）。验收官全量审抓出、修复批收口。
6. **死链句统一成一处**：「找不到这个球局，可能已被撤销」在战报子页、现场格死链态、局详情失效说明、现场进不去的提示四处共用同一句话——现场旧句「球局不存在或已结束」本就是链接死局场景的表述，随本册一并换成 §4.6 句，无残留。
7. **分享降级件共用**：系统面板→复制链接的降级链抽成一处共用，局详情页原有分享一并换用（行为不变）；分享出去的都是「打开这局战报页」的链接。
8. **收尾件长相**：提示行、完成/分享双钮、小字都住在回看页组件本体上——两个门牌（现场格、战报子页）天然同貌，「完成」在哪个门牌各表各义（现场格＝收摊、子页＝返回来路），组件只出信号不做主。

### 2026-10-12 分享统一修订（用户拍板，实现即日收口；改口 §4.3 落点）

> 起因：用户报两个观感——①战报门牌分享出去，收链接的人直落现场页回看态，门牌上「完成/分享」对局外人像「流程没走完」；②从打球记录 → 局详情分享出去的却是另一张脸（赛前口径详情），两种链接两个落点。评估三轮后用户拍板最小方案：**不动任何页面结构，三处分享统一发局详情链接**（收链接的人详情 + 「查看战报」一跳可达——「详情+战报」本来都在），现场签到二维码（拉人到场）不在统一之列仍落现场页。改口清单：
