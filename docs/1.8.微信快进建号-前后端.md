## 1. 这是要解决什么问题（必填，人话）

- 现在的毛病：新面孔在微信里点链接进来，人都授权完了（微信都说了「这是谁」），还得再填一张名片——名字、头像、手机号一样不能少；填了自己早已注册过的手机号，还会被回一句「这个手机号已经有人用了」，像是做错了事。微信授权这一步本来已经把人认清楚了，这步白做了。
- 一句话的成功画面：**微信里点一下「微信授权登录」，微信确认页点一下「允许」——名已经报完了，一张表都没填。** 名字系统顺手安好，手机号先欠着，想补的时候随时能补。

## 2. 给谁用（必填，按角色写）

- **新面孔**（主）：微信里两下进门开打，零输入；名字系统安好、随时可改，手机号想补再补。
- **没绑微信的老球友**（间接受影响）：从球局页的名片卡走微信授权会先开一个「微信号当家的临时账号」先用着；日后补手机号时若号码已有老账号，验证一次即回到老账号、微信绑定跟着回去。
- **组织者**：名册上可能出现没绑手机号的球友（尾号位置空着）；不加任何标注、不受任何提示打扰。
- 与本功能无关的角色不受影响：已绑微信的、已登录的、不用微信的（手填建号三把钥匙）一切照旧。

> 角色差异只用 §4 场景表达，不立权限表。

## 3. 用户故事（必填）

1. 作为微信里点链接进来的新面孔，我想点一下微信授权就把名报了，以便一张表都不用填。（→ §1 成功画面）
2. 作为懒得想名字的新面孔，我想让系统顺手把名字安好，以便零输入开打、以后随时能改。（→ §1）
3. 作为先玩起来的新面孔，我随时想补上手机号，以便球局有急事能被通知到。（→ §4.4）
4. 作为没绑微信的老球友，我从名片卡误走了微信快进，我想在补手机号时找回老账号，以便微信从此绑回我真正的账号、战绩不裂开两个我。（→ §4.5）
5. 作为不在微信里的访客，我想走原来的填卡建号路，以便用手机号拿到账号。（→ §4.6）

## 4. 输入 / 输出场景（必填，文档核心）

### 场景 4.1：微信里，新面孔两下快进建号 + 报名跟着办完
- **身份**：新面孔（从未注册过，微信号也没绑过任何账号）
- **前提**：微信内置浏览器里，从球局页/意向表/现场签到弹出名片卡（卡上主按钮是「微信授权登录」）；他可能顺手填了昵称，也可能什么都没填
- **操作**：点「微信授权登录」→ 微信确认页点「允许」
- **结果**：
  1. 系统直接开好账号：**不用填任何表**——昵称按「卡上亲手填的 → 微信昵称（过现有昵称的清洗规矩，不合格视同拿不到）→ 随机名（如 球友8421）」取第一个拿得到的；手机号空着；这个微信从此**正式绑**在账号上（授权那一刻就是本人）；
  2. 刚才点的报名/组局/留意向/签到自动接着办完，toast 就一句动作完成的原话（如「报名完成，已在名单中」）；**仅当名字落到随机名时**，toast 顺带报名字（「名单里你叫『球友8421』，随时可改」——主人得知道自己叫什么）；除此之外不说「绑上了」「记得补手机号」；
  3. 随机名和空手机号随时可在资料页/账号区改。
- **禁止**：弹出名片卡让他再填；补手机号的任何主动提示；为建号要他输手机号；用微信昵称覆盖他亲手填的名字。

### 场景 4.2：微信昵称拿不到时
- **身份**：同 4.1
- **前提**：授权成功，但微信昵称抓取失败或没给
- **操作**：（无——系统自己兜）
- **结果**：昵称取随机名（如 球友8421），建号照常完成；资料页随时可改。
- **禁止**：因昵称拿不到而打断建号或要求手填。

### 场景 4.3：卡上亲手填过昵称的
- **身份**：同 4.1
- **前提**：弹卡后他在「叫什么」里亲手打了字（哪怕手机号空着）
- **操作**：点「微信授权登录」→「允许」
- **结果**：账号昵称用他亲手填的那个，微信昵称让位；其余同 4.1。
- **禁止**：用微信昵称覆盖他亲手填的名字。

### 场景 4.4：先玩起来，随时补手机号
- **身份**：快进开号的球友（账号没有手机号）
- **前提**：他在「我的」页账号区，那里有一行「手机号未绑定」（样式与「密码未设置 · 设置密码」同类，安静常驻，不推送不标红）
- **操作**：点它 → 输 11 位手机号（号码旁带既有那张名片卡的用途说明原文——收集号码的告知义务跟着收集动作走）→ 收验证码 → 输码确认
- **结果**：
  1. 号码没人用时：验证过即绑上，账号从此能收紧急通知，绑定记录翻真；
  2. 号码已有账号（多半是他自己的老账号）：发码当场就拒——「这个手机号注册过。如果你就是号主，去登录页用短信验证进入那个账号，微信会自动绑回那个账号；你最近在临时号上的报名会留在那边，不会搬过来」（不透露那个账号是谁的）；点这句指路即退出当前账号、带到登录页；
  3. 验证这一刻微信绑定升为牢靠级（与短信验证过的同级）。
- **禁止**：不输验证码直接把号码挂到账号上；抢注别人的号码；话术里把号主当贼防（他多半就是号主本人）。

### 场景 4.5：快进号补手机号撞上老账号（老球友回家）
- **身份**：没绑微信的老球友，从名片卡误走了快进、现在补手机号
- **前提**：他快进开的账号还没绑手机号；他输的是自己老账号的手机号
- **操作**：同 4.4 输号收码
- **结果**：同 4.4 第 2 条——被指路去登录页（点指路即退登快进号、带到登录页）；走完短信验证后进入**老账号**，这个微信**自动搬回老账号**（系统在验证成功那一刻收编：发现这台设备登着的账号绑着这个微信，即迁绑到刚验证通过的账号，快进号就地解绑），下次微信一键进的就是老账号；快进号那段时间的报名战绩留在快进号里不搬家，指路话术里已说明（已知代价，一次说清不藏）。
- **禁止**：把两个账号悄悄合并或搬数据；让用户为迁绑再多点一次微信授权（收编是系统自己办的事）。

### 场景 4.6：不在微信里，走原来的填卡路
- **身份**：普通浏览器（或电脑）里的访客
- **前提**：从球局页弹出名片卡
- **操作**：（看卡）
- **结果**：主按钮仍是「确定报名/确定建局」手填路，手机号必填的规矩不破（没有微信身份的账号必须有手机号当根）；微信授权入口以说明行呈现（**本册新增的元素**——1.7 的填卡态本没有它），点了告知「在微信里打开才能用」。
- **禁止**：在微信外的环境里把「微信授权登录」摆在主按钮位（点了只会弹说明，添堵）。

### 场景 4.7：从登录页找回落下的名片卡，主钮不变
- **身份**：没绑微信的老球友（从登录页「微信一键登录」进来、被告知还没绑过的）
- **前提**：1.7 原路——登录页点微信 → 落到名片卡
- **操作**：（看卡）
- **结果**：这张卡的主按钮**保持手填「确定」**，微信行是次级——防止老球友在找回面被快进岔成临时账号；他的正路仍是右上角「登录 ▸」走短信/密码验证（验证完微信自动正式绑上，1.7 §4.3 原样）。
- **禁止**：把找回面的卡也换成微信主钮。

### 场景 4.8：占卡三出口的微信验证（沿旧）
- **身份**：手填名片时手机号被占的球友
- **前提**：名片卡显示三个证明出口（短信/密码/微信验证进入）
- **操作**：任选出口验证进入
- **结果**：照 1.7 §4.4/§4.5 原话原样——正式绑的微信直接接管进入；没绑/绑别处各得一句指路；验证进入后微信换绑到当前账号。本册一个字不改它。

### 场景 4.9：出错与自愈（沿旧 + 两条新的）
- **身份**：任何走微信键的球友
- **前提**：授权凭证过期、微信服务不通、快进建号在半路失败、或建号成了但挂起的动作办不成（局刚好满员/被撤/截止、回跳时动作丢失）
- **操作**：看提示、按提示再试
- **结果**：
  1. 过期→「微信授权已过期，请再点一次」可自愈（1.7 原样）；
  2. 服务不通→「微信登录暂时不可用，可先用短信或密码」；
  3. 快进建号半路失败→回话「没办成，请再点一次微信授权」，一切原样，重点一次即可，**不留半个账号**；
  4. 建号成功但动作没办成→**账号照留**（建号这件事成了就是成了），如实回话动作的结果（如「手慢了，这个局已满员」），人留在原页可另选动作；不假报「报名完成」。
  随机名撞名：允许重名，无处理。
- **禁止**：把可自愈的事当错误页吓人；建号成功假称动作也成功（反之亦然）。

### 场景 4.10：注销（如实版——快进号有一条前提）
- **身份**：想注销快进号的球友
- **前提**：注销历来要短信验证本人；快进号没绑手机号前，验证码无处可发
- **操作**：先按 §4.4 补绑手机号，再走 1.6 §4.6 注销
- **结果**：补绑后一切照旧（短信验证本人 → 注销 → 微信登记位随账号清除，1.7 §4.10 原样）；没补绑前快进号**没有注销路**（微信是他唯一的钥匙，不解绑）；被收编指路后的空壳快进号就地搁置——无钥匙可进、记录留档，不自动清理。
- **禁止**：为快进号单独发明免验证注销的捷径。

## 5. 验收标准（必填，可勾选）

- [x] **正常流程**：[新面孔] 微信内从球局页弹卡点「微信授权登录」→「允许」→ 报名自动完成、toast 一句动作原话、全程零输入；「我的」页能看到账号、名字有值、手机号显示未绑定（不显示假尾号）—— 故事 1

- [x] **安全**：补绑必须收码验证；输别人的号码发码当场拒 —— 场景 4.4
  → 验证：输未验证号码试两步（机器矩阵：未登录发码拒、有账号发码当场拒+落审计、验证码错拒；另加：已有手机号的账号借补绑换根号也被拒）

## 6. 边界与非目标（必填）

- ❌ 明确不做：
  - **任何补绑手机的主动提示**——报名后 toast、名册标注、红点、推送一律不做（用户原话「不要提示」）；安静入口只有「我的」页账号区一行；
  - 微信照片头像进名牌——头像体系自有（卡通小人），本轮只取昵称；
  - 快进号与老账号的数据合并/搬迁——撞占用只做指路，记录留守快进号；
  - 登录页找回面的引导优化（1.7 落卡指路文案等）——本册不动，另议；
  - 小程序手机号快捷填写——微信只对小程序开放手机号，留小程序二期；
  - H5 内拿微信手机号——微信不开放，不存在此路。
- ✅ 做但降级（自用够用）：
  - 微信昵称抓取失败/被拒：随机名兜底，不打断；
  - 补绑撞占用：指路登录页走既有找回 + 系统自动收编迁绑（不在账号区嵌接管界面）；
  - 快进号长期不补手机号：就一直欠着，不影响打球与战力；代价是**补绑前收不到短信类通知**，组织者只能靠名册空尾号自己心里有数；
  - 被收编后的空壳快进号：就地搁置留档，无入口清理（规模小、无实害；困扰案例多了再议清理）。

## 7. 附录（前端必拼，后端/数据按需）

### 附录 A：前端行为

**A1. 屏幕清单**
- 名片卡（动作弹出）：微信内主钮换「微信授权登录」，主钮下有一行小字「新朋友点这里两下进场 · 注册过的老朋友用下面手机号报名」（给误入的老球友留一条看得见的正路）；手填「确定」退次级（仍验手机号）；微信外主钮维持手填、微信授权入口以说明行呈现（本册新增元素，点了只说明）。
- 名片卡（登录页找回落下）：主钮保持手填，与 1.7 现状一致——不换。
- 「我的」页账号区：无手机号的账号，「手机号 XXX · 账号的根」一行换成「手机号未绑定 · 补上能收通知」的安静行，点开两步（输号收码 → 输码绑上，输号处带用途说明）；「换号先联系群主」提示行无号时不显示；顶部的尾号小牌无号时显「未绑手机」，**不得回落成演示尾号**（现状会顶着一个假尾号，此为顺带修正）；有手机号的账号一切照旧。

**A2. 每屏的状态**
- 空状态：快进号进「我的」页，手机号行显示未绑定；资料页名字是随机名时不特别提醒，改不改随他。
- 加载中：快进建号往返期间动作按钮呈忙碌态；回到页面即见结果。
- 出错：见 §4.9——可自愈的重点一次；建号失败回原样重点；服务不通指路短信/密码。

**A3. 操作与响应**
- 点「微信授权登录」→ 跳微信确认页 →「允许」→ 回来动作已完成，全程无需理解任何中间概念；
- 授权确认页点「取消」= 什么都不发生，回原画面重点即可。

**A4. 数据从哪来**
- 回来后「这个微信绑没绑、该快进还是该直进」由系统判定好给到，画面照结果走，不自己猜；
- 名字取用顺序（手填 → 微信昵称 → 随机名）由系统在建号那一刻定死，画面只显示结果。

### 附录 B：后台行为

**B1. 触发与响应**
- 授权问询在原有「这是哪个微信」之外多带一步「他微信名叫什么」（拿不到不拦路，回空）；
- 快进建号：凭绑定时凭条开新账号——无手机号、微信生而正式绑、发同级钥匙；随机名由系统生成（球友 + 四位数字）；建号与挂起动作两个成功各自如实回话，谁没成绝不说成；
- 补绑手机号：发码前先查占用，占用当场拒并给指路话术（撞占用的发生次数照日志既有计数落账，让「要不要立合并功能」有数可查）；验证过才落号并翻真绑定记录、升微信绑定牢靠级；
- **验证收编**（本册新增的后台行为）：登录页验明正身成功进入老账号的那一刻，若这台设备当前登着的账号绑着某个微信、且验证者刚用短信证明了自己是老账号的主人——这个微信自动迁绑到老账号，原（快进）账号就地解绑搁置；不需要用户再点一次微信授权；
- 换绑顶替规矩照 1.7 原样：一个微信永远只开一扇门。

**B2. 失败时用户看到什么**
- 微信服务不通：「微信登录暂时不可用，可先用短信或密码」；
- 快进建号中途失败：整个不生效（不留半个账号），回话「没办成，请再点一次微信授权」；
- 建号成功但挂起动作办不成：账号留下，动作如实回话（满员/截止/被撤各说各的）；
- 补绑发码被占用拒：指路话术见 §4.4，不透露对方账号。

**B3. 量放大 100 倍时**
- 快进建号一次多一次微信问询与一行账号记录，零边际成本；无手机号账号不收任何短信，不占短信预算。

### 附录 C：数据行为

**C1. 数据清单**
- 账号允许没有手机号（账本现成留了空位，注销功能当年就用它）；「绑定记录翻真」沿用现有的一格记号，不用新账本；
- 微信昵称不落库——只在开号那一刻写进名片名字，之后与微信无关。

**C2. 谁能看 / 改 / 删**
- 无手机号账号在名册上尾号位置空着（这是唯一可见的差别，让组织者知道谁通知不到），除此之外无任何标注徽记；客服也不看名单；
- 快进号的微信断开：补绑手机号前他解不开（微信是唯一钥匙，也没有短信接管可走——接管以手机号为目标）；补绑后照 1.7 C2 原样；被收编迁走后号壳就地搁置。

**C3. 留多久、删了会怎样**
- 快进号与普通账号同寿命：补绑后可按 1.6 §4.6 注销即清、微信登记位释放；
- 被收编后的空壳快进号：无钥匙可进、记录留档、不自动清理（可视为他用完即走的脚印；困扰案例多了再议清理工具）。

## 9. 实现偏差（2026-10-13 回写，此后本文冻结）

1. **手填昵称不合格如实报错**：卡上亲手填的名字超长/撞保留名时，按手填建号的既有规矩回错提示，不静默改随机名（§4.3 只禁「微信昵称覆盖手填」，手填不合格的处理规格没写——从严不吞）。
2. **补绑端点加一道「账号已有手机号则拒」的门**：§4.4 只写快进号补绑，没写有号账号借补绑换根号怎么办——验收时认定这是可被劫持会话利用的洞（换上攻击者的号就能后续短信重置密码），已加拒并回「手机号是账号的根，换号先联系平台客服」。验收标准「安全」条目已含此核实。
3. **占用拒落审计账**：补绑撞占用的发生次数照日志计数落账（附录 B1 说了「让要不要立合并功能有数可查」——实现明确为每次占用拒记一笔，含请求者与撞上的号）。
4. **收编挂点两路**：登录页短信找回与「忘记密码重置」都算「用短信证明自己是老账号主人」，验证成功那一刻都收编；密码登录不算（不是短信证明）。§4.5/B1 只写了找回路。
5. **指路不登出**：点「去登录页 ▸」只带人过去，不退当前快进号——收编要靠验证那一刻快进号还在这台设备上登着，真「退出」发生在进入老账号那一刻（§4.4-2 的「退出当前账号」以此实现；半途回退仍在快进号，非破坏）。
6. **随机名回执排在动作话后头**：名字提示和动作完成提示共用一个位置，后说的顶先说的——实测名字句会被动作句瞬间顶掉，改成动作话先展示、约两秒半后再报名字（主人一定看得到自己叫什么）；没有挂起动作时名字句即时说。
7. **「微信已绑定」状态行可持久看到**：绑定状态原本只在授权回话里带一次，翻页即丢——已在本人档案视图里补上这一格（走查发现的缺口，不然重启后已绑用户看不到绑定状态）。
8. **补绑面板跟着身份走**：面板开着时换账号/退登，面板和旧提示自动收起（走查发现残留，旧提示在新身份下会误导）。
9. **「换号先联系群主」对齐为「换号先联系平台客服」**：我的页该行现文与 1.6 冻结原文不一致（漂移），随本次触该行顺带对齐。
10. **被收编指路后的空壳号就地搁置**照案执行；「快进号没补绑前没有注销路」照案执行（注销历来要短信验证，空号无处发码）。

**三项 agent 建议裁决（§8 标「待用户过目追认」）已按案实现**：快进号微信生而正式绑、随机名时 toast 报名字、空壳号就地搁置。追认时同步：1.7 附录 B1 的「正式绑」定义补一句「或快进建号时的微信授权」。
