## 1. 这是要解决什么问题（人话）

- 现在，「谁该上场」这个问题的答案存在**三份实现**：前端发牌引擎（认歇认连战）、后端发牌闸（只认字面队头）、后端结算回流（只认字面队头）。三份分两种语言互相抄，一抄就漂：
  - **歇一轮白歇**：在打的人设了歇，打完结算补位照样把他从队头捞上场——「轮到你自动跳过」的承诺只在空片补人一条路上设计过，结算路压根不看。
  - **发牌被自己人打回**：前端引擎跳过歇着的人之后上报发牌，后端那道「必须正好是队头那拨」的把关闸对不上号，整个发牌 422「发牌的人不在候场队首」，空片卡住填不上（实测复现：跳过歇者 422 / 含歇者直发 200）。
  - **资历是假的**：结算的「待得最久的先下」从来没喂过资历数据，实际按名册顺序下人。
- 病根不是三处各自写错，是**同一个规矩有三份拷贝**。开发日志有学费在案：空降支线和带访客支线都漏调过发牌逻辑（「此前只有代办 setCheck 路会发」）——散在多处的规矩靠人记，这个代码库已经交过一次学费。
- 一句话的成功画面：**「谁上场」全站只剩一个定义点**（后端一个取队函数），歇、连战、考勤、资历四样状态在发牌和结算两条路上同一口径兑现；写动作落账时空片顺手补满；全权者多一颗「重排这片」按钮能立刻兑现刚设的歇/连战；手机轮询在没人动的时候不再白拉全量视图。

## 2. 给谁用（按角色写）

- **全场球友**：无感受益——歇一轮真的会跳过、连战真的会排最前、场子转得更快（结算回流凑齐另一片时顺手点亮）；「我到了」之后够人就上片不再依赖谁的手机来算牌。
- **全权者（组织者 ∨ 被封管理员）**：新增「重排这片」——刚排好的场想改阵容（比如有人刚设了歇），一颗键取消+立刻重发；「一键排阵」照旧但语义变为让后端补所有空片。
- **不变化的角色**：未到场者、访客（同规）、清扫态中的组织者（清扫红线不动）。

## 3. 用户故事

1. 作为**打累了的球友**，我在场上点「休息一轮」，这场打完结算补位时系统自动跳过我、坑由下一位顶、我保位留在队里——下一场第一个轮到我。（2.7 草稿幕五的教学承诺，首次真正成立。）
2. 作为**刚改主意的全权者**，我看到刚排好的场里有人设了歇/连战，点「重排这片」——场上的人原样回流队首、立刻按最新状态重发，一步到位。
3. 作为**组织者**，我点「一键排阵」，后端自己把所有空片补满——我不用管算法在哪算的。
4. 作为**普通球友**，我签到/空降/换人之后，只要人够了一片，空片自动开赛——不用等谁手动发牌。

## 4. 输入 / 输出场景（文档核心）

### 场景 4.1：取队规矩单一真值（自动；全路兑现 2.4 §4.8）

- **规矩**（全站唯一一份，住后端）：候场队按序取人——连战（fire）优先收、轮到歇轮者（skip>0）跳过这一轮并消耗一次、坑由下一位顶、跳过者保位回队；缺席/早退不可发但留队不动；取满即停，没被轮到的歇轮不消耗。
- **谁用它**：结算回流（打完一场谁下谁补）、空片补满（写动作收尾）、手动发牌（一键排阵/重排）——三条路同一个函数。
- **资历**：名册行带上场章（落位时刻的全局序号），「待得最久的先下」按章排——先上的先下；没章的存量行视为最新资历（并列按当前序）。
- **禁止**：任何一条路上再出现「只认字面队头」的旁路实现。

### 场景 4.2：写动作自动补片（自动；学结算补位已验证的模式）

- **规矩**：所有现场写动作落账成功时，顺手把空片补满（补不齐留空、不动队列）。新增写端点自动继承，不需要任何人记得挂。
- **豁免是声明式的**，四个端点各自声明不补片：改分重落（账面动作，物理面不动）、清扫态取消、一键清扫、散场。收口处不记名单——错忘的方向从「忘了补（静默坏）」翻转成「忘了豁免（显眼）」。
- **降级不连坐**：补片先算计划、算得出才落库；补片段出问题只回滚补片段（主动作照常提交），片留空态、记错误号，下一个写动作自然重试、组织者一键排阵兜底——不变量从「每次成立」降为「最终成立」。
- **审计**：自动开片落「自动排阵」审计行（动作名对照 6.1 §C1 清单登记；操作人记触发这次写动作的人）。
- **禁止**：补片的失败弄死签到/结算等主动作。

### 场景 4.3：歇一轮完整生命周期（兑现 2.7 草稿幕五）

- 场上设歇 → 这场照常打完 → 结算补位轮到他时自动跳过、消耗一次、保位回队 → 下一场第一个轮到。「歇不是马上消失」的口径从此两条路一致。
- 候场里设歇：挂在行上，排到取人窗口那一刻跳过。
- **禁止**：状态改动推翻在打的一场（自动轮转不掀桌，2.4 §4.9 哲学不变）。

### 场景 4.4：重排这片（全权，手动新增）

- **语义**：这片在打 → 场上的人**原样回流队首**（取消语义）→ 同一事务内立刻按当前规矩重发这片（吃最新的歇/连战/考勤）；这片空闲 → 等于补片。一次号跳。
- **责任模型**（2026-10-14 裁决）：全权按下 = 担保「我看过了，这场还没人开始记分」——比分活在各手机本地，服务器判定不了「有没有人开始记分」，用人眼担保。UI 二次确认一句（「重排会推翻当前这场」）。
- **与取消对局的关系**：取消保留原语义（只清不补，管清扫与纠纷）；重排是「想换阵容」的正路。清扫态里重排不可用。
- **禁止**：非全权重排；重排无声推翻（必须经确认）。

### 场景 4.5：手动一键排阵（全权，语义微调）

- 按下去 = 让后端补满所有空片（不再由前端算牌上报）；非全权拒绝。发牌算法从前端退役，后端「排阵上报」端点改为空载荷。

### 场景 4.6：轮询条件拉取（自动，用户无感）

- 手机每 3 秒问一次「现场变了吗」，带上自己手里的版本号（总账号+改价指纹）；没变回 204 空体，变了才回全量视图。稳态拍的服务器成本从「组一棵视图」降到「一次整数比对」。
- **不上推流通道**（WebSocket/SSE）：单局 ≤20 人、3 秒粒度够用，连接管理复杂度不值。
- **号跳纪律**：无变更不 bump；所有影响视图的写必须 bump 号（测试锁死，含改价路径——改价走指纹不走号，两把锁各管各的）。

### 场景 4.7：边缘态

- **打短**（在打片人数不足）：维持现有产品语义（继续打/换人/结算回流），本册不变更——补片只管空片。
- **换单双打过渡期**：在打片照旧打完；空片按当前规则开；结算后新场按新规则（2.4 §4.7-3 现行口径不变，只是执行者从前端引擎换成后端）。
- **多片同时要人**：候场队按片号先后供给（2.4 §4.9 现行口径）。
- **并发**：两台手机同时触发写动作，号锁裁决一台 409 带回最新视图（现行机制，不新增冲突面）。

4. [x] **资历**：N 人下模式按上场先后下人（先上先下），不再按名册序——「2人下」模式下先上场的人先下、后上的留下——不再按报名顺序下人（上场章落位即盖，结算按章排）
5. [x] **连战**：场上设连战 → 打完结算补位他排最前被取——场上的人设连战，打完这场结算补位时他被第一个取上场
6. [x] **自动补片**：报到/空降/换人/取消/改规则/tempo 成功后空片被顺手补满；改分重落、清扫取消、一键清扫、散场四处不补——签到/空降/换人/取消/改规则/取消歇，成功后空片凑够人就自动开赛；改分重落、清扫单取消、一键清、散场四处不补（各自声明的豁免，逐端点锁）
7. [x] **取消歇点亮空片**：唯一结构性时刻（取消歇恰好凑齐最后一人）空片开赛——唯一会因取消歇而凑齐最后一个人的时刻，空片当场开赛
8. [x] **降级不连坐**：补片段构造性失败时主动作照常提交、片留空、错误号落审计/错误日志——构造补片段出错（人为埋爆）：签到照常成功、片留空、错误记进日志，下一个写动作自然重试——主动作永不被连坐
9. [x] **审计标**：自动开片落「自动排阵」审计行——自动开片落「自动排阵」审计行，操作人记触发这次写动作的人
10. [x] **一键排阵**：全权按 → 后端补所有空片；非全权拒——组织者/管理员按「⚡ 自动排阵」后端把所有空片补满；普通球友按钮置灰、直调接口被拒（真局走查两视角）
11. [x] **重排**：全权重排在打片 → 原样回流队首 → 立刻按当前规矩重发；歇+重排 = 跳过这轮保位、下一场先上；非全权拒、清扫态拒——全权点「重排这片」→ 确认句「重排会推翻当前这场——确认还没人开始记分」→ 场上的人回队首立刻按最新状态重发；歇+重排=歇者这轮不上、保位、下一场第一个上（真局走查全链）；非全权不显示钮、清扫态不亮钮
12. [x] **轮询 204**：稳态拍（无写无改价）带 since 请求回 204 空体；有写回全量；改价回全量（指纹含改价）——没人动的时候手机每 3 秒问一次「变了吗」都得到空回应（后端日志连排 204）；有人写或改价（改价不走现场账的号，靠指纹把住）才回全量
13. [x] **号跳不变量**：无变更不 bump；影响视图的写全 bump（后端测试锁）——一个写动作恰好跳一个号；读不加号（连续稳态拍都空回应）
14. [x] **前端薄壳**：前端生产路径无本地算牌；现场页全量行为不回归——手机上不再有本地算牌——签到响应回来场就排好了；前端引擎取人四件退役，只剩展示换算；前端测试绿、类型净、真局走查不回归

## 6. 边界与非目标（必填）

- **记分本地化不动**（2026-10-09 裁决）：比分继续活在各手机本地；「没计分就能改」的安全模型维持「手动可改 + 责任人担保」，不做机器判定。
- **不引入「已发牌未开打」中间态**：落牌即开打模型不变（2026-10-14 裁决）。
- **LiveBook 不拆分不重排**：本册净减宽（闸删、样板收口）；拆服务是另一个话题不搭车。
- **打短语义、换人/取消/改分重落既有语义不变**：重排是新增不是改这些。
- **「暂停自动排阵」开关**（组织者先攒人再手动排）：真实需求可另立产品决定，不入本册。
- **示例局（2.7 草稿）实现另册**：其幕五依赖本册兑现；示例局本机引擎届时镜像本册后端规矩（镜像对象从三份变一份）。
- **推流通道不做**（见 4.6）。

## 7. 附录（前端必拼，后端/数据按需，同样人话）

### 附录 A：前端行为

- 现场 store 的本地算牌退役：签到/取消/改规则后的「够人自动发牌」不再前端算+上报，写动作响应视图即排好结果。
- 「一键排阵」按钮改调空载荷排阵请求（全权闸不变）；片卡全权菜单新增「重排这片」（带二次确认句）。
- 轮询请求带版本号参数；204 时空拍保持现状不重渲染。
- rotate.ts 的取人四件（取队/分边/补片/补所有片）退出生产路径；纯展示派生（每片人数/片数/可打人数/空片谓词）保留。
- 前端引擎的歇消耗本地预减逻辑删除（消耗真值归后端行上）。

### 附录 B：后端行为

- 取队纯函数住轮换模块（不碰数据库框架，纯 dict 进出可单测）；结算回流、自动补片、手动发牌三路共用。
- 名册行新增「上场章」列（落位时刻的全局序号），存量行无章按最新资历参与并列。
- 写路径公共出口统一接管「号跳、补片、提交」；豁免端点显式声明。
- 补片写回段包保存点（SAVEPOINT），失败只回滚补片段。
- 排阵上报端点改空载荷（全权）；新增重排端点（片号+两级号，全权）；读视图端点增版本号参数（没变 204）。
- 自动开片记「自动排阵」审计行。

## 8. 裁决记录（必填）

### 收编裁决（2026-10-14，用户拍板）

1. **取队算法全部收编后端单一真值**：用户以「每个人信息不一样」直觉发起，核实后确认病根为三份实现互相漂移（422 实测 + 开发日志漏调学费在案）；裁定「策略在纯函数层一份、机制在服务层一份、出口一个」，方案 A（两处补丁）被包含取代。
2. **「没计分就能改」安全模型**：机器判定不了「有没有人开始记分」（比分在手机上）——维持「结算前都可手动改（换人/取消/改分重落），但得有人按下按钮留名字」；不引入无计分窗口的机器判定。
3. **不引入「已发牌未开打」中间态**：落牌即开打；想立刻改阵容走全权重排。
4. **重排=取消+立刻重发二合一**，全权、责任担保、二次确认。
