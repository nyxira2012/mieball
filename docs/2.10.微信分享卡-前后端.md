## 1. 这是要解决什么问题（必填，人话）

- 现在球友把球局或战报发进微信群，群里只看到一行裸链接——从「分享」按钮经手机系统分享面板发出去的，还掺着标题字，连链接都不是纯的。就算老老实实只贴链接，微信自动拼的卡也只有写死的站名「夜球场 NIGHTCOURT」，看不出是哪局、几号打、报了几人——群友不点开就不知道这是什么，自然也不点。
- 一句话成功画面：在微信里打开局详情或战报，点右上角「···」转发给群，群里出现一张卡——标题是局名，下面一行这局的要点（「10月18日 19:30 · 某某球馆 · 已报 6 人」，或散场后的「6 场对局 · 看看谁赢了」），左边一张夜球场的方图；点卡片直接进这局的详情页。

## 2. 给谁用（必填，按角色写）

- **组织者**：发局进群收人——卡片就是招牌，局名、时间、场地、已报几人一眼可见。
- **球友**：赛后把战报转进群——群里一眼认出是哪局、打了几场，接着聊。
- **看客（未登录/访客）**：点卡片能看详情和战报（沿 2.6「链接任何人可看」，本册不扩不缩）。
- 不为任何角色服务的部分：无。
- 与本功能无关的角色：不受影响——不碰现场、报名、账单任何一页的功能。

## 3. 用户故事（必填）

- 作为组织者，我想把球局转发进群时群里看到一张像样的卡片，以便更多球友点进来报名。（问题：裸链接没人点）
- 作为球友，我想散场后把战报转进群，群里一眼看出是这局、几场对局，以便大家接着聊今晚的球。（问题：看不出是哪局）
- 作为在微信里点「分享」的球友，我想知道怎么把卡发出去，以便不被「复制链接」糊弄——复制出去的成不了卡片。（问题：按钮与卡片两条路不通）

## 4. 输入 / 输出场景（必填，文档核心）

### 场景 4.1：组织者在微信里转发还没散场的局
- **身份**：组织者
- **前提**：在微信里打开这局的详情页；局还没散场（报名中或进行中）；服务号那边的两项登记（附录 C）已办妥
- **操作**：点右上角「···」→「发送给朋友」→ 选一个群
- **结果**：群里出现一张卡——标题是局名；描述一行「10月18日 19:30 · 某某球馆 · 已报 6 人」；左边一张夜球场方图。群友点卡片进这局的详情页，没登录也能看
- **禁止**：卡片上不出现任何人的手机号、考勤记录；描述里不出现比分

### 场景 4.2：球友散场后转发战报
- **身份**：球友
- **前提**：在微信里打开战报页（散场当场那页，或日后从「我的 → 打球记录」翻回来的同一页）
- **操作**：点右上角「···」→「发送给朋友」
- **结果**：卡片标题是局名；描述「6 场对局 · 看看谁赢了」；点卡片进局详情，详情里「查看战报」一跳可达（沿 2.6 的落点规矩）

### 场景 4.3：发朋友圈
- **身份**：球友
- **前提**：微信内打开局详情或战报
- **操作**：点右上角「···」→「分享到朋友圈」
- **结果**：朋友圈那条显示局名和那张方图——朋友圈的卡片只显示标题、没有描述行，这是微信的规矩，不是漏做

### 场景 4.4：微信里点页面上的「分享」按钮
- **身份**：任意能看到分享按钮的人（三处：局详情、战报页、现场散场门牌）
- **前提**：在微信里
- **操作**：点「分享」
- **结果**：链接照旧复制进剪贴板，提示语换成「链接已复制 · 访客可看 · 发卡片点右上角 ···」——2.6 定下的「访客可看」知情句保住，后半句指路
- **禁止**：不再装作能打开手机自带的分享菜单——微信里本来就没有；也不再只说「链接已复制」不指路

### 场景 4.5：微信外一切照旧
- **身份**：用户
- **前提**：手机浏览器或电脑上打开页面
- **操作**：点「分享」
- **结果**：和现在一模一样——手机系统分享面板优先，设备不支持就复制链接并提示「链接已复制 · 访客可看」。本册不改微信外任何行为

### 场景 4.6：卡片登记没成（边缘）
- **身份**：任意在微信里的用户
- **前提**：服务号没配好、微信那头暂时没给出凭据、或网慢
- **操作**：照常右上角转发
- **结果**：转出去的是微信默认样子（标题是站名、没有描述行）——页面其它一切照常，不弹任何错误，不打扰
- **禁止**：不许因为登记失败弹错、卡页面、或让分享按钮失灵

### 场景 4.7：同一趟浏览里从详情点进战报
- **身份**：球友
- **前提**：微信内已打开局详情，点「查看战报」进了战报页
- **操作**：在战报页右上角转发
- **结果**：卡片说的是战报那句（场数句），不是详情那句——每一页各自登记自己的说法

### 场景 4.8：局撤销之后点旧卡片（边缘）
- **身份**：看客
- **前提**：球局被组织者撤销，旧卡片还留在群里（卡上仍是「已报 6 人」那句）
- **操作**：点卡片
- **结果**：进详情页，页面照常打开，看到的是这局已撤销的样子（撤销的局不会消失，只是状态变了）。卡片内容是转发那一刻定格的，不会跟着局的状态变——微信的规矩
- **禁止**：不许因为局已撤销就把人拦在门外或报错；只有局真的不存在（链接被改坏）才显示「找不到这个球局，可能已被撤销」

  → 验证：真机发一条朋友圈看样子 【浏览器实测：朋友圈登记只带标题＋方图（无描述行）；真机发圈留验】

  → 验证：微信外的浏览器里点分享，与 2.6 时代行为一致 【浏览器实测：页面零登记动作（无脚本注入、无签名请求），分享落复制兜底老句】
- [x] **出错降级**：把服务号那边弄成没配好的样子，再打开页面 → 页面一切照常、无任何报错，右上角转发出的是微信默认样子。 —— 对应场景 4.6
  → 验证：开发环境（假通道）下走一遍打开与转发，页面功能全部照常 【两层实测：假通道下接口答「未开通」；真钥匙未进白名单时接口答「暂不可用」——两种都页面零报错零打扰，登记静默不成】
- [x] **边界·局名和场地名超长**：起一个很长的局名 → 卡片标题、描述随微信自己截断，页面不另做处理。 —— 对应场景 4.1
  → 验证：真机转发一张长局名的卡，看群里显示 【留真机——页面不限长，照拼全量交微信】
- [x] **边界·散场但一场对局都没打**：散场后转战报 → 描述只说「已散场」，不出现「0 场对局」。 —— 对应场景 4.2
  → 验证：造一局开账后直接散场的局，看卡片描述 【字面量锁测：场数为 0 出「已散场」；场次取不到时出「已散场 · 看看谁赢了」（§8 偏差一）】
- [x] **边界·终止或撤销的局**：一局已终止（或被组织者撤销）后，在微信里打开它的页面再转发 → 描述说「这局已终止」（或「这局已撤销」），不再说日期场地。 —— 对应附录 A4
  → 验证：造一局终止的局和一局撤销的局，各在微信里打开后转发看描述 【字面量锁测两态各出各句】
- [x] **同一趟浏览不串台**：微信里打开已散场局的详情转发 → 看到场数句；接着点「查看战报」进战报页再转发 → 仍是场数句；换一局报名中的：详情转发看日期句，再从详情点进别处回来转发还是日期句——每一页各说各的话，不会把别页的话带过来。 —— 对应场景 4.7
  → 验证：真机同一趟浏览里连转两次，比对两张卡的描述行 【浏览器实测同一趟：详情（报名中）日期句 → 战报页场数句 → 散场局详情场数句 → 现场门牌场数句，四页各说各话】
- [x] **页面长开跨了阶段再转发**：微信里打开报名中的详情页放着不关；等这局开打并散场后，切回这个还开着的页面刷新一下再转发 → 卡面说的是场数句，不是过期的「已报 N 人」。 —— 对应附录 A2
  → 验证：真机挂着页面跨过散场，刷新后转发看描述行 【机制实测：页面数据一变即按新数据重登记（同内容不重复登记）；真机跨阶段留验】

## 6. 边界与非目标（必填）

- ❌ 明确不做：以下六件
  - **每局一张专属图 / 战绩合成图**——一张全站共用的品牌方图；想要「带比分的战绩图」是另一个功能，不夹带。
  - **发出去的卡片内容跟着局更新**——微信规矩：转发那一刻定格，无法追改（知情取舍，与 2.6「链接转发不可控」同一条根）。
  - **小程序端的分享卡**——沿 2.6 §6 原话：随小程序端一起做。
  - **微信内点「分享」直接替用户发出卡片**——微信不给网页这个口子，只能引导右上角；不做蒙层大指引图，一句提示够用。
  - **示例局（2.7 教学态）配卡**——零真人数据，没有分享价值。
  - **描述里露比分、积分涨跌、考勤**——卡片是给群外人看的门面，门面不晒账。
- ✅ 做但降级（自用够用即可的部分）：
  - 登记失败静默退微信默认样（不弹错、不重试轰炸）。
  - 标题/描述超长随微信截断，不自己限长。
  - 卡片登记要等页面数据到齐才做——用户若手快在登记完成前就转发，出的是微信默认样，接受。
  - 满员或已开打的局照发「已报 N 人」的日期句——卡片是定格的门面，点进详情才见真相（满员/进行中状态详情页自会显示），不另造「已满」「进行中」两句。

## 7. 附录（前端必拼，后端/数据按需，同样人话）

## 附录 A：前端行为

### A1. 屏幕清单
- **局详情页 / 战报页 / 现场页（散场门牌）**：三页各自在打开后向微信登记「这一页分出去的卡片长什么样」；登记用的局名、日期、场地、人数、场数都是页面现成拿得到的信息（详情页都显示在画面上；战报页画面上只显示人数和场数，局名与日期在它手里但不上画面），卡片一个字不自己编。三页的「分享」按钮照旧存在，微信内改提示语（场景 4.4）。

### A2. 每屏的状态（逐屏过）
- **空状态**：局信息还没到 → 先不登记，等到了再登记（用户通常点不到那么快）。
- **信息更新了**：页面上的局信息刷新了（自己下拉刷新、从后台切回来重新拿了一份、局的阶段变了）→ 用最新信息重新登记一次；重新登记没成，维持上一份。
- **加载中**：登记本身无可见等待，不转圈不打扰。
- **出错**：登记没成 → 静默，页面功能一切照常（场景 4.6）。

### A3. 操作与响应
- 用户点「分享」（微信内）→ 提示「链接已复制 · 访客可看 · 发卡片点右上角 ···」，链接进剪贴板。
- 用户点「分享」（微信外）→ 与 2.6 时代一致：系统分享面板优先，复制兜底。
- 用户右上角「···」转发/发朋友圈 → 走微信自己的流程，出现登记好的卡片。

### A4. 数据从哪来
- 卡片标题：局名，照页面上显示的。
- 卡片描述：报名中、已成局（名单锁定还没开打）、进行中 →「日期 时间 · 场地名 · 已报 N 人」（场地名没有就省掉那一段；N 把组织者本人算在内，万一是 0 也照说「已报 0 人」，不另造句）；散场 →「N 场对局 · 看看谁赢了」（一场没打 →「已散场」）；已终止 →「这局已终止」（组织者眼里的「待处置」也按这句，别人眼里它本来就是已终止）；已撤销 →「这局已撤销」（与 6.2 的叫法一致：人数不够自动死的叫终止，组织者主动撤的叫撤销）。全部取自页面现成拿得到的信息，只负责拼成一句话。
- 卡片落点：局详情页的网址（沿 2.6 三处统一）。
- 卡片方图：一张放在咱们网站上的固定图片，全站共用。

## 附录 B：后端行为

### B1. 触发与响应
- 页面打开 → 系统拿微信给的凭据、替这一页办好登记手续，一两秒内完成，用户无感。
- 微信给的凭据两小时内有效、且每天要的次数有限——系统拿到一份后两小时内反复用，不每人每次现要。

### B2. 失败时用户看到什么
- 凭据拿不到（服务号没配好/微信那头超时）→ 卡片退微信默认样，页面照常；不连环重试，下一次打开页面再试。
- 数据不会丢：登记只关乎卡片长相，不碰任何业务数据。

### B3. 量放大 100 倍时
- 登记手续跟着页面打开次数走，100 倍人也只是 100 倍次打开；凭据全站共用一份，不随人数涨——微信那头的次数账单不炸。

## 附录 C：动工前提（项目主人要在公众号后台办的两件事）

## 附录 D：卡片方图的要求（给设计/换图用）

- 正方形，边长至少 300 像素（建议 500×500）；微信群里实际显示成左下角一枚小方图。
- PNG 或 JPG，文件小于 100KB——几 KB 到几十 KB 最好，小图加载快。
- 主体居中、四周留至少 10% 的边；深底高对比（与全站深色底一致）。
- 图上不写局名、日期、比分——那些是卡片文字行的事；图只放品牌印记（夜球场图形或「夜球场」三个大字），要放字就只放这三个字，别放长句。
- 全站共用一张，图的地址固定不改名、换图只换内容——这样旧卡片上的图不会突然变空白；换了图重新发版，之后转出去的新卡片即刻换新（已经发出去的旧卡不变，微信规矩）。
