## 1. 这是要解决什么问题（必填，人话）

- 现在产品只有网页版一扇门：球友在微信里搜不到我们；从群里点链接进来是网页版，网页版的登录状态带不到小程序里；现场扫码也只能跳去网页版。现在小程序资质已经全部办妥，代码底子本来就支持一套代码出网页版和小程序两端，就差把小程序这扇门正式打通。
- 一句话成功画面：球友在微信里搜到小程序，打开就是熟悉的界面和全套功能；网页版用微信登过的老球友点一下「微信一键登录」就能进自己原来的号；现场亮出的码用微信一扫直接进小程序现场页；发到群里的是小程序卡片，点开直达球局页面。

## 2. 给谁用（必填，按角色写）

- **组织者**：多一扇更顺手的门——微信里直接搜出来就能发局、现场亮小程序码收人，球友扫码直接进小程序现场页。
- **球友**：小程序里功能一样不少——报名、签到、记分、账单、战力、装扮照常使用；网页版和小程序共用同一个账号，战力和打球记录跟着人走。
- **看客（未登录/访客）**：点开群里的小程序卡片能看球局详情和战报（延续「链接任何人可看」的老规矩，范围不扩不缩）。
- 不为任何角色服务的部分：无——本册不加新功能，只是把网页版已有的功能完整搬进小程序。
- 与本功能无关的角色：习惯用网页版的球友不受影响——网页版除顺手去掉名片卡底部那行无意义的「使用手机浏览器打开本程序」小字外，其余功能与操作一概不动。

## 3. 用户故事（必填）

1. 作为球友，我想在微信里直接搜到小程序打开就用，不用每次去群里翻网页链接。（问题：小程序这扇门还没开）
2. 作为在网页版用微信登过的老球友，我想在小程序里点一下微信登录就进原来的号，让战力和打球记录都跟着我。（问题：网页版和小程序发的是两把不同的微信钥匙，不打通就会变成两个号）
3. 作为新球友，我想在小程序填名片时点一下就能填入自己的微信昵称，不用从头手打名字。（问题：小程序静默登录不会自动带回微信昵称）
4. 作为组织者，我想现场亮出的二维码让球友扫了直接进小程序现场页，空降签到一步到位。（问题：扫网页链接码会跳去网页版，小程序用户还得重登）
5. 作为球友，我想把球局或战报用小程序卡片转到群里，让大家一眼看到「局名 · 时间」、点开直达。（问题：小程序还没有转发卡片）
6. 作为用手机号注册的老球友，我想在小程序里用短信验证码或密码登进原来的号，换哪边都能进。（问题：网页版的本机登录记忆带不到小程序里）

## 4. 输入 / 输出场景（必填，文档核心）

### 场景 4.1：新人第一次打开小程序
- **身份**：访客（未登录）
- **前提**：在微信里搜到并第一次打开小程序
- **操作**：浏览各个页面
- **结果**：长相和网页版完全一样——底部同样是「现场、约球、战力、我的」四个栏；当前没有进行中的球局时，现场页照常摆着两张新手教学示例局卡片；随便翻看页面不拦人，直到点报名、建局、留意向或现场签到时，才弹出名片卡建号。
- **禁止**：不因为换成了小程序就改动任何页面的排版或业务规矩。

### 场景 4.2：老球友微信一键登录——两端自动打通（主场景）
- **身份**：在网页版用微信登录过的老球友
- **前提**：公众号与小程序已绑定在同一个微信开放平台账号下（附录 D 第 1 项）；这位球友在绑定生效后用微信登过网页版（账号里已记下微信的统一编号），且这是第一次在小程序点微信登录
- **操作**：在小程序登录页点「微信一键登录」
- **结果**：不跳授权确认页、也不弹多余的确认框，一两秒内直接进入**他原来的账号**——昵称、战力、打球记录全在；如果登录前正准备报名或建局，登录后自动接着办完。反过来也一样：先在小程序用微信建的号，日后去网页版点微信登录，同样凭统一编号直进同一个号。
- **禁止**：已经认出是老号还当新人另开空号；多弹一次确认框；已经绑过小程序钥匙的账号，不再因为统一编号自动换到别的号上（先认小程序自己的钥匙，见附录 B1；两边对不上号时记一笔交人工，见场景 4.13）。

### 场景 4.3：新球友在小程序里快速建号
- **身份**：还没注册过的新球友
- **前提**：点报名、建局、留意向或现场签到时，弹出名片卡
- **操作**：填名片——点一下昵称输入框，键盘上方会冒出自己的微信昵称，点一下即可填入（不点也可以自己打字，或干脆留空）；头像从卡片列出的公共头像里挑（小程序不提供「使用微信头像」，见 §6）；手机号想填就填、不填也行；最后点「微信授权登录」（原卡片底部那行「使用手机浏览器打开本程序」的小字，网页版和小程序两边一并去掉）
- **结果**：一两秒建好账号，刚才点的报名等动作自动接着办完。按手机号填没填分三种结果：
  1. **没填手机号**：直接建好账号先玩起来（昵称也没填就自动起个「球友XXXX」的随机名并轻提示告知），以后随时可在「我的」页补绑手机号；
  2. **填了手机号、且没人用过**：直接建好带手机号的账号，小程序微信钥匙同时绑牢；
  3. **填的手机号已被注册过**：卡片切到「这个手机号已经有人用了」，给出短信验证、密码、微信验证三种方式证明是本人，验过直接进入那个账号。
- **禁止**：因为没填昵称或没填手机号就拦着不让建号。

### 场景 4.4：没能自动认出来的老球友（手机号找回 + 人工兜底）
- **身份**：已有老账号，但这次微信登录没能靠统一编号自动对上的球友（例如以前只用手机号注册没绑过微信，或是本功能上线前注册的老号还没记下统一编号）
- **前提**：第一次在小程序里登录
- **操作**：从登录页点「微信一键登录」；没被认出来后，点名片卡右上角「登录 ▸」（或关掉卡片）回登录页，用短信验证码或密码登录原账号
- **结果**：
  1. **点「微信一键登录」那一下**：系统发现这个微信还没对应上任何账号，不会悄悄新建空号，而是弹出名片卡（此时按钮是「确定」，要求填手机号，避免老球友误点一键开出新号）。
  2. **回登录页用短信验证码或密码登进原账号**——进号的同时，小程序微信钥匙自动绑到老账号上，以后再点就是一步直进。
  3. **如果不小心开重了号，或老号当年没留手机号**：比如在报名弹卡时没填手机号直接点了「微信授权登录」开出了新号，或者老号当初就是网页版免手机号建的、没法收短信——遇到这类绑不上或开出两个号的情况，直接联系群主（平台客服）在后台人工调整绑定即可，不在产品里做复杂的自助并号。系统若自己先察觉到两端对不上号，会主动记一笔「跨端绑定不一致」记号，群主不必等球友来报（场景 4.13）。
- **禁止**：在登录页没认出人时悄悄新建空号；未经本人验证自动把两个账号的数据合并。

### 场景 4.5：现场亮码收人（两端各亮各的码）
- **身份**：已在现场签到的球友或组织者（现场页顶部的二维码按钮，到场的人都能点）
- **前提**：在小程序现场页，球局已开场（已开账）
- **操作**：点顶部的二维码按钮
- **结果**：弹出二维码浮层，中间显示这局的**小程序码**（因为要向后台现取，比网页版多等一眨眼），外圈的局名、场馆、已到场人数、空降签到提示与网页版完全一致。球友用微信扫一扫，直接打开小程序进入这局现场页：之前登过的还是登录状态，没来过的是访客，可先看也可当场签到。网页版那边点二维码按钮**照旧显示原来的网页链接码**，两边各亮各的码。
- **禁止**：取码等待的那一瞬间让浮层一片空白没有加载提示。

### 场景 4.6：小程序码没取出来时的兜底
- **身份**：已在现场签到的球友或组织者
- **前提**：后台还没填小程序配置，或者向微信申请小程序码时网络超时
- **操作**：点顶部二维码按钮
- **结果**：浮层自动退回显示**网页版的链接二维码**（带完整线上网址），保证现场永远有码可扫；别人扫了会打开网页版进入这局现场页，照样能签到上场。全程不弹错误提示。
- **禁止**：因为小程序码没取到就弹报错、卡住浮层，或让二维码按钮失灵。

### 场景 4.7：把球局转发到微信群
- **身份**：组织者或球友
- **前提**：在小程序里打开一局球局详情页
- **操作**：点页面上的「分享」按钮（或点小程序右上角「···」选转发）
- **结果**：直接拉起微信的转发选人面板（不用像网页版那样先复制链接再去点右上角）。发到群里是一张小程序卡片：标题为「局名 · 10.26 周日 19:00」（日期与时间写法跟网页版分享卡一致），配图为全站统一的夜球场品牌方图。群友点开卡片直接进小程序的这局详情页，没登录也能看。
- **禁止**：卡片上不出现手机号、考勤记录和具体比分；标题超长交给微信自己省略，咱们不截断。

### 场景 4.8：转发战报与分享到朋友圈
- **身份**：球友
- **前提**：在小程序里打开已散场球局的战报页（或刚散场时的现场战报门牌）
- **操作**：点页面上的「分享」按钮转发给朋友/群；或点右上角「···」分享到朋友圈
- **结果**：转发逻辑与网页版保持一致——发到群里的卡片同样是「局名 · 时间」配品牌方图，群友点开卡片**统一进入小程序的这局详情页**（详情页上点「查看战报」一跳即看，未登录也能看）。发到朋友圈时只显示标题和配图（微信朋友圈本身没有描述行）；别人从朋友圈点开时，按微信规矩会打开分享时的当前页（单页只读预览：内容能正常翻看，按钮暂时点不动，想接着操作点顶部微信自带的「前往小程序」即可）。
- **禁止**：卡片上露出任何人的手机号或考勤明细。

### 场景 4.9：短信、密码等原有账号操作照常
- **身份**：任意球友
- **前提**：在小程序的登录页或「我的」页
- **操作**：收短信验证码登录、密码登录、设置或修改密码、补绑手机号、退出登录、注销账号
- **结果**：界面和规则与网页版完全一样。网页版和小程序各自记住各自的本机登录状态——换到小程序第一次需要掏钥匙登录一次，之后小程序自己一直记住。注销账号时，绑在号上的微信钥匙（公众号钥匙、小程序钥匙及统一编号）一并清空释放，日后可重新绑新号。
- **禁止**：因为换到小程序就改动短信冷却时间、密码连错锁定等任何原有规则。

### 场景 4.10：第一次用到隐私能力时的微信官方弹窗
- **身份**：任意球友
- **前提**：小程序后台已填妥《用户隐私保护指引》（附录 D 第 4 项）；球友第一次触发需要调用微信隐私能力的动作（例如点昵称框一键填入微信昵称、复制内容到剪贴板）
- **操作**：照常点对应的输入框或按钮
- **结果**：微信会自动弹出官方默认的隐私同意弹窗（只弹一次，不自己画弹窗）——点同意后正常使用，以后不再打扰；点拒绝则那一项快捷能力不用，照样可以自己打字手填，不影响其他操作。点「微信一键登录」本身只是静默识别身份，不会触发这个弹窗。
- **禁止**：绕过或伪造微信官方的隐私同意弹窗（微信提审必查项）。

### 场景 4.11：后台还没填小程序配置时
- **身份**：任意球友
- **前提**：后台还没填小程序的 AppID 和密钥（附录 D 第 2 项未办）
- **操作**：在登录页点「微信一键登录」、弹出名片卡建号、或在现场点二维码按钮
- **结果**：登录页点微信按钮提示「微信登录即将开通 · 资质到位后点亮」；名片卡退回「确定」按钮走填手机号建号的老路，新球友照常能注册不卡壳；现场亮码自动退回显示网页链接码（场景 4.6）。其余功能全部照常；等后台把配置填上，按钮和小程序码自动生效，不用重发小程序版本。
- **禁止**：因为微信配置没填就报错或影响别的功能。

### 场景 4.12：装扮与新手教学照常使用
- **身份**：球友
- **前提**：打开装扮页，或浏览名片、战力榜、现场名单等任何带头像和卡背的位置
- **操作**：查看页面、试穿或更换装扮
- **结果**：长相与网页版完全一致；头像和卡背图片统一从线上服务器拉取（第一次加载某张图可能多等一眨眼）。装扮页里的「微信头像」选项保持原规矩：以前在网页版授权过、账号里存有微信头像的老球友能看到并穿戴；纯小程序注册的新球友账号里没存过微信头像，就不显示这一项。现场页的新手教学示例局也原样可用。
- **禁止**：图片万一没加载出来时露出裂开的破图图标（取不到图自动显示默认头像或素色卡底）。

### 场景 4.13：两端绑定对不上号——记一笔交人工（边缘）
- **身份**：任意球友（典型：先在小程序快速建了号，网页版另有一个用微信登过的老号）
- **前提**：他这一端的微信钥匙已经绑在甲号上；这次登录时微信给出的统一编号却指向乙号（另一端用微信登过的那个号）
- **操作**：点「微信一键登录」（网页版或小程序任一端）
- **结果**：进**甲号**——先认本端钥匙，不换号、不并号；系统在甲、乙两个号上各记一笔「**跨端绑定不一致**」记号（记下对方是哪个号、什么时候发现的）。球友画面上不多出任何提示、不弹窗让他当场选号，照常使用；群主（平台客服）在后台运维工具里能翻到带记号的账号清单，联系本人确认后手工处理（把钥匙搬到该去的号，或按本人意思并账），处理完清掉记号。
- **禁止**：自动合并两个号；自动换号；弹窗逼球友当场选；记号对球友本人或其他人显示。

## 6. 边界与非目标（必填）

- ❌ 明确不做：以下七件
  - **小程序里上传微信头像**——不做「从微信选头像再上传到咱们服务器保存」的功能（既要自建图片存储清理，又要过用户上传图片的内容安全审核）。想用微信头像的老球友在网页版微信登录一次就会自动记下，小程序里照样能显示和选用；纯小程序新球友只选装扮头像
  - **跨端异常账号的自助合并工具**——上线前没记下统一编号又没留手机号的老号，或球友误操作开出了两个号，这类情况极少，统一联系群主在后台人工处理，不做自助并号界面、也不搬迁历史数据
  - **微信支付**——本产品账单只管记账算分摊、不经手钱款，全站不接支付
  - **其他平台客户端**（手机 App、其他家小程序）——虽然代码底子预留了跨端能力，本轮只开微信小程序一扇门
  - **网页版强推去小程序**——不在网页版任何地方弹提示赶人去小程序；两边并存，球友爱用哪边用哪边
  - **小程序阉割版先行**——不砍功能，一开门就是完整功能
  - **教学示例局配转发卡**——示例局全是假数据，没有转发意义
- ✅ 做但从简（够用即可）：
  - 统一编号没对上时，有手机号的老球友用短信或密码登一次就自动绑好，特殊遗留情况人工后台兜底，不卡上线
  - 小程序码万一没取出来，自动退回显示网页链接码（场景 4.6）
  - 转发卡标题太长时交给微信自动省略，不自己算字数截断
  - 四个底栏主页之外的七个次要页面做成按需加载（分包），第一次点开多等一眨眼，不做后台预取
  - 线上装扮图片加载失败时自动回落默认头像或素色底，不报错拦人

## 7. 附录（前端必拼，后端/数据按需，同样人话）

## 附录 A：前端行为

### A1. 页面清单
- **四个底栏主页（现场 / 约球 / 战力 / 我的）与七个次要页（球局详情 / 战报 / 登录 / 参加登记 / 装扮 / 打球记录 / 账单）**：全部按网页版原样搬进小程序，一页不增、一页不减。界面可见的调整只有几处：底部导航图标、现场球拍图案、签到二维码三处图形换成小程序支持的画法；点「分享」改成直接拉起微信转发面板；名片卡昵称输入框支持点一下带入微信昵称，且名片卡底部那行「使用手机浏览器打开本程序」小字网页版与小程序两边一并去掉；装扮图片统一从线上服务器拉取（A5）。

### A2. 每屏的状态
- **空状态 / 加载中 / 出错**：各页面保持与网页版一致；小程序新增的三处短暂等待都给明确状态、绝不干晾着——点「微信一键登录」识别身份的一两秒（按钮转圈并防重复连点）、点二维码按钮向后台取小程序码的一瞬间、第一次点开分包次要页的一瞬间。
- **未填微信配置时**：登录按钮弹「即将开通」提示、亮码退回网页链接码（场景 4.11），其余页面一切如常。

### A3. 操作与响应
- 点「分享」→ 直接弹出微信转发选人面板（卡片内容见 A4）。
- 点顶部二维码按钮 → 显示小程序码；点「微信一键登录」→ 静默识别身份直进账号。
- 点名片卡昵称输入框 → 键盘上方浮出微信昵称供一键填入，不点就自己打字。
- 在群里点小程序转发卡 → 与网页版一致，统一打开小程序进入这局的球局详情页；用微信扫现场小程序码 → 直接打开小程序进入这局的现场页。

### A4. 数据从哪来
- 页面上所有的业务数字和状态判定（球局状态、分摊金额、战力积分、候场排位）全由后台算好下发，小程序只管展示，不另起炉灶重算。
- 本册新增由后台提供的两样东西：**这局的小程序码图片**（后台向微信生成后发给前端展示）；**微信跨端识别结果**（后台核对小程序钥匙与统一编号后直接返回是哪个账号，前端不自己猜）。
- 转发卡标题「局名 · 时间」：取自该局详情信息（战报页与散场门牌手里没有时顺手从详情补取，与网页版一致），时间格式与网页版分享卡一致（如「10.26 周日 19:00」）；卡片落点与网页版一致，三处转发进群统一落小程序球局详情页。

### A5. 包体瘦身两刀（硬要求）
- 微信平台硬规矩：打开小程序最先下载的「主包」不能超过 2MB。目前小程序编译产物按实际内容算约 1.14MB（早先看到的 2.3MB 是几百个小文件按硬盘分块算出的虚高占用），虽然眼下没超 2MB，但装扮图片以后会一直增加，趁早把包体结构理顺。
- **第一刀：装扮图片不打进包里，统一走线上加载**——装扮素材目录已从前端打包目录独立出去（与网页版共用线上服务器同一套图片地址），小程序包里一张装扮图都不塞，直接省下约 500KB；更重要的是，**以后上新头像和卡背不用重新提交微信审核**。
- **第二刀：七个次要页面拆成按需加载（分包）**——主包只留四个底栏主页和共用组件，其余七页第一次点到时再临时下载。
- 两刀做完后主包内容约 0.7MB，离 2MB 红线余量充足。球友能感受到的变化只有两处：装扮图第一次看多加载一眨眼、七个次要页第一次打开多等一眨眼。

## 附录 B：后端行为

### B1. 触发与响应
- 点「微信一键登录」→ 后台拿小程序发来的登录凭证向微信换回「小程序钥匙」和「统一编号」，一两秒内按固定先后顺序找人：
  1. **先查小程序钥匙**：已经绑在哪个账号上，就直接进哪个账号（顺带核对统一编号：若它指向的是另一个账号，仍进钥匙绑的这个号，不换不并，只在两个账号上各记一笔「跨端绑定不一致」记号交人工——场景 4.13；网页版微信登录遇到同样情况照此办理）；
  2. **再查统一编号**：小程序钥匙没绑过号，但统一编号对上了某个老账号，就直接进那个老账号，并顺手把小程序钥匙也绑上去（验证等级沿用原账号已有的状态，不凭空升级）；
  3. **两样都没查到**：返回「未绑定」并附带一张 10 分钟有效的绑定凭条，前端弹出名片卡（场景 4.4）；若球友在报名等名片卡上直接点「微信授权登录」，则按快速建号规矩当场建新号并绑牢（场景 4.3）。
- 点现场二维码按钮 → 后台向微信生成带这局编号的小程序码图片返回给前端，扫码后直达这局现场页（正式发布上线前可配置为生成体验版码供测试对演，发布上线时切回正式版码——微信规定线上尚无正式版时不生成正式版小程序码）。
- 后台调用微信小程序接口所需的调用凭据（有效期两小时）在服务器内存里缓存复用，不用每次请求都现向微信申请；同一局的小程序码也可短时复用，减少重复请求。

### B2. 失败时用户看到什么
- 后台没配小程序密钥，或微信那边接口超时 → 登录提示「即将开通」或「暂时不可用，可先用短信或密码」，现场亮码自动退回网页链接码；后台不连环重试，等用户下次点击再试，页面不报错不崩溃。
- 识别身份和生成小程序码都不改动任何球局、账单和战力数据，失败了也不会弄脏账目。

### B3. 量放大 100 倍时
- 登录换号和生成小程序码都是轻量请求；微信接口调用凭据全站共用一份、两小时才换一次（一天也就十几次），就算人数翻 100 倍也远在微信每日免费额度之内。

## 附录 C：数据行为

### C1. 数据清单
- **小程序钥匙登记位**：记录哪个账号绑了哪把小程序钥匙（与网页版的公众号钥匙并排存放，各记各的）。
- **统一编号**：微信开放平台给同一主体下各应用共用的跨应用身份号，只用来在后台把同一个人的网页版和小程序认到同一个账号上（网页版微信授权时也同步记下它）。
- **「跨端绑定不一致」记号（本册新增）**：任一端认人时发现本端微信钥匙与统一编号指向两个不同账号，就在两个账号上各写一笔——记对方是哪个号、什么时候发现的；只供群主在后台运维工具里翻查。
- **小程序码**：随用随取，数据库里不存图片文件。
- 全站所有业务数据（球局、账单、战力、装扮）网页版和小程序读写的都是同一套库，不复制、不分家。

### C2. 谁能看 / 改 / 删
- 小程序钥匙与公众号钥匙同规同权：「我的」页账号区只给本人显示一行「微信已绑定」（没绑不显示），任何人都看不到别人的微信编号；统一编号纯粹后台内部认人用，对所有人不可见、不出现在任何分享内容里。
- 遇到老球友跨端开重号或遗留老号绑不上等个别情况，由群主通过后台运维工具人工调整绑定归属；「跨端绑定不一致」记号只有群主在运维工具里看得到、处理完手工清掉，对球友本人和其他人一律不显示。

### C3. 留多久、删了会怎样
- 绑定记录跟着账号走；当账号注销、被新微信号换绑顶替、或通过短信接管清场时，账号名下的公众号钥匙、小程序钥匙与统一编号一并清理释放，释放后该微信可重新绑别的账号。「跨端绑定不一致」记号随人工处理完毕清除，账号注销时连带清除。
- 不导出、不外传。

## 附录 D：动工与上线前提（项目主人在微信后台要办的五件事 + 收尾两步）

1. **微信开放平台绑定两个应用**：登录微信开放平台管理中心，把「服务号（公众号）」和「小程序」都绑定到同一个已认证开放平台账号下（光注册认证还不够，必须把两个应用都绑进去，微信才会给同一位球友下发相同的统一编号）。
2. **后台填入小程序 AppID 和 AppSecret**：在微信小程序后台「开发管理 → 开发设置」里拿到 `AppID` 和 `AppSecret`，填入咱们服务器的环境变量（和网页版服务号配置同理，填上即生效，不用改代码；开发期没填真密钥时走本地假通道测试）。若小程序后台开启了「服务器 IP 白名单」，把咱们服务器的公网 IP 一并加进去。
3. **配置小程序合法域名**：在小程序后台「开发管理 → 开发设置 → 服务器域名」里，把咱们正在用的线上已备案 HTTPS 域名填进 `request合法域名`（顺手把 `downloadFile合法域名` 也填上同一域名备着）——小程序调后端接口和加载线上装扮图片都要过这个白名单。
4. **填写《用户隐私保护指引》**：在小程序后台「设置 → 服务内容声明 → 用户隐私保护指引」里，如实申报收集「昵称、手机号、剪贴板」等实际用到的信息及用途（用于建立球员档案、球局通知联系、复制分享或诊断信息）——不填妥这一项，提审必被打回，真机上的昵称一键填入等功能也会被微信拦下。
5. **选好小程序服务类目**：提审前在小程序后台「设置 → 基本设置 → 服务类目」里选好类目（体育 / 工具方向，按后台可选范围定）。

**收尾两步**（代码做完后办，不办外人搜不到）：先上传设为**体验版**，自己人和几位常打球的球友真机试跑一圈；确认没问题后正式**提交审核、审核通过后点击发布上线**。
