## 1. 这是要解决什么问题（必填，人话）

- 现在的毛病：球友多半从微信群点链接进来，明明微信里人手一个现成的身份，还得靠「这台手机认识你」的本机记忆，换了手机、微信重装或清理过，就要重新走短信验证。1.6 立第四把钥匙时资质没到位，登录页和名片卡上只留了两个「即将开通」的空位。
- 一句话的成功画面：**球友在微信里点一下「微信一键登录」，微信弹出确认页，再点一下确认——名片、报名、战绩原样回来，从此换手机、微信重装清理过都不怕**。第一次用的新面孔，确认完落去填一张名片，微信号顺手记在账号上；下次再点，一步直接进。

## 2. 给谁用（必填，按角色写）

- **球友**（含组织者，人人同权）：多一把不输不记的钥匙——微信里点两下就进；绑过之后换设备、微信重装过也不用等短信。
- 与本功能无关的角色不受影响：不用微信登录的人，短信、密码、本机记忆三把钥匙一条路不变。
- 不为任何角色服务的部分：无（抓微信头像昵称、小程序端登录等见 §6，都不是本轮件）。

> 角色差异只用 §4 场景表达，不立权限表。

## 3. 用户故事（必填）

1. 作为球友，我在微信里点开球局链接想报名，想点一下微信授权就认出我，以便永远不用输手机号等验证码。（→ §1 体验）
2. 作为球友，我换了手机或微信重装清理过，想凭微信点两下拿回全部战绩，以便不用找短信。（→ §1 体验；对齐 1.6 故事 4）
3. 作为第一次来的新球友，我在微信里点「微信一键登录」，想填一张名片就建号开打，以便微信身份顺手记上、下次直接进。（→ §1；对齐 1.6 故事 8/9）
4. 作为老球友，我以前没用微信登过，这次微信登录说我是新面孔，我想收一条短信证明账号是我的，以便微信从此自动接上、下不为例。（→ §1；对齐 1.6 故事 8「老账号自动接上」）
5. 作为填手机号时被告知「已被占用」的球友，我想用微信证明这个号是我的，以便少等一条短信直接进入那个账号。（→ §1；对齐 1.6 故事 13 占卡第三出口）

## 4. 输入 / 输出场景（必填，文档核心）

### 场景 4.1：微信里，正式绑过的老球友一键回家
- **身份**：球友（已在册，微信号已**正式绑**在账号上——见 4.3 的「正式」怎么来的）
- **前提**：在微信内置浏览器里打开登录页；这台设备不认识他（新手机、微信重装或清理过），或这台设备上正登着别人的账号、他想切回自己
- **操作**：点「微信一键登录」→ 微信授权确认页点「允许」
- **结果**：
  1. 跳回登录页，画面一闪已换成「欢迎回来 · 战绩都在」——名片、报名、战绩原样；
  2. 原先进行到一半的动作（比如刚点的报名）接着办完，不用重新点；若那件事已经办不成了（球局满员/截止/被撤），回来说明原因，不静默吞掉；
  3. 若这台设备原先登着别人的账号——微信进门即切换成本人，与现有「登录即切换」同款，不另立规矩；
  3. 在微信确认页点「取消」=什么都不发生，回原画面重点一次即可。
- **禁止**：不弹任何要输手机号或验证码的框；不重置他设过的密码、不踢他别的设备（日常进门，不是接管）。

### 场景 4.2：微信里，新面孔落名片建号
- **身份**：从未注册过的球友
- **前提**：在微信里打开登录页（或从名片卡右上角「登录」进来），点「微信一键登录」→ 确认页点「允许」，系统回话「这个微信号还没绑过账号」
- **操作**：按画面引导继续
- **结果**：
  1. 跳回后落到的就是**现有的名片卡**原样（叫什么/选头像/手机号三行，手机号旁的用途说明照旧，右上角「登录」照旧在）——新面孔直接填卡提交；
  2. 建号成功，**绑定真成了**才多提示一句「微信号已绑上 · 下次一键直接进」；这次没绑上（比如填得太慢凭条过期）就只报建号成功，不说绑上的话，下次再试自然补上；
  3. 之后再点「微信一键登录」，走 4.1 直接进。
- **禁止**：跳过名片直接建号（手机号必填的规矩不破，1.6 §4.12 明令）；授权确认页之外再加第二次确认。

### 场景 4.3：老账号自动接上微信（就这一次短信）
- **身份**：在册老球友，微信号还没绑过
- **前提**：同 4.2 的开场——微信登录回话「还没绑过账号」，落到名片卡
- **操作**：他不填卡（那会建新号），点名片卡右上角的「登录」，走现有的「收验证码」或「用密码」任一栏验证自己
- **结果**：进入账号的同时提示「微信号已正式绑上 · 下次一键直接进」——从这次起走 4.1。这把「正式绑」从此与短信同级可靠。
- **禁止**：再要他做任何额外的「绑定」操作（验证那一刻自动接上）。

### 场景 4.4：占卡态，微信验证直接进——与短信出口完全同待遇
- **身份**：填手机号建号/报名时被告知「这个手机号已经有人用了」的球友
- **前提**：名片卡显示三个证明出口（短信 / 密码 / 微信）；他的微信号已**正式绑**在这个手机号的账号上
- **操作**：点「微信验证进入」→ 微信确认页点「允许」
- **结果**：跳回后直接进入那个账号，效果与短信出口**完全一致**（1.6 §4.5 原文）：刚才明确填过的名片内容并入账号、全设备旧记忆作废（含密码，宽限窗内可免码设新密码）、挂起的动作接着办完。
- **禁止**：这条出口自创一套与另两条出口不同的效果。

### 场景 4.5：占卡态，微信还证明不了——分情形指路
- **身份**：同 4.4，但属于下面两种之一
- **前提**：三种情形，前两种同用一句通用话术——
  - 甲：这个微信号从没绑过任何账号；
  - 甲'：这个微信绑的**正是当前这个账号**，但只是当年建号时顺手记的、没验过手机号（本人换设备直接填卡触发的占卡）；
  - 乙：这个微信已经属于**另一个**账号。
- **操作**：点「微信验证进入」→ 微信确认页点「允许」
- **结果**：跳回后按情形各说各的话，说完留在占卡画面，短信、密码两个出口照常可用：
  - 甲/甲'：「这个微信还证明不了这个账号是你的——用短信或密码验证进入，进去就自动绑牢」；
  - 乙：「这个微信已经属于另一个账号——这个账号请用短信或密码验证」。
  - 走完任一验证进入后：这个微信**换绑到当前账号**（原先绑着的账号的微信绑定自动解开），下次点一键登录进的就是现在这个账号；甲'则原地升为正式绑。
- **禁止**：把两种情形拼在一句话里说；透露那个「另一个账号」是谁；乙情形绝不允许放行进入。

### 场景 4.6：不在微信里点微信登录
- **身份**：任何球友
- **前提**：用普通浏览器（或电脑）打开登录页
- **操作**：点「微信一键登录」
- **结果**：说明「请在微信里打开本页（把链接发到微信里再点开）才能用微信登录，或直接用短信/密码」，画面不动；短信、密码两栏照常可用。
- **禁止**：跳去一个打不开的授权页让用户卡死。

### 场景 4.7：资质还没配好（通道关着）
- **身份**：任何球友
- **前提**：平台侧微信通道还没配置（资质、密钥没填）
- **操作**：点「微信一键登录」
- **结果**：维持现状——说明沿用 1.6 的占位原句「微信登录即将开通 · 资质到位后点亮」；配置一填上，同一颗按钮自动变真，不用改版。

### 场景 4.8：授权凭证过期/失效
- **身份**：任何球友
- **前提**：点完「允许」后在微信里停了太久（凭证约 5 分钟有效）或网络断了才跳回来
- **操作**：跳回登录页
- **结果**：提示「微信授权已过期，请再点一次」，画面回到可重点的状态；重点一次即走通。其他钥匙路完全不受影响。
- **禁止**：把过期当错误页处理（可自愈的事不吓人）。

### 场景 4.9：冒填者的微信进不来（安全底）
- **身份**：冒填者（拿别人手机号建号并顺手绑了自己的微信）
- **前提**：账号真主人此后任意一次验明正身（短信验证/密码登录/接管任一）
- **操作**：（真主人的正常操作）
- **结果**：冒填者顺手绑的微信**自动解开**——他的微信再点「一键登录」会被当新面孔对待，进不了这个账号；这与现有「验证一次杀掉未验证钥匙」同一条规矩，只是扩到了微信。
- **边界说明**：若「顺手绑」的其实是本人（建号时没验手机号、后来自己验了一次身）——绑定同样被解开，下次微信点一键会被当新面孔，再走一遍 4.3 重新正式绑上即可；这是一次性代价，防冒填者的必要代价。也要说实话：顺手绑跟着微信走，比本机记忆（只困在一台设备上）更能跨设备——冒填者的寄生能力强一档，所以杀绑的闸门必须立（待遇与未验证钥匙同级，闸却是两道）。
- **禁止**：让未验过手机号的微信绑定享有与短信同等的开门权、接管权。

### 场景 4.10：注销后微信登记位释放
- **身份**：注销账号的球友
- **前提**：按 1.6 §4.6 走完注销
- **操作**：（注销流程本身，无新增操作）
- **结果**：微信号与旧账号的绑定随之清除；他日重新注册新账号，同一微信号可绑新号，互不纠缠。

## 5. 验收标准（必填，可勾选）

- [ ] **正常流程**：[球友] 微信内、账号与微信已正式绑定时，登录页点「微信一键登录」→ 微信确认页点允许 → 回来即进入账号，名片战绩齐全，进行到一半的动作接着办完；办不成的（满员/截止）回来说明原因 —— 故事 1/2
  → 验证：开发库造一个已绑定账号，微信内（或开发假通道）走一遍，回来看到「欢迎回来」且无任何输码步骤
- [ ] **空状态（新面孔）**：[球友] 无账号的微信点「微信一键登录」→ 落到现有名片卡（右上角登录入口在），填完建号且绑定真成了才提示「微信号已绑上」；同一微信再点一次 → 直接进 —— 故事 3

  → 验证：老账号 + 新微信，短信路与密码路各走一遍（B1：凭条在两处验证时刻都被消费），再各走一遍 4.1
- [ ] **占卡微信直进**：[球友] 占卡态点「微信验证进入」（已正式绑在该号上）→ 直接进入那个账号，效果与短信出口一致（名片并入、全设备旧记忆作废、挂起动作接着办）—— 故事 5
  → 验证：造一个已绑定账号，用另一台设备占卡，走微信出口后拿旧设备的钥匙试认人（应已失效）
- [ ] **占卡指路**：[球友] 甲（没绑过）、甲'（顺手绑在本账号）、乙（绑在别处）各点微信出口 → 通用话术与分情形话术各就各位，短信密码出口照常；走完验证后甲/甲'原地或换绑成正式绑、乙的原账号绑定自动解开 —— 故事 5
  → 验证：三情形各造一例核对文案、不放行与换绑结果
- [ ] **出错**：凭证过期/网络断 → 「请再点一次」可自愈；微信服务不通 → 「微信登录暂时不可用，可先用短信或密码」 —— 场景 4.8
  → 验证：用过期凭证与关闭假通道各试一次
- [ ] **边界（安全）**：冒填者建号顺手绑微信，真主人短信验证进入后，冒填者微信成新面孔、进不来；本人顺手绑被解开后再走一遍 4.3 可重新正式绑上 —— 场景 4.9

  → 验证：电脑浏览器与空配置各点一次
- [ ] **不动旧路**：不用微信的球友，短信/密码/本机记忆三把钥匙行为与 1.6 完全一致 —— §2
  → 验证：回归跑 1.6 全部既有用例不红

## 6. 边界与非目标（必填）

- ❌ 明确不做：
  - 小程序端登录（另一套通道）——第二阶段；本轮设计不堵死将来的路（绑定登记不与小程端冲突）；
  - 静默授权秒认（无确认页）——留二期评估（见 §8 裁决 1）；
  - 微信一键建号跳过名片——1.6 §4.12 明令禁止；
  - 抓微信头像/昵称——名片体系自有，账号不绑死微信；
  - 解绑/换绑微信的用户界面——换绑走「验证即顶替」（4.5 下文）自然完成；系统侧的自动清绑（接管/注销/验明正身杀顺手绑）照做但不是用户操作。
- ✅ 做但降级（自用够用）：
  - 开发期无资质：走「假通道」（同短信开发期把验证码打日志的先例）——假通道里授权凭证即身份号，全链可测；上线换配置即真；
  - 绑定凭条超时：静默跳过绑定、**不说「已绑上」**，绝不拖垮建号、找回这些主流程本身（下次再试自然补上）；
  - 转微信授权的一趟往返里，挂起动作存在本机——回来接着办；若存的过程本身失败（极老旧机型），退化为回到原页重点一下动作，不丢数据。

## 7. 附录（前端必拼，后端/数据按需）

### 附录 A：前端行为

**A1. 屏幕清单**
- 登录页（我是老球友）：「微信一键登录」行从占位点亮为真按钮；点后跳微信确认页、带凭证回来后本页自动完成进门或分流。
- 名片建号卡（占卡态）：「微信验证进入」行同样点亮；点后同样跳微信，回来进登录页收尾。
- 名片建号卡（填卡态）：不新增任何元素——「还没绑过」的微信落到这里就是现有卡原样（4.2/4.3 一副面孔服务新老两拨人：新面孔填卡，老球友点右上角「登录」）。

**A2. 每屏的状态**
- 空状态：微信号未绑定时点一键登录 → 落名片卡（带绑定凭条在手里，填卡提交即顺手绑；点右上角登录走短信/密码，验证完同样顺手绑）；
- 加载中：跳微信前把「回来要用的东西」（占卡手机号、进行到一半的动作、原页面位置）存进本机——确认页往返是整页跳转，不存就丢；
- 出错：见场景 4.8——可自愈的提示重点，不可自愈的指路短信/密码。

**A3. 操作与响应**
- 点「微信一键登录 / 微信验证进入」→ 即刻跳微信确认页 → 允许后带凭证回来 → 画面自己走完剩下的路（进门/落名片/指路），全程无需用户理解「凭证」；
- 误操作可救：授权确认页点「取消」=什么都不发生，回原画面重点即可。

**A4. 数据从哪来**
- 跳微信前要向系统要「去哪里授权」的地址——系统算好整条链接，画面只管跳；
- 回来后「这个微信绑没绑、绑得牢不牢、绑在谁身上」是系统判好定死的，画面照结果分流，不自己猜；
- 「已绑上/还没绑」的提示语跟着系统判定走：绑定真成了才说「已绑上」，一个字不编。

### 附录 B：后台行为

**B1. 触发与响应**
- 要授权地址：即时回；未配置时明确回「还没开通」（画面据此显示占位说明）；
- 拿凭证问身份：调微信官方的问询（正常几百毫秒内），问回「这是哪个微信」后按登记位**三支分流**：
  - 正式绑 → 发钥匙，钥匙与短信验证过的同级（本人短信找回不会登出它）；
  - 顺手绑 → 也发钥匙进门，但只当「没验过身份」用——待遇与建号时那把本机记忆同级（真主人验明正身时一并杀），但比本机记忆更能跨设备（跟着微信走），故另有「验明正身解绑」这道闸（4.9）；
  - 没绑 → 发一张十分钟有效的绑定凭条，同时发凭条给顺手绑的微信（供换绑顶替用，见 4.5 下文）；
- 绑定凭条在建号、短信验证、密码验证这些「验明正身」的时刻被带着，成功即顺手绑上：验证时刻绑的=正式绑；纯建号（未验手机号）时带的=顺手绑；
- **换绑即顶替**：凭条绑上时，这个微信原先绑着的别的账号的绑定当场解开——一个微信永远只开一扇门；同一账号重绑只升不降（正式绑不因新凭条降回顺手绑）；
- 授权凭证五分钟一次性（微信侧规矩），绑定凭条十分钟一次性（与建号续接窗口同刻度）。

**B2. 失败时用户看到什么**
- 微信官方服务不通：「微信登录暂时不可用，可先用短信或密码」——三把旧钥匙完全不受影响；
- 凭证被微信判失效：「请再点一次」；
- 绑定凭条过期/已被用过：静默跳过绑定（不说「已绑上」），主流程照常成功（§6 降级）。

**B3. 量放大 100 倍时**
- 微信授权问询零边际成本、单次毫秒级，几百到几千人量级无感；不设短信那样的花钱限频；若被恶意刷授权问询，加简单的每设备每天次数上限即可（量级未到不做）。

### 附录 C：数据行为

**C1. 数据清单**
- 微信登记位：每个账号至多记一个微信号绑定，含「绑的时刻」与「正式与否」两笔标记；同时每个微信至多开一扇门（新验证绑上即顶替旧绑定，旧微信当即失效）；
- 绑定凭条（临时）：十分钟内有效的一次性凭条，只存加工后的记号不存原文（同钥匙、验证码的既有规矩）。

**C2. 谁能看 / 改 / 删**
- 登记位只有本人间接感知（「已绑上」提示）；任何人都看不到别账号绑了什么微信号；客服也不看名单——需要断开某个微信时，引导本人走短信接管（接管清场时微信绑定一并作废，4.4），不用后台动手。
- 换设备照常在：绑定在云端，不在本机。

**C3. 留多久、删了会怎样**
- 绑定随账号长期保存；自动清除的时刻：
  - 账号注销（登记位释放，同手机号释放）；
  - 短信/密码出口的接管（1.6 §4.5 清场语义——短信证明的是号码，号码可能易主，旧绑定可能是别人的）；**微信出口的接管不清绑定**——它清场其余同款（旧钥匙/密码），但微信绑定本身就是这次的进门凭证，清了本人下次一键就废了；
  - 验明正身时清除「顺手绑」档（防冒填者，4.9；正式绑不动）；
  - 换绑顶替（新的正式绑定当场解开旧绑定，4.5 下文）。
- 「忘记密码重置换锁」**不清**正式绑——换锁后微信这把钥匙还在，本人多条活路；被盗微信的断开走短信接管（见 C2）。
- 清除后同一微信号可绑任何账号，无残留；绑定凭条过期自动作废，不落个人资料。
