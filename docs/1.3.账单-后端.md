## 1. 这是要解决什么问题（必填，人话）

- 球打完、钱在微信里转，账全靠人脑记：谁转了谁没转、组织者垫了多少收回来多少，一周就糊了。app 里的账单页目前是演示数据，记不了真账（0号 问题 6：「订了又常来不够人，场地费亏着分摊」——钱的事没个准数，就不敢再订场）。
- 一句话成功画面：**一场球完整散场，账自动算出来**——谁该摊多少、欠谁，一眼看清；转完的标已转，收到的标已收，月底翻旧账依然笔笔对得上。

## 2. 给谁用（必填，按角色写）

- **参加者（球友）**：每场该摊多少、欠谁（就是那场的组织者），转完钱点一下「结算」，自己的账自己心里有数。
- **组织者**：垫了多少钱、谁还了谁没还，按人收账不漏人；散场时忘了填总价，事后补上账照样出来。
- 哪些部分不为任何角色服务：无。
- 与本功能无关的角色：**管理员**（组织者临时封的现场帮手）——现场事项同权，但**不碰钱**：补填总价、看点收明细、点「已收」都只归组织者本人（见附录 C2）。游客——照旧看演示账单，不受影响（见场景 4.9）。

## 3. 用户故事（必填）

1. 作为参加者，我想散场后立刻看到这场我该摊多少、欠谁，以便微信转钱不用问人。（→ §1）
2. 作为参加者，我想转完钱点一下「结算」，以便账单里待付归零、心里踏实。（→ §1）
3. 作为组织者，我想看到这场谁还没转钱、按人收账，以便挨个催不漏人。（→ §1）
4. 作为组织者，我散场时没填总价也能事后补，补完账自动出来，以便漏填不丢账。（→ §1）
5. 作为任何人，我想按近 7 天 / 近 30 天翻账，以便月底对总账。（→ §1）

## 4. 输入 / 输出场景（必填，文档核心）

> 三数 = **应付**（我还欠的，红）、**已付**（我结清了的）、**应收**（我垫的钱别人该还我的，黄）。已收讫的整笔不占三数，翻旧账仍能看到。

### 场景 4.1：散场出账 · 参加者看到自己那一行
- **身份**：参加者
- **前提**：这场局报名锁了名单、完整打完并散场；组织者在散场确认前填过总价（如 2 片场 700 元——开打后加场、买球买水的钱也随时可以加进总价，见 4.5）
- **操作**：组织者散场；我（打完球回家）打开「我的-账单」
- **结果**：
  - 账单里多一笔**待付行**：局名、日期记散场那天、我该摊的金额，行上写明「欠 ×××」（那场的组织者）；
  - 我带了朋友的话，行上金额是「人均 ×（1 + 带来的人数）」，旁边一行小字「含带来的朋友 ×2」；
  - 顶部三数里的「应付」随之变大；
  - 点这行仍进原来那场的局页，能看到这场总价多少、人均多少、名单里有谁、我自己那份多少——**局页里「我自己那份」和账单行是同一个数**（含朋友份、同样带小字）。
- **禁止**：我在任何地方看不到别人摊多少、别人结没结。

### 场景 4.2：散场出账 · 组织者看到整场的账
- **身份**：组织者（同一场局）
- **前提**：同 4.1
- **操作**：打开账单
- **结果**：
  - 多一笔**应收行**：局名、日期、金额起步=这场别人该摊的合计（我自己那份我自己出了，不算欠）；
  - 点开这行是**按人明细**：每个别人该摊多少、收没收到；带朋友的人金额含朋友份（同样带小字）；明细末尾一行「总价 700 · 我自己那份 62」——我兜的零头不用自己心算；
  - 三数下方的「谁还欠你」块跟着更新：谁、一共欠多少、几场。

### 场景 4.3：转完钱点「结算」（参加者）
- **身份**：参加者
- **前提**：有一笔待付，钱刚在微信里转给了组织者
- **操作**：在该待付行点「结算」，屏幕先问一句「钱已经转出了吗？点了就不能改回」，确认后生效
- **结果**：行从待付变**已付**，三数的应付随之减少；这个动作只是我自己记账，组织者那边仍按他点没点「已收」算（见 4.4）——两边各记各的，谁也不用等谁。
- **禁止**：点完不能再改回待付（转错了线下找组织者商量，账不留反悔口子）。

### 场景 4.4：逐人收账（组织者）
- **身份**：组织者
- **前提**：有一笔应收，其中小赵把钱转来了
- **操作**：点开应收行的按人明细，点小赵名下的「已收」（同样先问一句「钱已经收到了吗？点了就不能改回」）
- **结果**：
  - 小赵这行标已收；「谁还欠你」里小赵的合计减掉这笔；应收行的金额点一个人、少一笔——点完最后一个，整行自动变**已收**（已收的整笔不占三数，翻旧账仍能看到），不会出现 0 元的行；
  - 已说过「已转」的人（自己那边点过「结算」），明细里名字旁有一行灰字「已转 · 待收」——提示组织者先去微信里对一下账再催。
- **禁止**：点完「已收」不能撤销；参加者点「结算」不会替组织者把任何人标成已收。

### 场景 4.3b：对方先收了，我这边还挂着（参加者）
- **身份**：参加者
- **前提**：我用现金付了、或转完忘了点「结算」；组织者对完账已经点了我的「已收」
- **操作**：打开账单
- **结果**：我的待付行上有一行只读灰字「对方已收款 · 记得回来点结算」——三数还照旧（以我点没点「结算」算），但我知道钱其实对方已经认了，不会以为自己还欠、转两遍。
- **禁止**：系统不会替我自动点「结算」（各记各的裁决不变），也不会把这条灰字发给组织者以外的任何人。

### 场景 4.5：改总价、补填总价（组织者）
- **身份**：组织者
- **前提**：局还没散场（或散场了但一直没填过总价）
- **操作**：散场确认前，我随时改总价——开打前在局页的订场登记面板改，开打后一样改（加一片场、中场买球买水，钱都往总价里加）；散场确认那一步，看着屏幕亮出的数字收工；没填过总价的局，事后点账单页顶部那句提醒、直达局页补填总价（真免费填 0）
- **结果**：
  - 改总价改多少次都行——账还没出，改价不碰任何人的账；
  - 散场确认那一步，屏幕亮出这场的总价、摊钱人数、人均（如「总价 700 · 12 人 · 人均 58」），我过目后收工——填错 7000 的，这最后一眼能拦住；
  - 散场时总价还没填过的，不出账：谁的账单里都没有这场；我的账单页顶部挂着一句提醒「你有 1 场局费用未定，补填后才出账」（提醒本身可以点，点了直达填总价的地方）；那场局的局页里费用仍显示「未定」，填的口子只让填总价、不再改场地号；
  - 补填时先给我看一步确认：「将按人均 X 元向 N 人出账」，我点定，账**那一刻**出现，日期仍记散场那天；填 0 的话不出账、提醒消失。
- **禁止**：散场确认之后，填过的总价不能再改——价格就此定死；只有「从未填过的局」才留补填这一个口子。

### 场景 4.6：翻旧账与看账的边界（任何人）
- **身份**：任何人
- **前提**：账单里已有若干笔
- **操作**：切期间筛选（近 7 天 / 近 30 天 / 全部）
- **结果**：三数、逐笔列表一起跟着筛选走；每笔按**散场那天**归入期间；「谁还欠你」也跟着筛选走，但块上带一行小字「只算所选期间内散场的局」——切「近 7 天」后旧的欠款从块里消失，是筛选不是结清。
- **看账边界**（谁登录谁只能看自己的账）：我看到的逐笔只有我的待付/已付 + 我的应收/已收；组织者能看自己那场的按人明细；**任何人都看不到「别人欠别人」的钱**；我点进一局，看得到总价、人均、名单和我自己那份，看不到别人摊多少、结没结。
- **禁止**：账单不支持按局外分享给别人看。

### 场景 4.7：没打完的局永远不出账
- **身份**：任何人
- **前提**：局被组织者撤了、或到截止人数不够黄了、或还在进行中
- **操作**：过任意久再打开账单翻找这场局
- **结果**：任何情况下都找不到这笔账——只有**完整打完散场**的局才算消费了场地，才有账。撤掉 / 黄掉的局，组织者真订场真亏的钱 app 里不记账（场地损失自认，见 §6）。

### 场景 4.8：注销账号与账（参加者 / 组织者）
- **身份**：任何人
- **前提**：想注销账号
- **操作**：走 5.1 已定的注销流程（后果说明 + 短信验证 + 二次确认）
- **结果**：还有没结的**待付**、或没收完的**应收**，都先提醒一句去结清 / 收清（提醒一次，不拦死，仍可继续注销）；注销后，别人账单里跟我的往来**留档不删**，我的名字显示为「已注销球友」，金额照旧——账要对得上，人可以走。

### 场景 4.9：游客看账单（2026-10-10 修订：演示账单随 mock 世界退役）
- **身份**：游客（没登录）
- **前提**：从没登录过、或钥匙已失效，处于游客状态
- **操作**：打开「我的-账单」
- **结果**：账单页顶部亮一行「未登录 · 登录后看你的真账」，旁边给登录入口；下面是空账（三数 ¥0、无逐笔），不发请求。登录后换成真账，从第一场真局开始积累。
- **沿革**：原版游客看演示账单（假数据标明「演示」）。2026-10-10 mock 演示世界整体退役，演示账单无数据源，改为空账自持；「不许假数字冒充真账」的禁止原意不变，且更彻底——根本不再有假数字。
- **禁止**：游客态不许把任何编造的金额冒充真账给人看。

### 场景 4.10：断网点「结算」/「已收」
- **身份**：参加者 / 组织者
- **前提**：网络不好
- **操作**：点「结算」或「已收」
- **结果**：提示「网络不给力，请稍后再试」，可重试；点成功的不会丢、也不会因为多点几下记重——这笔账只有「转了/没转」「收到/没收到」，没有数量，重复点不出错。

### 场景 4.11：打完忘散场，事后补散场（组织者）
- **身份**：组织者
- **前提**：局完整打完，但我忘了点「散场」直接走了；局到点后自己显示「已结束」
- **操作**：事后想起来，回到这场的现场页补点「散场」（残局清完、考勤照常定格）
- **结果**：散场补上那一刻，账照常出——总价填过的直接出账，没填的挂「费用未定」提醒等补填（4.5）；已经记的分数、考勤原样保留。
- **禁止**：参加者不能替组织者散场（散场是组织者的确认动作）。

## 5. 验收标准（必填，可勾选）

- [x] **正常流程**：[参加者] 完整散场的局（总价已填）出账，待付行写明欠谁、金额正确，带朋友的含朋友份并带小字标注 —— 故事 1
  → 验证（✓ 已实现）：真页走查——带 2 个朋友的球友账单行显 174 与「含带来的朋友 ×2」，点行进局页「我自己那份 ¥174」同数；12 人 700 元散场即出账，11 个别人各 58，作为参加者打开账单：我的待付行金额 58、行上「欠 组织者」；带了 2 个朋友的人看到 174 与「含带来的朋友 ×2」；局页里「我自己那份」同样是 174
- [x] **正常流程**：[组织者] 应收行金额=别人该摊合计，按人明细齐全、末尾带「总价 · 我自己那份」，点某人「已收」后「谁还欠你」与应收金额实时缩水 —— 故事 3
  → 验证（✓ 已实现）：真页走查——组织者明细末行「总价 ¥700 · 我自己那份 ¥62」；点小赵的「已收」：应收 638→580、「谁还欠你」小赵 116→58；已收整笔翻已收不占三数、无 0 元行「总价 700 · 我自己那份 62」；点小赵（58）的「已收」：应收从 638 变 580，「谁还欠你」小赵少 58；11 人全点完整笔变已收、不再占三数、没有 0 元的行
- [x] **正常流程**：[参加者] 转完点「结算」（先过一句确认），待付变已付、不反悔 —— 故事 2
  → 验证（✓ 已实现）：真页走查——点「结算」先弹「钱已经转出了吗？点了就不能改回」；确认后行变已付、按钮消失（无入口改回）；应付 348→174「钱已经转出了吗？点了就不能改回」；确认后行变已付；再点无反应也无报错；没有任何入口改回待付
- [x] **空状态**：新登录用户账单页三数为 0、无逐笔、「谁还欠你」收起
  → 验证（✓ 已实现）：陌生账号视角接口全零（自动化测试锁）；页面空态渲染空样式不报错，看到空账的样子而不是报错或白屏
- [x] **加载中**：打开账单页等待时显示占位样式，不超过 3 秒
  → 验证（✓ 已实现）：账单页先占位后补上（真页刷新可见占位一闪；弱网未专门模拟），先看到占位、随后内容补上
- [x] **出错**：断网点「结算」/「已收」提示网络重试，恢复后重试成功、不重复记账 —— 场景 4.10
  → 验证（✓ 已实现）：断网提示「网络不给力，请稍后再试」可重试（自动化测试锚断网文案与重试后成功）；重复点不重记（后端幂等测试锁）；恢复后重试，行变已付；连续快点多次不出错
- [x] **边界**：摊钱名单——把锁单时**正式报名**的人和现场实际打球的人合成一份名单，同一个人只算一次；锁单后缺席的照摊、没报名空降的照摊、早退的整份照摊、**候补不算**（没占坑也没打球）—— 场景 4.1
  → 验证（✓ 已实现）：自动化测试——缺席照摊、空降照摊、早退整份、候补不算，四种人同局各断言——锁单后缺席的、没报名扫码直接打的、打一半早退的、一直候补没转正的：前三人账单行都出现、金额都是整份，候补者没有
- [x] **边界**：除不尽的零头组织者兜底，合计恒等于总价
  → 验证（✓ 已实现）：真页走查 11×58+组织者 62=700；自动化测试另锚 650/9、1000/15（含访客归担保人）恒等：11 个别人各 58、组织者自己那份 62；应收合计 638，加组织者自己出的 62 正好 700
- [x] **边界**：总价散场确认前随时可改、确认亮数、确认后定死 —— 场景 4.5
  → 验证（✓ 已实现）：自动化测试——开打后改价成功、到点未散场可改、散场后改价被拦；真页走查散场确认页亮「总价 500 · 3 人 · 人均 166」；已填价的散场后无改价口（买球），散场确认那步亮出「总价 800 · 12 人」；确认后账按 800 摊；散场后开订场登记面板：填过价的改不了，没填过价的只能填总价
- [x] **边界**：费用未定不出账，补填（带出账确认步）才出、日期记散场日、填 0 不出 —— 场景 4.5

## 6. 边界与非目标（必填）

- ❌ 明确不做：微信内付钱 / 代发起转账；一键催款；消息推送提醒；给谁免摊、少摊、手动改某人金额；垫钱人指定为组织者以外的人（朋友帮垫不支持）；账单分页；旧演示数据迁移；账单作废重开；**撤掉 / 黄掉的局的场地损失不记账**；**管理员碰钱**（补填、点收、看明细都只归组织者）。
- ✅ 做但降级：费用未定的提醒=账单页顶部一句话（可点直达，不做推送）；游客看演示账单沿用现状（但须标明「未登录 · 演示数据」）。

## 7. 附录（前端必拼，后端/数据按需，同样人话）

### 附录 A：前端行为

**A1. 屏幕清单**
- 账单页（「我的」进入）：真数据账单的主场；期间筛选、三数、「谁还欠你」、逐笔列表都在这。
- 局页（原场次页）：摊账明细的展示位；订场登记面板散场确认前一直可改总价，散场后对没填过价的局保持「只填总价」的补填口。
- 散场确认（现场页收工那步）：亮出总价、摊钱人数、人均，过目后收工。

**A2. 每屏的状态**
- 空状态：三数 0、无逐笔、「谁还欠你」收起；费用未定时顶部一句话提醒（仅组织者可见、可点）。
- 游客态：顶部「未登录 · 登录后看你的真账」+ 登录入口；下方空账（三数 ¥0）。（2026-10-10 修订，原「演示数据」版随 mock 退役）
- 加载中：占位样式，3 秒内补上。
- 出错：断网提示 + 重试；已点成功的动作不丢。

**A3. 操作与响应**
- 点「结算」/「已收」→ 先问一句「钱已经转出 / 收到了吗？点了就不能改回」→ 行立刻变化（1 秒内）→ 不可撤销。
- 补填总价 → 先看「将按人均 X 元向 N 人出账」→ 点定出账。
- 误操作怎么救：都不支持 App 内撤销——转错、点错线下商量（账只记事实，不留反悔口子）。

**A4. 数据从哪来**
- 每笔该摊多少、按人明细每行多少、三数、「谁还欠你」的每人合计与场数——全部是**引擎算好定死的**，界面一个数不许自己算、不许自己改（「应收」永远等于按人明细里没结的加总，两处必须永远是同一个数）。
- 订场时局页显示的人均是**预估**（按当时报名人数算）；散场后局页显示的人均是**实摊**（按摊钱名单算）——两个数可以不同，界面要让看的人分得清哪个是估算（预估标「约」）。

### 附录 B：后端行为

**B1. 触发与响应**
- 散场确认那一刻：总价已定的，账当场算好；组织者补填总价那一刻：账当场出现。都不用任何人再点「生成」。
- 总价散场确认前随时可改（含开打后加钱），改多少次都行——账还没出，改价不碰任何人的账。
- 点「结算」/「已收」：1 秒内生效；「已转 · 待收」「对方已收款」两个方向的提示实时同步给对方。
- 出账算的是**定格名单**：散场定格的现场名单（谁在场、谁早退、谁没到、谁带来的朋友、谁空降）合上锁单的正式报名名单，一次算定，事后进出的变动不再影响这笔账。
- **空降与带访客要能进账，先得有账可进**：这两类人目前只记在组织者手机上、系统的总账本里还没有他们——本域落地时要把这两条记账通道补上（2.3 收口时挂账移交的四动作之二），否则「空降照摊、朋友份额归担保人」无从算起。

**B2. 失败时用户看到什么**
- 断网：提示重试，不丢账；重试不产生重复记录（这笔账只有转没转、收没收，没有数量）。

**B3. 量放大 100 倍时**
- 一年几百笔账全量翻：账单页仍一次打开（不分页）；筛选、三数即时得出。微信群量级下最先扛不住的是翻很久以前的全部列表——到那一步再谈分页（记 §6 非目标）。

### 附录 C：数据行为

**C1. 数据清单**
- 一场局的账：摊钱名单每人一行——该摊多少、说「转了」的时刻、组织者点「收到」的时刻；外加这场局的总额与散场日。
- 名单定格依据：散场定格的现场名单 + 锁单的正式报名名单，算完即定格，不再随局变动。

**C2. 谁能看 / 改 / 删**
- 我的那行：本人看、本人点「结算」；组织者那场的明细：仅组织者看、仅组织者点「已收」——**管理员同权管现场，但账单相关动作一律不沾**。
- 别人欠别人的钱：谁也看不到。
- 换设备登录：账还在（跟着账号走，不跟手机走）。

**C3. 留多久、删了会怎样**
- 账永久留档，没有删除入口，也没有作废重开；局被撤、黄掉的不产生账，已出的账不随任何后续操作消失。
- 注销账号：往来账留档、名字变「已注销球友」；注销前有未结待付 / 应收先提醒一次（不拦死）。
- 整体导出：暂无（对齐 0号 未承诺，将来要加属修订）。

## 9. 实现偏差（回写留痕，实现期裁决）

- **改价/补填窗口的前端显隐收成后端能力旗**（2026-10-08 债清偿）：窗口规则本体（§4.5 修订①）一直在后端把关，但前端拿派生状态拼了一份镜像，两处锚不同构——「到点未散场」的局（场景 4.11）派生已显示「已结束」，前端会把订场钮收走（后端窗其实开着）、把补填钮错亮（后端必拒）。现后端在局视图「我的」块直发 can_book/can_fill_fee/can_lock 三面旗（与写闸同一份代码算出，闸旗同源），前端显隐直读；同时补发 ended（散场确认锚），账已开未散场的局现场入口常在——场景 4.11「事后回去补散场」的路原先会被前端收走，就此修通。行为不变，实现收口；后端写闸原样保留当保险丝。
- **open 局提前开账再散场的，散场时把局簿名单翻成「已锁」**（走查发现的缺口，2026-10-08 修复）：不锁的局散场后局页一直当「没打完」看，费用未定的补填入口会丢。散场即名单定格，与锁名单同一语义；已在锁单窗口内的局不受影响。
