## 1. 这是要解决什么问题（人话）

- 现在的头像是捏小人——肤色发型表情六部件拼一拼，人人长得差不多；卡背就四档渐变色，而且全站只有「我的战力卡」一处能看见。形象既没味道，也没有奔头，0号「头像做有味道」的承诺一直空着。
- 打球的行为（上场次数、水平分、张罗局）攒了一堆账，却没有一处能兑换成「看得见的荣誉」。
- 一句话成功画面：**打完球翻开装扮页，新解锁的头像挂着「新」标等着穿；穿上之后战力榜、名片、名单、现场到处是我的形象——打得多、打得好、张罗得多，衣柜里见。** 特制款要么实打实打出来、要么官方授予，每一件都有来路；同时把「谁拥有哪件装扮」这本账先立好，将来要收费只是多一种往账本里写记录的方式，不用返工。
- 本册同时宣告退役：现状装扮（捏小人六部件 + 四档渐变卡背）整体下线，我的页规格的装扮节随实现回写挂修订指针。

## 2. 给谁用

- **球友**：一个越打越满的衣柜——公共款随便换、荣誉款达标解锁、被授予的定制款独享；穿上的形象全站可见。
- **组织者**：本身也是球友，另有一条「张罗局」的成就线——发起并正常散场的局数也能换装扮，组织行为被记账。
- **运维（项目主人）**：按手机号或账号编号发卡、收卡的运维口——授予定制款、纠错回收。
- **访客 / 未登录者**：只被动看到别人穿戴的效果，自己没有装扮页。
- **不为任何角色服务的部分**：付费地基——解锁账本按将来能收钱的规格立好，但现在没有任何收费入口，属地基投资，交评审知悉；哨兵线：为收费多预留的任何额外数据都算越线，账本保持零成本留口。

> 账单、战报等页面的既有使用者不受影响：名单、榜单里的人还是那些人，只是形象换新。

## 3. 用户故事

1. 作为球友，我想打满一定场数 / 攒到某个水平台阶 / 张罗够若干局就自动拿到新装扮，以便打球有看得见的奔头。（→ §1 激励）
2. 作为球友，我想在装扮页试穿还没解锁的荣誉款、并看到差什么条件，以便知道下一件怎么拿。（→ §1 激励 + 透明）
3. 作为球友，我想穿上的装扮在名片、档案、榜单、名单、战报、球局卡上都见得到，以便稀缺身份感。（→ §1 身份感）
4. 作为球友，我想直接用微信头像当头像，以便不折腾也有个真形象。
5. 作为新球友，我想注册时挑一个现成头像，以便一进来就有形象。
6. 作为被授予定制款的球友，我想这件装扮只有我有、别人连它存在都看不见——只看得见我穿上的效果，以便专属感。
7. 作为运维，我想按手机号或账号编号往某人解锁清单里塞装扮、还能顺手帮他穿上，也支持收回，以便授予与纠错。
8. 作为球友，我想掉分之后已解锁的装扮不被收回，以便荣誉只增不减。（→ §1 激励）

## 4. 输入 / 输出场景（文档核心）

### 场景 4.1：建号挑形象
- **身份**：新球友（注册卡）
- **前提**：第一次建号（手填或微信快进都一样）
- **操作**：在注册卡头像栏从 **6 款公共基础头像**里挑一个（可不挑，默认第一款）
- **结果**：建号完成，全站各处显示所选头像；之后随时可进装扮页换
- **禁止**：注册卡上不出现荣誉款、定制款；不出现捏小人部件

### 场景 4.2：打开装扮页（顺手核算）
- **身份**：已登录球友
- **前提**：任意时候；可能已有新达标但还没核算的成就
- **操作**：从「我的」页名片点进装扮页
- **结果**：
  1. 系统先核对他的三类数据（参与对局场数 / DUPR 台阶 / 组局数），把新达标的款写进解锁清单——等待感与平常打开页面相当；
  2. 页面分两栏：**选头像**、**选卡背**；顶部一个大试穿框（全站最大的形象展示位），试穿所选的组合；
  3. 新解锁的款挂「新」标记，本人下次再进装扮页后摘掉；
  4. 每件的名称、属于哪一档、没解锁时锁头上的条件文字，全部照官方装扮册子显示，页面上不自造规则。
- **禁止**：核算不改动任何打球记录、积分与账单；不在打完球的当场实时解锁（那是现场链路，不碰）

### 场景 4.3：换穿公共款
- **身份**：已登录球友
- **前提**：在装扮页
- **操作**：点头像栏里某件公共款 → 大框立即试穿；再点卡背栏某件公共款 → 大框换背景；点「保存」
- **结果**：保存成功自动返回我的页，名片立刻换新；之后全站各展示位跟随
- **禁止**：无

### 场景 4.4：试穿未解锁的荣誉款（保存把关）
- **身份**：已登录球友，尚未达标某件荣誉款
- **前提**：装扮页里该荣誉款带着锁头图标与条件文字（例：「参与 20 场对局解锁」）
- **操作**：点这件带锁的头像（或卡背）
- **结果**：
  1. 照样能点、大框照样试穿预览；
  2. 底部保存按钮变灰不可点，按钮文字直接显示还差什么（例：「还差 7 场对局解锁这件」）；
  3. 换回公共款或已解锁款，保存按钮恢复可点。
- **禁止**：未达标时任何途径把荣誉款存成穿戴（见场景 4.11）

### 场景 4.5：达标解锁（三类数据怎么算）
- **身份**：已登录球友
- **前提**：三类数据至少一项过线，档位后续可自行加档：
  - **参与对局**：累计打完并已记进账本的对局场数，打过的就算、那局后来撤没撤不追究——档位 **5 / 20 / 50 场**；
  - **水平台阶**：满 5 场定级后的 DUPR 积分，打开装扮页那一刻的分数达到 3.0 / 3.5 / 4.0 / 4.5 即解锁——判定只看当下，解锁后掉分不收回；
  - **张罗球局**：本人发起、且正常打完散场的球局数，中途撤销的局不算、一场对局没打就空散场的局也不算——档位 **3 / 10 / 30 局**。
- **操作**：下次打开装扮页（系统顺手核算）
- **结果**：过线的款写进解锁清单、挂「新」标，从此永久拥有、随时可穿
- **禁止**：不因为掉分、散场后改账等原因把已解锁的收回

### 场景 4.6：专属定制栏（被授予者视角）
- **身份**：被运维授予过定制款的球友
- **前提**：解锁清单里有定制款
- **操作**：打开装扮页
- **结果**：头像栏 / 卡背栏里多出「专属定制」一节，被授予的定制款在里面，换穿与保存跟公共款一样顺畅；穿上后全站各处都看得到效果
- **禁止**：无

### 场景 4.7：定制款隐身（普通人视角）
- **身份**：从未被授予定制款的球友
- **前提**：打开装扮页
- **操作**：浏览两栏
- **结果**：**完全看不见**定制款的存在——没有「专属定制」节、没有灰影占位、没有任何「别人有你没有」的暗示
- **禁止**：向未授予者透出任何定制款的名字或图

### 场景 4.8：用微信头像
- **身份**：绑了微信的球友
- **前提**：头像已经被记下——它只在微信授权登录那一刻顺手记录，之后每次授权登录刷新一次。绑定得早、功能上线后还没再走过微信授权的老球友，要等下一次微信授权登录才有这个选项，在那之前装扮页不显示它、也不报错
- **操作**：装扮页头像栏选「微信头像」→ 保存
- **结果**：全站头像位显示微信头像，圆形规矩同所有头像；球友在微信里换了头像、下次授权登录后站内跟随刷新
- **禁止**：头像还没被记下的人看到这个选项

### 场景 4.9：全站看到我（展示端）
- **身份**：任何浏览者，包括未登录的人
- **前提**：某人穿着头像 A、卡背 B
- **操作**：翻战力榜、点档案、看约球名单、进球局现场
- **结果**：各处显示他的头像 A 与卡背 B 的效果——跟看普通图片一样直接就出来，不会先空白一下再蹦出、也不会卡；哪些位置铺头像、哪些位置铺卡背、怎么取景，按附录 A5 / A6 的全站总账执行
- **禁止**：任何展示位因为「查权限」而变慢或闪烁

### 场景 4.10：运维发卡与收卡
- **身份**：运维（项目主人）
- **前提**：用现有的用户运维工具样式，按手机号或账号编号找到人
- **操作**：发卡——把某件定制款编号塞进他的解锁清单，可选「顺手帮他穿上」；收卡——从清单里收回某件定制款
- **结果**：发卡即时生效，被授予者下次打开装扮页即见、穿上的效果即刻全站可见；收卡时若他正穿着这件，系统自动帮他退回默认公共款，头像、卡背各退各的默认——安静收回，被收回者下次进装扮页自然见不到这件，不另发通知
- **禁止**：发不存在的编号；发或收荣誉款编号——荣誉款的进出只走达标核算一条路，运维口对荣誉款直接报错

### 场景 4.11：越权提交（边缘）
- **身份**：已登录球友
- **前提**：绕过界面、比如改本机数据，把一切不满足穿戴条件的值提交保存——未解锁的荣誉款、已失效的微信头像都算
- **操作**：提交
- **结果**：系统拒绝，穿戴保持原样——「能不能保存」的判定真值在系统手里，界面上变灰只是提示
- **禁止**：越权保存成功

### 场景 4.12：老用户与注销（边缘）
- **身份**：存量老球友 / 注销者
- **前提**：老账号里存的是旧装扮数据；或某人注销了账号
- **操作**：老用户打开装扮页 / 注销发生后他人翻历史名单
- **结果**：老账号自动穿默认公共款，头像、卡背各兜各的默认；注销者的解锁清单与穿戴一并清空，历史名单里显示默认公共款头像与「已注销球友」昵称；访客在名单里的格子铺素底
- **禁止**：老数据的存在阻塞登录或装扮页

## 6. 边界与非目标

- ❌ **明确不做**：订单、支付、商店货架、限时到期回收、球友之间转赠——等真正要收费那天再接，账本已按可扩展立好；不做即时解锁通知（弹窗 / 推送 / 红点轰炸）；不做「看别人的衣柜」（装扮页只看自己的）；不做穿戴历史与获得原因流水账（编号自带来历已替代）；不做用户上传自定义头像（定制款由官方授予）。
- ✅ **做但降级**：
  - 解锁时刻的仪式感降级为装扮页里的「新」标记（看过一次即摘）；
  - 首批公共款 / 荣誉款的具体件数由素材管线产出定，册子留位支持后续加款加档，规格只锁档位结构与数值；
  - 微信头像只在授权时刻顺手记录与刷新，不做站内单独的「同步微信头像」按钮；

### 附录 B：后端行为

#### B1. 触发与响应
- 球友打开装扮页 → 系统先顺手核算三类数据，翻现有的战力账、局账、对局账各一笔 → 写解锁清单 → 返回整页；等待感与平常打开页面相当，无需进度提示。
- 保存穿戴 / 运维发卡收卡 → 即时生效。
- 解锁判定只在「打开装扮页」一个时点发生：打完达标的那场球，装扮不会当场变，等本人下次进装扮页核算——这是刻意的，现场记分结算链路一概不碰；核算结果与实时算完全一致。
- 微信头像：授权登录成功的那一刻顺手记录 / 刷新，不额外等待。

#### B2. 失败时用户看到什么
- 核算失败：装扮页照常打开，按上次的解锁状态显示，下次进再算——不拦路。
- 保存失败：提示失败可重试，穿戴不变。
- 发卡 / 收卡失败：运维口报具体原因（人不存在、编号不存在），不产生半个状态。

#### B3. 量放大 100 倍时
- 核算是每人翻三笔现成账，放大后仍是眨眼间的事；装扮册子整本一份（件数为几十级，不随人数放大）；卡背与头像素材是静态图、全站共用同一份，不随人数放大。

### 附录 C：数据行为

#### C1. 数据清单
- **装扮册子**（官方资产册，全站集中一处管理）：每件的编号、名称、属哪一档（公共 / 荣誉 / 定制）、图片、荣誉款的解锁条件与锁头文字、卡背焦点位置——加款加档只改这本册子，界面零改动。
- **每人账号上的三样**：当前穿的头像值——某件装扮编号或「微信头像」、当前用的卡背编号、已解锁的装扮编号清单。公共款不塞进个人清单：人人默认可用，能穿的范围就是全部公共款加本人清单，当场拼出来。
- **微信头像图**：只在微信授权登录时顺手记录、每次刷新；绑定早还没记录过的老球友，等下一次授权登录补上。只存图，不存别的微信资料。

#### C2. 谁能看 / 改 / 删
- 穿戴的写入方只有三个：本人（装扮页保存）、运维（发卡顺手穿上）、系统（收卡自动退默认）；换设备登录跟着账号走。
- 解锁清单的写入方同样三个：系统核算（达标）、运维发卡（仅定制款）、运维收卡（仅定制款）。
- 定制款条目：只有被授予者本人的装扮页显示；他人任何界面都碰不到它的名字与条目——穿戴效果图除外，穿上的效果全站谁都能看到。
- 装扮册子：整本一份，荣誉款连条件文字都公开；展示按人裁——未授予者的装扮页不显示定制款这一节。

#### C3. 留多久、删了会怎样
- 解锁永久：达标即终身拥有，掉分、改账、散场均不收回；收卡是唯一的删除途径（仅运维）。
- 注销：三样与微信头像一并清空；重新注册的新号从零开始。
- 老账号：默认公共款兜底，旧数据原样放着不动、不做迁移。
- 数据不导出（对齐 0号 自用规模底线）。
