## 1. 这是要解决什么问题（必填，人话）

- 现在现场所有事都压在组织者一部手机上：三片场同时开，记分、签到、换人全靠他一个人点，根本点不过来；其他球友只能干看，想搭手也没门。
- 现场的名册、候场、轮转这些事，目前只活在演示数据里，没有真正的账——散场后谁几点到、几点走，无据可查。
- 成功画面：组织者到场先封一个管理员，然后就敢自己下场打球——比分有球友顺手记，换人有球友随手调，每人手机上都能看到同一个现场；空降的朋友扫码就能进，不会被线上满员挡在门外；散场时每个人的到场时刻都在账上，摊钱有依据。

## 2. 给谁用（必填，按角色写）

- **组织者**：当场封/撤管理员分担事务；只有他能封撤管理员、只有他能散场收局（组织者已提前走时管理员可代收）。
- **管理员**：组织者封的帮手，拿到与组织者一样的手柄处理现场事项。
- **球友（参与者）**：不再干看——能给任意一片记分、能把任何人换上换下（换人留名）、自己的节奏自己管（休息跳轮/连战/上下场）。
- **空降的朋友**：没报名但人到了现场，扫码建号直接进场。
- 不为任何角色服务的部分：无。
- 与本功能无关的角色：没进现场的球友不受影响（名单层谁能看谁，1.2 已管，本册不动）。

> 谁能做什么，全靠 §4 场景讲清楚（谁看到什么、想做做不了时看到什么），不另立权限表。

## 3. 用户故事（必填）

1. 作为组织者，我想当场封/撤管理员，以便我下场打球或顾不过来时有人兜底。（§1 问题一）
2. 作为管理员，我想用与组织者一样的手柄管现场（代办签到、换人、改规则、确认终局），以便搭把手不用等人。（§1 问题一）
3. 作为球友，我想给任意一片记分、撤一分，以便组织者没盯着的片也有人把比分记上。（§1 问题一）
4. 作为球友，我想把任何人换上换下，以便临时纠偏不用等组织者。（§1 问题一）
5. 作为球友，我想累了按一下就休息跳一轮、想多打设连战、把自己换下，以便自己的体力节奏自己管。（§1 问题一）
6. 作为空降的朋友，我想扫码建号直接进现场名册，以便人到了不被线上满员拦在门外。（§1 问题一）
7. 作为组织者，我想散场时每个人的到场时刻都留了底账，以便事后摊钱有依据。（§1 问题二）
8. 作为报名的球友，我想到场扫码就亮「已到」，以便不用等人点名、马上进候场队。（§1 问题一）

## 4. 输入 / 输出场景（必填，文档核心）

> 现场的一切——名册、候场队、比分、战报——记在同一本总账上：谁改了什么，全场几秒内在各自手机上看到同样的变化。本册场景都建立在这个前提上。

### 场景 4.1：开场点亮现场（组织者）
- **身份**：组织者
- **前提**：球局已成局
- **操作**：在局里点「开始打球」
- **结果**：
  1. 现场点亮：报名名单整队变成**现场名册**，每人先记「未到」，谁报到谁亮
  2. 若名单里有人带了随行朋友，名额展开成**随行访客**：名字挂在担保人名下（如「小李的球友·1」），与正式球友一样上场打球
  3. 报到的人按先后排进**候场队**，够一片的人数就自动发牌上片（按现行三种轮换法：赢家留场 / 纯轮转 / 均衡配对）
  4. 现场二维码亮出，等大家扫码
- **禁止**：名册里出现没报名也没到场的人。

### 场景 4.2：扫码到场（球友）
- **身份**：报名名单里的球友
- **前提**：现场已点亮，本人还没到场
- **操作**：扫现场二维码
- **结果**：
  1. 没建过号的新朋友先填一张名片建号（老球友免）
  2. 开球**前**到的：名册亮「已到」，按先后排进候场队；开球**后**才到的：标「迟到」，排到候场队尾（见 4.5）
  3. 候场条上自己那句「还有 N 轮到我」几秒内出现
- **禁止**：散场后的二维码还能用（提示「球局不存在或已结束」）。

### 场景 4.3：代办到场与请出（组织者/管理员）
- **身份**：组织者或管理员
- **前提**：有人迟到了、老人孩子没带手机；或有人不打招呼就走了；或扫码的人根本不在现场（二维码被拍照转发）
- **操作**：三选一——在迟到待签到清单里逐个点「到场」；点某人「代办早退」；点某人「移出名册」
- **结果**：
  1. **代办到场**：名册亮「已到」；开球后代办的标「迟到」排队尾；可同时代办带访客（称呼＋人数＋担保人）
  2. **代办早退**：标「早退」，从候场队和场上同时清掉，当场落离场时刻——人不打招呼就走，候场队里也不再排他
  3. **移出名册**：人从名册消失（对付「远程扫码」的幽灵到场），底账留痕
- **禁止**：无。

### 场景 4.4：空降进场（空降的朋友）
- **身份**：没报名的球友
- **前提**：现场已点亮；线上报名可能已满员、甚至候补栏也有人
- **操作**：扫现场二维码 → 填名片建号
- **结果**：
  1. 直接入名册，标「中途加入」排到候场队**尾**，排到就上
  2. 名册上带「空降」标记，全场看得到
  3. 线上满员和候补**都不拦**：现场以到场为准，名册人数可以比线上人数上限还多；线上名单与候补栏原样不动（摊钱时怎么把他算进去，归账单那本册，见 §6）
- **禁止**：把线上候补栏里没到场的人挤掉报名资格。

### 场景 4.5：迟到、中途加入与早退（球友）
- **身份**：球友
- **前提**：本人已在现场名册里
- **操作**：三选一——迟到了才报到（扫码或被代办，已过开球时刻）；中途才来（开场没到、现在到了，或先离场又回来）；点「提前走」
- **结果**：
  1. **迟到**：标「迟到」，排到候场队尾（谁后到谁后上，不插队）
  2. **中途加入**：标「中途加入」，同样排到候场队尾
  3. **早退**：标「早退」，从候场队和场上同时清掉；正打着的片上人少了，由组织者/管理员替补或作废这局（见 4.11、4.12）
  4. 三种情况发生的时刻（几点到、几点走）当场落进出勤底账，散场后可查
- **禁止**：早退的人还留在候场队里等发牌；出门转一圈回来就排到队首（回来也是队尾）。

### 场景 4.6：封撤管理员（组织者）
- **身份**：组织者
- **前提**：现场已点亮
- **操作**：在名册里点某位球友 → 「设为管理员」（或对管理员点「撤掉」）；想封几个封几个，随时可撤
- **结果**：对方头像带管理员标识，立即拿到与组织者一样的全部手柄（见 4.7）；被撤的人手机上弹一句「组织者收回了管理员身份」
- **禁止**：除组织者外的任何人封/撤管理员——管理员自己也不能再封管理员。

### 场景 4.7：管理员全权处理（管理员）
- **身份**：管理员
- **前提**：已被组织者封为管理员
- **操作**：与组织者同一画面、同一套手柄——代办到场与请出（4.3）、带访客、给任何人换人/设休息设连、一键排阵、改分制/轮换模式/场地片数、终局类动作（清零、改比分、确认终局）
- **结果**：做的每件事与其他人几秒内同步；只有两件事点了会提示「只有组织者能做」——封撤管理员、散场收局（组织者已提前走的除外，见 4.14 兜底）
- **禁止**：无。

### 场景 4.8：球友记分（球友）
- **身份**：球友（未被封管理员）
- **前提**：任意一片正在打
- **操作**：点比分按钮 +1 分；点「撤回」减 1（只撤刚才那一分）
- **结果**：
  1. 比分跳动，全场几秒内看到同样的数
  2. 打到收局分数时**该片自己的**终局结算窗弹出（多片各自弹各自的，互不等待）——球友**只能看**：确认按钮对球友是灰的，旁边一句「请组织者或管理员确认」
- **禁止**：球友清零比分、改终局比分、确认终局。

### 场景 4.9：球友换人（球友）
- **身份**：球友（未被封管理员）
- **前提**：至少一片正在打，候场队里有人
- **操作**：点场上的人 → 选候场的人对调（也可互换同片两队）
- **结果**：
  1. 对阵立即更新，两边手机的画面几秒内同步
  2. 战报里出现一句留名的话：「小王 把 老张 换下 · 小李 上」——全场看得到是谁换的
  3. **被换下的人排到候场队尾**（他刚打完一轮；想尽快再上可以点连战）；被换上的人候场条马上变成「该你上场了」
- **禁止**：换不在现场名册里的人。

### 场景 4.10：休息与连战（球友自助；组织者/管理员可代设任何人）
- **身份**：球友
- **前提**：本人在候场队里（组织者/管理员则可点任何人）
- **操作**：点自己（全权者点别人）→ 选「休息一轮」或「连战」；「休息一轮」可以连着按
- **结果**：
  1. **休息一轮**：轮到我上场时自动往后跳一轮——这一轮不上，坑由下一位顶上；还想歇就**再按一下、再跳一轮**（按几次跳几轮，可无限叠加，没有冷却）；跳完照常上场，中途想上随时可取消。一轮＝全场每一片各打完一场（各片各自确认终局、互不等待）
  2. **连战**：下一场优先排到队首（不是留在场上连着打）
  3. 两者互斥：设一个，另一个自动取消
- **禁止**：球友给别人设休息/设连战（点了提示「请找组织者或管理员」）。

### 场景 4.11：纠偏手柄（组织者/管理员）
- **身份**：组织者或管理员
- **前提**：出现需要人手纠偏的状况——场地空着人闲着、或场上有人早退/受伤
- **操作**：三选一——点「一键排阵」；手动换人（与 4.9 同法）；点「找替补」
- **结果**：
  1. **一键排阵**：按当前轮换法自动落位，空片补满
  2. **手动换人**：对阵立即更新，战报留名（同 4.9）
  3. **紧急替补**：候场队首的人自动顶上早退者的位置，这局接着打完
- **禁止**：无。

### 场景 4.12：作废对局（组织者/管理员）
- **身份**：组织者或管理员
- **前提**：一片打到一半——人不够了、或记岔了
- **操作**：对局卡上点「取消对局」→ 弹一句后果「这场将不计分，场上的人回候场队最前面」→ 再点一次确认，才作废
- **结果**：这场**不计分**；场上的所有人回到候场队**最前面**，下一场马上轮到他们（补偿没打成的）。
  ※ 这条修订了现行行为（原来是排到队尾且无确认），裁决见 §8。
- **禁止**：作废的对局进任何人的战绩。

### 场景 4.13：随行访客照常轮换（与正式球友同规）
- **身份**：全场（无需任何人操作）
- **前提**：任意轮换方式（2026-10-07 终裁：访客不单独对待，推翻本册原「访客打赢不留场」裁决，记录见 §8）
- **操作**：无——按轮换规则自动发生
- **结果**：
  1. 访客与正式球友一个待遇：打赢照样留场（输家下）、按资历上下（N人下·先上先下）、连庄照样算、到点照样整队下
  2. 他们与正式球友唯一的不同仍是「不建号、战绩不入账」（怎么算归战力与账单那两册）
- **禁止**：给访客单设一套上下场规矩。

### 场景 4.14：散场收局（组织者）
- **身份**：组织者
- **前提**：现场已点亮，无片正在打（还有片在打时按钮先拦）
- **操作**：点「散场」→ 弹一句后果「散场后二维码失效、不能再进」→ 再点一次确认，收局
- **结果**：
  1. 现场封存，二维码失效
  2. 出勤底账定格：每人几点到、几点走、哪位访客是谁带的、被移出名册的留痕——留给事后摊钱用（怎么摊归账单那本册）
  3. 兜底：组织者已标「早退」离场时，管理员能看到散场按钮代为收局（否则没人能收）
- **禁止**：还有片在打时直接散掉（先收局或作废）；组织者在场时管理员和球友散场。

### 场景 4.15：两人同时动手（球友＋组织者）
- **身份**：任意两人（如组织者换人、球友同时记分）
- **前提**：两人几乎同时各自动手
- **操作**：各自在手机上点自己的操作（一个换人、一个记分）
- **结果**：现场只有一本总账——**不同操作各算各的、按先后依次生效**（一个换人、一个记分，两笔都算数）；两人恰好改**同一处**时才先来后到、后落的为准，先落的人画面跳一句「现场已更新」。不会出现两边各记各的比分、各排各的队，也不会把先落的那笔吞掉。
- **禁止**：两边画面长期不一致（最迟几秒内对齐）。

## 5. 验收标准（必填，可勾选）

- [ ] **正常流程**：[组织者] 开场点亮，名册就位 —— 对应 §3 故事 1 前置
  → 验证：报名 5 人（小李带 2 位朋友）点开始打球，名册出现 7 行，访客名挂「小李的球友·1/·2」，每人初始「未到」；再试无人带随行的局，名册行数与报名数相同，照常点亮。
- [ ] **正常流程**：[球友] 扫码亮已到 —— 故事 8
  → 验证：开球前扫码，名册亮「已到」、按先后进候场队，候场条几秒内出现「还有 N 轮到我」。
- [ ] **正常流程**：[球友] 空降扫码直入 —— 故事 6
  → 验证：线上已满员时，未报名者扫码建号后直接出现在名册（带「空降」标记、排候场队**尾**）；线上名单和候补栏原样不动。
- [ ] **正常流程**：排队位统一 —— 故事 5、6、8

## 6. 边界与非目标（必填）

- ❌ 明确不做：
  - **发牌多类型**（单打、3人轮换、4人轮换）与**连庄上限**——挪到将来专门一册「发牌与换人算法」；本册只保现行 2v2 三种轮换法。
  - **记分几分收局、终局结算怎么确认**的规则本身——归 2.1 已有行为与记分结算那本册管；本册只定「谁能按这些按钮」。
  - **连战/休息的 CD 刹车**——连战是「排队首」的弱形态、休息是「按几次跳几轮」，都用不着冷却。
  - **包时到点强制收盘**、**记分提议审批制**、**执裁代管**（被管理员角色取代）——见 §8。
  - **2.1 的内容清理**——后续另走修订，不在本册流程内（只在 2.1 头上贴了指向标）。
- ✅ 做但降级（自用够用即可的部分）：
  - 管理员数量不限、无需审批——现场十几个人，靠人情管不靠系统设卡。
  - 球友换人没有提议/审批环节——靠「操作留名进战报」的透明约束。
  - 访客计分怎么算半权重不进榜——归战力那本册；访客上下场与正式球友同规（2026-10-07 终裁），轮换规则真值归《2.4 轮换算法》。
  - **空降建号、访客不建号——有意为之**：空降扫码走建号流程成为正式球友（战绩长期累积）；随行访客与代办访客只挂担保人、不建号（战绩不入账）。两类人的区别，将来战力册与账单册要接住。
  - **空降不进线上报名名单**：摊场地钱时，账单册按本册的出勤底账把空降者补算进去——留给账单那本册。

## 7. 附录（前端必拼，后端/数据按需，同样人话）

### 附录 A：前端行为

**A1. 屏幕清单**
- 打球页（现有页面，组织方式不变）：本册在其上新增——名册/点人抽屉里的「设为管理员」入口与管理员标识、「代办早退/移出名册」入口；球友视角下终局结算窗的确认按钮置灰；战报里的换人留名句。
- 封管理员入口：组织者点开某人面板即可见；管理员和球友视角看不到这个入口。

**A2. 每屏的状态**
- **空状态**：开场后没人报到——名册全「未到」、候场区空、对局卡显示等人的样子。
- **加载中**：进现场页，名册与候场队几秒内出全，等待时画面有骨架不白屏。
- **出错**：断网或操作失败——提示「网络不给力，请稍后再试」，可重试；重试后到场不重复、比分不多加。

**A3. 操作与响应**
- 记分 +1 → 比分即时跳动 → 全场几秒同步；撤回只撤「刚才那一分」。
- 换人 → 对阵即时更新 → 战报出现留名句；换错不可一键撤销，但可以再换回来（换人永远可用）。
- 休息一轮/连战 → 即时生效提示 → 休息按几次跳几轮、随时可再按可取消；连战下一场排队首。
- 越权操作（球友点终局确认/给别人设休息）→ 按钮置灰或点击提示「请找组织者或管理员」，不是点完才报错。
- **危险动作先确认**：取消对局、清零比分、散场收局，点下先弹一句后果，再点一次才执行。
- **「还有 N 轮到我」不乱跳**：换人、空降、作废回流让这个数变化时，战报里都有对应一句（谁换的、谁来了、谁回流）。

**A4. 数据从哪来**
- 画面上的每个东西——名册顺序、候场队、还有 N 轮、比分、战报、谁在歇谁连战——都是现场总账**算好定死**给的，画面只负责显示，一个字不自算。
- 「还有 N 轮到我」也是按候场队现况算好给的；换人之后它跟着变。

### 附录 B：后端行为

**B1. 触发与响应**
- 自己动手的操作，画面即时更新；别人动手的操作，几秒内出现在自己画面上（画面定期与总账对表）。
- 谁能做什么由总账把关：球友的越权动作就算绕过画面直接送到总账，也一律拒绝并回同一句提示——不指望手机端拦住。
- 出勤底账当场落：到场、早退、移出的当下就记好，不等散场补。
- 封管理员即时生效：封完的下一秒对方就能用全部手柄；撤掉即时收回。

**B2. 失败时用户看到什么**
- 断网/失败：提示可重试；到场重试不重复记（一个人到场只记一次），比分重试不多加。
- 部分成功：代办 5 人到场只成 3 人时，提示哪几位没成，可逐个重点，不用从头再来。

**B3. 量放大 100 倍时**
- 几百人的「现场」（远超微信群场景）：画面更新变慢（对表变久、战报刷不过来），先扛不住的是同步速度；但总账不乱——名册、比分、底账仍只有一本，慢而不错。
